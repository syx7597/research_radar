# 查询修复最小验证协议 v1

冻结日期：2026-09-26。状态：数据、比较边界及校准策略已冻结；截至本次策略冻结时，2,000题holdout尚未评估。之后的结果另存报告，不回写选择阈值。本协议不宣称修复有效。复现实验命令见[运行说明](QUERY_REPAIR_RUNBOOK.md)。

## 1. 研究问题与固定基础

目标是提高KQA Pro最终答案准确率，并减少修复引入的新错误。比较“局部事实约束＋保守接受”是否超过普通全局字段匹配及扩大生成候选的效果。

固定首轮5,000题训练的BART-base检查点、tokenizer、生成配置与官方baseline执行器；本轮不重新训练生成器或额外训练修复模型。记录模型权重哈希、执行器版本、KB哈希、代码版本及所有策略参数。继承合法重复查询的生成配置，不重新启用摘要模型的重复抑制。此前500题的80.0%仅为开发成绩，不能作为新检查集准确率。

### 执行器一致性修正（holdout评估前冻结）

所有执行进程统一设置`PYTHONHASHSEED=20260926`，固定集合/字典相关遍历的进程级哈希种子。已发现原官方`Find`在同名实体/概念场景下，使用`+=`将概念ID追加到持久的`entity_name_to_ids`列表；重复调用可能改变后续候选执行结果。局部前缀查询增加调用次数，因此必须先消除这种跨调用污染，才能公平比较方法。

本项目`KoPLExecutor`为每次官方`Find`调用提供临时列表副本，并在`finally`恢复原索引列表；下载的官方源文件保持原样。beam4、beam8、global、local及其消融均使用同一修正适配器、同一官方源与KB。此修正用于保证实验基础设施一致，**不计为查询修复算法的创新或收益**。

`scripts/check_executor_stability.py`对原6500条金标程序分别按原顺序和完全逆序执行，两遍各初始化新引擎。两遍均6500条可执行、6498条答案匹配，逐ID输出差异为0；原有`train:2522`和`train:40416`两例不匹配仍保留，不改标签、不删题。完整校验见`results/condition_consistency/query_repair/executor_validation.json`。该检查只支持这些金标程序上的顺序稳定性，不证明任意预测程序语义正确。

保留首轮pilot及其旧执行结果，不覆盖历史报告。当前相同500题dev在统一修正执行条件下的beam4 first-valid为401/500，旧报告为400/500；两者不属于同一执行条件，不能将这1题变化归因于新修复算法，也不能直接把本轮修复结果减去旧80.0%作为增益。本轮增益均相对同批候选、同一修正执行器重新得到的对照。

## 2. 数据冻结与金标隔离

由`python3 -m experiments.condition_consistency.prepare_repair_splits`生成；脚本调用原`prepare_data.make_splits`，复核原6500题及源文件哈希。共享归一化问题或完整程序的记录连成组件，只取最小原始索引代表；排除与official val问题或程序重叠的整个组件。

| 划分 | 题数 | 用途与历史 |
|---|---:|---|
| generator_train | 5,000 | 已训练基础模型；仅引用原划分 |
| design | 500 | 原reranker_train的一半，用于错误分析和方法设计；并非从未用过的数据 |
| calibration | 500 | 原reranker_train另一半，仅用于选择修复接受阈值和预先规定的策略配置；并非独立测试集 |
| dev_diagnostic | 500 | 原开发集，已检查过，用于诊断和可修复覆盖分析 |
| holdout | 2,000 | 原训练集剩余未用组件中随机冻结；不参与算法选择，最终一次性比较 |

design/calibration使用种子20260927：原1000题索引排序后打乱，前后各500。holdout使用种子20260928：排除原全部6500题所属组件后，将剩余代表排序打乱取2000。严格检查ID、归一化问题、完整程序和组件不重叠。题数、ID、文件哈希及检查结果保存在`results/condition_consistency/query_repair/split_manifest.json`。

所有划分分别写入`*.questions.jsonl`（仅id、question）和`*.gold.jsonl`（含程序、答案，供离线校准/评分）。生成与修复只读取问题文件、模型候选及KB，不读取金标。构建划分时金标程序仅用于精确去重，不执行程序、不按答案、难度、程序类别或模型表现筛选holdout。holdout问题文件可先生成候选；任何holdout金标错误分析均在策略冻结及最终评分之后。

## 3. 对照与预算

| 方法 | 生成候选 | 新修复候选/题 | 比较目的 |
|---|---:|---:|---|
| beam4 first-valid | 4 | 0 | 当前主要基线；按模型次序取第一个可执行候选 |
| beam8 first-valid | 8 | 0 | 扩大生成候选的直接对照；独立beam8解码，不假设等于beam4列表扩展 |
| global field repair | 4 | 最多4 | 角色和类型合法的全局字段匹配修复 |
| local field repair | 4 | 最多4 | 相同修复预算，增加可信前缀的局部字段/所属事实约束与保守接受 |

修复方法每题只有一轮，每个候选只替换一个字段参数；不改变实体、数值、日期、比较符、方向、函数列表、依赖及其他输入，不递归继续修。去重后每题最多执行4个新增候选，不能按每个原候选分别放大预算。所有方法共享KB访问权限、相同超时和执行语义。

触发必须有独立、推理时可见的角色schema或类型异常证据。合法空集、计数0、否定答案或某实体局部没有某字段均不能单独触发；不能通过放松条件取得非空答案。局部前缀可信性规则必须可记录、不可读金标；限定符候选绑定所属事实，不能跨不相关事实拼接。首版无法建立可信局部上下文时放弃该位置的修复提议并记录原因，不回退到全局候选；最终没有可接受提议时保留原输出。

修复的选择、分数定义、阈值网格和并列处理规则写入最终策略文件；阈值仅在calibration选择，holdout执行前保存文件哈希。保守回退为原beam4 first-valid结果；原列表无可执行结果时仍保留该题，不能从评测中删除。

首版具体评分与校准规则（holdout评分前补录）：

- 字段匹配分数`match = 0.85 × 原字段/新字段归一化字符串相似度 + 0.15 × 新字段词在问题中的覆盖率`。相似度采用`SequenceMatcher`；分词为小写英文字母/数字片段。构造候选时最低匹配分为0；先按原候选排名轮流分配新增候选预算，父候选内部按匹配分、程序位置、输入位置、替换字段名排序，重复程序不再执行。
- 原查询与修复查询均由同一固定BART教师强制评分；取目标token的平均对数概率`tf_mean`，包括训练格式中的BOS/EOS，忽略padding，不直接混用beam score。选择分数为`S = tf_mean + alpha × match`。
- 可接受候选必须执行合法、修复后不存在角色schema/显式类型冲突，并达到`min_match`。取S最高者，同分保留候选列表中较早者。与原first-valid查询的`tf_mean`相比，增量至少为`margin`才接受；若原列表没有可执行结果，则与修复候选自己的原父查询相比，否则继续保留失败。
- global/local各自在同一calibration集合独立选择配置。网格为`alpha ∈ {0, 0.25, 0.5}`、`min_match ∈ {0, 0.4, 0.6, 0.8}`、`margin ∈ {-0.25, 0, 0.1, 0.25, 0.5, 1.0}`，另含完全关闭修复，共73种。按正确题数最多、改错数最少、切换次数最少、alpha最小依次择优；仍同分按网格枚举次序选首项（关闭修复优先，然后alpha、min_match、margin升序）。保存全部校准尝试，不仅保存最佳结果。
- `no_acceptance`消融在存在可执行且schema干净的修复时，直接选S最高的修复；不使用关闭开关、min_match或margin，但继续保持执行/schema检查。它使用完整方法校准出的alpha，不另在holdout调参。global与local各自校准后的比较代表完整策略对照，不单凭该比较宣称某一个阈值或局部约束具有独立因果贡献。

在上述500题calibration及统一修正执行条件下，最终冻结参数如下；两种方法均启用修复。这些参数在查看holdout成绩前确定。

| 方法 | alpha | min_match | margin |
|---|---:|---:|---:|
| global | 0.5 | 0.8 | -0.25 |
| local | 0.5 | 0.4 | 0.0 |

以`frozen_policy.json`为机器可核验记录，保留全部73项校准尝试及选择结果。记录并核验selector、repair、scorer、执行器适配层与官方源哈希；同时核验分区清单、KB、模型配置和完整权重哈希、各模式候选预算配置、输入输出缓存哈希以及`PYTHONHASHSEED`。代码或数据身份变化后不能沿用该冻结策略作为同一次实验。

候选数量不等于计算量相等。分别统计新增候选、实际执行次数（含前缀查询）、生成token、教师强制重评分token、字段检索耗时、总耗时和每题延迟；共享缓存的冷/热状态与预处理耗时单独注明。至少比较局部约束的去除消融；若评价保护/接受机制的贡献，还须给出明确对应消融，不能仅由整体效果归因。

## 4. 开发、冻结、评分顺序

1. 在design及已见dev上分析覆盖并实现全局修复和局部修复；最多两轮有记录的开发调整，每轮保存配置、诊断结果及修改原因。
2. 在calibration选择阈值；所有方法比较须完整500题，不能只选触发或可修复的问题。金标只供离线阈值比较，不进入单题候选构造。
3. 固定算法、候选上限、候选顺序、阈值、超时、模型版本及评测脚本，保存策略与代码哈希；确认holdout答案尚未用于选择。开发结论为覆盖不足时也可停止，不能只为正结果继续换题。
4. 对完整2000题运行全部冻结方法，然后一次性离线计分。程序异常、超时、缺失预测、金标疑点都留在总分母；缺失项记错误，接口ID错配则先修复管道再评分并披露。
5. 不依据这2000题的答案调参重报“未接触集”成绩。若需后续研究，则将其明确标为已见诊断集，保留首次冻结结果并另立正式实验协议；不反复抽新集合挑选提升。

## 5. 指标与判断

主要指标为全部问题上的官方答案比较准确率；同时报告相对beam4、beam8和全局修复的净增益、纠正数、改错数及2000次问题级配对bootstrap的95%区间（固定随机种子20260926）。所有方法使用同一批题与配对抽样，不能仅比较各自独立置信区间。

辅助指标包括触发率、拒绝率、修复候选可执行率、候选答案覆盖上限、未覆盖错误数、单字段覆盖情况和上述成本。类别分析明确标记为事后诊断，不用其挑选下一次主结果。合法执行或非空答案增加不能替代答案准确率提升；答案相同也不证明程序语义等价。

只优于原始top1或明显较弱的修复器不足以支持拟议机制。局部策略应在合理候选预算和成本下，较执行筛选和全局修复呈现可解释的净收益；不承诺特定百分点或显著性。无收益、覆盖过低或收益完全来自普通字段匹配，则如实保留结果并调整研究范围。

本轮仅一个固定生成器种子，属于可行性验证。正式论文阶段若进入扩大实验，使用多个生成器训练种子和完整official val（11,797题，明确称validation，披露旧项目曾使用该集合）；雷达应用另设来源独立的核验数据，不能由KQA Pro成绩直接推出领域能力。
