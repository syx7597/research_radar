## 论文题目

**面向复杂雷达情报问答的图检索策略学习方法研究**

英文题目建议：**Graph Retrieval Policy Learning for Complex Radar Intelligence Question Answering**

> 本题目固定三个长期稳定的要素：复杂雷达情报问答、图检索决策和策略学习。雷达情报问答是应用场景，知识图谱与文本库是知识环境，Agent 是策略与环境交互的执行形式，SFT 和强化学习是策略优化手段。题目不绑定具体决策结构、优化算法、基座模型、工具数量或知识图谱版本。

## 一、开题摘要

雷达情报知识分散于装备手册、技术报告、结构化数据库、网页和扫描文档中，具有型号别名多、实体关系密集、来源异构以及查询组合复杂等特点。装备档案、型号对比、体系关联和统计分析等任务通常需要完成实体识别、多跳关系遍历、多约束筛选、集合交并差、计数聚合及图文证据补充。传统检索增强生成主要依赖一次性文本召回，难以稳定处理精确计数、高基数枚举和多关系组合；现有 GraphRAG 方法虽然利用图结构增强检索，但多数采用固定检索流程、启发式路径搜索或扁平工具调用，大模型仍需在较大的动作空间中同时完成任务分解、工具选择、参数生成和结果计算，容易出现计划不可执行、实体漂移、重复检索及长程决策不稳定等问题。

本研究拟将复杂雷达情报问答统一建模为可执行图检索策略学习问题，并围绕两个递进问题展开。第一，针对扁平工具空间过大以及大模型同时承担任务分解、工具选择、参数生成和精确计算所导致的长程决策不稳定，研究类型化图检索决策表示：由策略模型完成问题分解、宏动作选择和结构化参数生成，由确定性执行器完成关系查询、路径遍历、集合运算、计数、聚合和比较，通过类型约束、中间变量及数据依赖形成可执行计划。这里的分层结构属于动作空间与执行协议设计，低层不是独立学习策略，不将其过度表述为经典层次化强化学习。第二，针对仅使用最终答案 EM/F1 所造成的奖励稀疏和长程信用分配困难，将知识图谱、文本库与类型化执行器封装为可交互知识环境，利用计划合法性、类型和变量依赖正确性、支持事实覆盖、状态进展、错误修复、重复调用及执行成本构造多粒度可执行反馈；先以成功轨迹监督微调完成策略冷启动，再通过策略优化学习稳定、经济且具备组合泛化能力的检索行为。

实验拟在自建雷达复杂问答数据集上开展主实验，并以 KQA Pro 和 MetaQA 作为公开验证集。核心实验采用“扁平 SFT、类型化/分层 SFT、扁平 RL、完整方法 RL”的 2×2 对照，分别检验动作空间结构化和执行反馈策略学习的独立价值；进一步设置 IID、实体隔离、算子/程序组合隔离和错误恢复测试，并分别报告环境 oracle、策略执行和最终答案结果。评价指标包括答案正确率、计划有效率、执行成功率、组合泛化能力、工具调用成本和跨领域迁移性能。来源、置信度和冲突元数据仅用于可追溯展示及附加实验，不作为核心训练信号或论文成立条件。

关键词：雷达情报问答；图检索；策略学习；类型化决策；可执行反馈；组合泛化

## 二、研究背景与意义

### 2.1 研究背景

雷达领域问题既包含“某型号由谁研制”这类单事实查询，也包含以下复杂任务：

1. 查询某雷达的改型，再追踪改型所部署的平台；
2. 找出同时满足国家、频段和工作模式约束的全部雷达；
3. 统计某平台、厂商或频段关联的雷达数量；
4. 比较两个型号在研制方、频段、平台和功能方面的异同；
5. 先从图谱获得结构化事实，再从叙述文本补充原理和结构说明；
6. 将前一步结果作为后一步工具输入，批量生成档案或对比报告。

这些问题的难点不只是“召回相关段落”，而是将自然语言问题转换为可执行的数据流和组合运算。单轮 Top-K 检索对关键词和局部事实有效，但无法保证精确集合与完整路径；让大模型直接在长上下文中计算集合和数字，又容易产生遗漏和幻觉。因此，需要把大模型擅长的语义规划与程序执行器擅长的确定性计算分离。

### 2.2 理论意义

本研究将复杂雷达情报问答建模为可执行图检索策略学习问题，关注两个递进的理论与方法问题：

1. 如何设计覆盖多跳、集合、计数、比较、多约束和图文协同的类型化动作空间，使语义规划与确定性计算解耦；
2. 如何利用计划和执行过程中的自动可验证反馈缓解稀疏奖励与长程信用分配困难，使策略泛化到未见实体和算子组合。

研究有助于连接知识图谱问答、工具增强语言模型、程序化执行和策略优化，为专业领域复杂检索提供一种可复现的决策建模与学习范式。

### 2.3 应用意义

该方法可用于雷达装备档案、型号对比、关联分析、统计报告和情报问答。低层执行过程能够输出计划树、工具轨迹和命中事实，使系统结果便于人工复核。来源和证据元数据可继续用于结果展示，但不影响基本查询与推理能力。

## 三、国内外研究现状

### 3.1 传统 RAG 与 GraphRAG

传统 RAG 通过稀疏或稠密检索获取相关文本，并将召回内容送入生成模型。该范式适合局部事实和文本解释，但对多跳关系、集合操作和全局统计支持有限。GraphRAG 通过实体关系图、社区结构或知识图谱组织外部知识，使检索能够利用结构连接。Microsoft GraphRAG 主要面向语料级全局摘要；知识图谱问答方向则更关注关系路径和可执行查询。

ToG 将大模型作为 Agent 在知识图谱上逐步探索关系和实体；RoG 采用“关系路径规划—图检索—基于路径推理”的流程提高忠实性和可解释性。这些工作证明图结构对复杂推理有价值，但仍以提示式搜索、路径启发式或单层规划为主。

### 3.2 工具交互与可执行检索决策

ReAct 将语言推理与环境行动交错执行，使模型能够根据工具观察继续决策。Plan-and-Execute 类方法先生成任务计划，再按步骤调用工具，适合长任务和带依赖的工作流。现有工具 Agent 常把所有工具平铺在同一动作空间中，由模型同时决定任务分解、工具名称、参数和结果组合。随着工具增多和任务变长，非法参数、重复调用和错误传播会明显增加。

分层决策思想可以通过子目标或宏动作组织长程任务。对于本研究，可将“路径查询”“集合过滤”“计数聚合”“图文补充”等定义为语义宏动作，将关系参数、变量引用和确定性计算交由类型化执行器，从而降低策略搜索难度。由于低层是按协议执行的程序模块而非独立学习策略，本文将该设计称为“分层/类型化图检索决策”，不将其等同于经典层次化强化学习。

### 3.3 图检索策略学习

Search-R1 将搜索引擎作为环境，使用 NQ 与 HotpotQA 问答金标，通过最终答案精确匹配奖励训练模型学习何时搜索和如何生成查询。ReSearch 仅使用 MuSiQue 问题和答案，以答案 F1 和格式作为奖励，在没有人工推理轨迹的情况下学习多轮搜索。Graph-R1 将文档知识超图作为环境，以格式和答案 F1 训练多轮图检索策略。GraphRAG-R1 进一步使用渐进检索衰减奖励和成本感知 F1，在答案质量与检索次数之间进行平衡。

上述研究证明执行结果可以训练检索策略，但其动作通常以自然语言查询和 retrieve 操作为主，对集合、计数、差集、比较等类型化组合操作支持不足；过程奖励也主要关注格式和检索次数，较少利用可执行计划树的类型信息和中间结果。

### 3.4 本研究定位

本研究不把 Agent、GraphRAG 或使用某种强化学习算法作为创新，而是研究：**如何以类型化动作表示复杂图检索决策，并利用多粒度可执行反馈学习具有组合泛化能力的检索策略。**

| 方法 | 决策结构 | 主要动作 | 主要奖励 | 本研究区别 |
|---|---|---|---|---|
| ReAct | 扁平、逐步 | 通用工具调用 | 无训练或任务反馈 | 缺少类型化计划与策略学习 |
| ToG / RoG | 路径式 | 关系/实体路径 | 启发式或监督 | 集合、聚合和多工具数据流表达有限 |
| Search-R1 / ReSearch | 扁平、逐步 | 文本搜索 | 答案 EM/F1、格式 | 不执行类型化图运算 |
| Graph-R1 | 多轮图交互 | 查询、子图检索 | 格式、答案 F1 | 以文档知识超图和自然语言查询为主 |
| GraphRAG-R1 | 多轮图文交互 | 检索调用 | 检索次数、F1、成本 | 不显式学习类型化算子计划树 |
| 本研究 | 类型化计划 + 确定性执行 | 图路径、集合、聚合、图文检索 | 答案、计划、执行进展、成本 | 动作空间设计与可执行反馈学习统一 |

## 四、核心科学问题与研究假设

### 4.1 总体科学问题

面对需要多跳关系、集合操作、精确计数、比较、多约束和图文协同的复杂领域问题，如何设计可执行的图检索决策空间，并利用多粒度执行反馈学习稳定、经济且具有组合泛化能力的检索策略？

### 4.2 关键子问题

1. 如何定义既覆盖复杂查询、又保持类型安全的动作、计划和执行协议？
2. 如何在语言策略与确定性执行器之间可靠传递结构化参数、中间变量、数据依赖和错误状态？
3. 如何构造比最终答案更细粒度且不易被策略投机的计划与执行反馈？
4. 执行反馈策略优化能否超越成功轨迹模仿，学习未见算子组合和错误恢复行为？
5. 所学策略能否在公开 KGQA 数据集上得到独立验证，并与知识环境覆盖因素解耦评价？

### 4.3 可检验研究假设

- H1（动作空间）：类型化/分层决策相对扁平工具决策，可提高计划有效率、执行成功率和复杂问题准确率。
- H2（策略学习）：在相同动作空间下，多粒度执行反馈策略优化相对 SFT-only，可提高组合隔离和错误恢复测试上的性能。
- H3（信用分配）：相对仅使用最终答案奖励，多粒度执行反馈可减少空执行、重复调用和无效长轨迹，同时不降低答案质量。
- H4（外部效度）：在至少一个公开 KGQA 数据集上观察到同方向增益，说明方法不只是雷达实体或模板记忆。

## 五、已有研究基础

### 5.1 知识与检索基础

当前项目已构建雷达领域知识图谱。构建报告记录 22,241 条边、10,744 个实体和 16,609 条属性记录；当前 edges.json 有 21,928 条边记录，RL 工具过滤后保留 11,432 条记录（2026-09-26 复核）。系统已实现 BM25、FAISS、RRF、图扩展和 Cross-Encoder 重排组成的混合检索链路，并建有 1,432 段叙述文本库，可分别支持结构化事实和原理/结构类文本查询。

### 5.2 可执行图检索基础

项目中已经存在可复用的双层执行原型：

- 外层 `agent_loop.py`：将复杂请求分解为带步骤依赖的数据流计划，支持前序结果引用和集合逐项处理；
- 内层 `planner.py`：将组合问题转换为 JSON 计划树；
- 类型化执行器 `composition.py`：确定性执行 `constraint`、`intersect`、`union`、`difference`、`path`、`count`、`enumerate`、`aggregate`、`compare` 和 `contains`；
- 反思节点：根据空结果和失败叶节点进行一次或多次重规划。

现有 72 道组合评测中，计划有效率和执行成功率为 100%，答案正确率约 99%。这些结果说明类型化计划与确定性执行具备工程基础，但样本规模较小，当前规划仍主要依赖提示式 LLM，没有经过系统的策略学习，不能直接作为拟研究方法的实验结论。

### 5.3 策略训练数据与环境基础

`ca_agraphrag/data` 当前包含：

| 数据划分 | 数量 | 主要题型 |
|---|---:|---|
| train | 4,277 | 单跳、两跳、计数、枚举、比较、否定、多约束 |
| dev | 582 | 同上 |
| test | 542 | 同上 |
| SFT 成功轨迹 | 4,277 | 与训练问题对应的可执行轨迹 |

已对 5,401 道问题完成 oracle 回放，所有金标轨迹均能由当前工具复现。可自动构造的候选任务包括约 21,928 个单跳事实、15,868 个两跳桥接、813 个计数/枚举分组和 19,385 个比较对，具备扩大训练集的条件。

现有环境反馈仅包含答案正确性、动作格式和步数惩罚，策略优化脚本是待 GPU 验证的简化原型。因此开题时应表述为“数据与环境原型已经具备，多粒度反馈设计、策略训练和完整实验拟开展”。

### 5.4 已有结果对新研究的启示

已有固定路由方法在 RadarKG-QA-499 上达到 88.6%，显著高于单轮基线；但在 KQA Pro 约 500 题的已有实验中，总体结果与基线基本持平，且 Count 题受局部子图覆盖限制。该现象说明固定策略在领域内有效，但跨领域和复杂组合能力仍受决策表示、知识环境覆盖与检索策略限制，正好构成本研究开展类型化决策建模、策略学习和公开集验证的动机。

## 六、研究内容、方法与技术路线

### 6.1 问题建模与总体技术路线

将复杂雷达情报问答建模为策略与知识环境的序贯交互过程。知识环境包括雷达知识图谱、叙述文本库和一组可执行工具；策略根据问题、历史动作和执行观察生成下一步结构化检索动作；执行器完成类型检查、工具调用和精确计算并返回新状态，直至策略输出终止动作。Agent 仅指这一交互与执行形式，不作为独立研究标签。

总体技术路线为：

```text
复杂雷达情报问答
  -> 多跳、集合、计数、比较、多约束和图文协同需求
  -> 类型化可执行图检索决策
  -> 多粒度计划与执行反馈
  -> 成功轨迹 SFT 冷启动与策略优化
  -> 可执行且具有组合泛化能力的图检索策略
  -> 雷达数据和公开 KGQA 数据验证
```

其中图检索构成结构化事实查询和组合计算的主干；文本库作为知识环境中的补充通道，由策略在需要原理、结构和背景说明时选择。实体集合和中间变量以结构化值传递，不经过语言模型自由改写。

### 6.2 类型化图检索决策建模

针对扁平工具空间中任务分解、工具选择、参数生成和精确计算相互耦合的问题，将一次图检索决策表示为结构化动作 `a_t = (z_t, p_t)`：

1. `z_t` 表示语义宏动作，例如事实查询、路径追踪、约束过滤、集合组合、聚合统计、文本补充、结果验证和终止；
2. `p_t` 表示该宏动作的结构化参数，包括实体、关系、算子、变量引用及数据依赖；
3. 确定性执行器 `E` 检查动作类型和变量依赖，执行相应工具并返回结构化观察，不参与策略学习或语言概率生成。

策略与环境交互可写为：

```text
a_t = (z_t, p_t) ~ pi_theta(a | s_t)
o_{t+1} = E(s_t, a_t)
s_{t+1} = U(s_t, a_t, o_{t+1})
```

其中 `s_t` 包含原始问题、已执行计划、中间变量、支持事实、错误状态和剩余预算，`U` 为状态更新函数。该设计在表示层面具有“语义规划与确定性执行”的分层结构，但学习对象只有策略 `pi_theta`，因此本研究的核心是动作空间设计，而非训练相互嵌套的高低层策略。

### 6.3 类型化计划与执行协议

计划节点采用统一 JSON Schema，并为每个节点定义输入输出类型：

| 节点类别 | 输入 | 输出 |
|---|---|---|
| constraint / find | 关系、目标值、可选实体类型 | EntitySet |
| path / subgraph | 起始实体、关系链或跳数 | EntitySet / Subgraph |
| intersect / union / difference | 一个或多个 EntitySet | EntitySet |
| count / aggregate | EntitySet、属性和聚合函数 | Scalar |
| compare / contains | 实体、集合或关系维度 | Boolean / CompareResult |
| text_search / hybrid_search | 自然语言查询、实体上下文 | EvidenceSet |
| finish | 已执行结果和引用变量 | AnswerArtifact |

执行前进行 Schema、类型和变量依赖检查；执行后返回结果规模、样例、命中支持事实和错误类别。非法计划不直接进入生成阶段，而是作为可学习的负反馈返回检索策略。

### 6.4 多粒度可执行反馈

与只依赖最终答案的稀疏奖励相比，本研究将每一步可执行反馈转换为过程奖励，并与终局答案奖励组合：

```text
r_t = lambda_v * R_valid,t
    + lambda_e * R_evidence,t
    + lambda_g * R_progress,t
    + lambda_x * R_repair,t
    - lambda_s * C_step,t
    - lambda_r * C_repeat,t

R_tau = R_answer + lambda_f * R_format + sum_t gamma^t * r_t
```

- `R_answer`：最终答案的 EM、集合 F1、计数正确率或结构化比较得分；
- `R_valid,t`：当前计划节点可解析、类型正确、变量依赖合法；在有金标程序时可计算算子匹配，在无唯一程序时使用执行等价性；
- `R_evidence,t`：当前执行结果对金标支持事实或目标关系的覆盖程度；
- `R_progress,t`：候选集合、未完成子目标或状态距离是否向正确答案收敛；
- `R_repair,t`：检测到空结果、非法参数或错误关系后是否完成有效修正；
- `R_format`：合法 JSON、合法工具与必要字段；
- `C_step,t`：当前步骤的工具调用、token 和延迟等成本；
- `C_repeat,t`：重复状态、相同参数重复调用和无信息增益检索。

逐步反馈为中间动作提供局部信用信号，终局答案约束整条轨迹的任务正确性。奖励采用门控或分阶段方式：格式奖励只能帮助模型学会协议，不能让错误答案获得接近正确答案的高分；过程奖励设置上限并接受执行等价性检查，防止模型通过增加无意义步骤刷分。

### 6.5 基于成功轨迹和执行反馈的策略学习

训练分为四个阶段：

1. 协议学习：使用已有 4,277 条成功轨迹进行 SFT，使模型掌握类型化动作格式；
2. 基础策略优化：在单跳、计数和简单路径题上用答案与格式反馈训练稳定工具调用；
3. 组合策略优化：加入集合、多约束、比较和未见算子组合，启用计划与进展反馈；
4. 错误恢复：主动注入实体别名、空结果、非法关系和局部检索缺失，训练重规划与停止行为。

策略优化优先采用成熟训练框架，具体可在 GRPO、PPO、REINFORCE++ 等优化器中依据开发集稳定性和资源消耗选择，不把当前简化自研脚本直接作为正式算法。论文贡献落在类型化图检索决策建模和多粒度可执行反馈，而不是某个优化器名称。

### 6.6 图文协同检索

结构化事实、多跳集合和精确统计优先由知识图谱工具处理；工作原理、内部结构和背景描述由文本检索处理。检索策略根据问题目标与图执行观察决定是否切换知识通道：

- 图谱已完整回答时直接终止，避免无必要文本检索；
- 图谱返回实体但缺少解释时，以实体和关系作为文本搜索条件；
- 文本命中只能补充叙述，不替代已确定的集合与数值计算；
- 混合问题将图结果和文本证据分别保存，在最终生成阶段按字段渲染。

### 6.7 可追溯输出与扩展边界

计划树、工具轨迹、命中事实和文本片段用于生成可追溯答案。KG 中已有的 `evidence`、`doc_ids`、`source_kinds`、`tier` 和 `corroborated` 可用于展示来源和筛选证据，但当前 `confidence` 基本按构建层级固定赋值，冲突数据也包含别名和多值关系，因此不将其直接作为核心训练真值。

若后续人工校准证明来源层级和多源印证与正确率显著相关，可增加来源感知反馈消融；若未通过验证，则只保留确定性引用和人工复核机制，不影响主论文方法。

## 七、数据集与公开验证方案

### 7.1 雷达复杂问答数据完善

在现有题型基础上重点增加能区分类型化策略、扁平工具调用与单次检索的任务：

1. 三步以上关系链和路径后集合运算；
2. 两个或多个约束集合的交集、差集和嵌套计数；
3. 图查询后文本解释的跨模态任务；
4. 前一步实体集合驱动后续批量工具调用的数据流任务；
5. 空结果诊断、别名修复和替代路径选择任务。

问题生成后执行程序回放，只保留答案非空、程序可执行且支持事实完整的样本。dev/test 自动润色版本仍需人工检查问题与程序语义是否一致。

### 7.2 数据划分与泄漏控制

正式实验设置四类测试：

- IID 划分：检验总体学习效果；
- 实体隔离划分：核心问题实体不跨训练和测试；
- 算子/程序组合隔离划分：测试关系组合或算子树模板不在训练集中出现；
- 错误恢复测试：注入实体别名、非法参数、空结果或局部知识缺失，检验诊断、重规划和停止能力。

组合隔离划分是验证“学习组合策略而不是背模板”的主测试。还需检查答案实体重叠、正反问泄漏、自然语言近重复和公开集训练污染。

### 7.3 公开数据集

| 数据集 | 主要特点 | 在本研究中的作用 |
|---|---|---|
| KQA Pro | 117,970 个问题，提供 KoPL 程序、SPARQL 和答案，覆盖 27 类函数 | 验证类型化计划、集合、比较、计数和程序级反馈 |
| MetaQA | 电影领域知识图谱，提供 1/2/3-hop 问题 | 验证路径决策和跨领域多跳泛化 |
| GrailQA | 64,331 个问题，包含组合与零样本划分 | 时间允许时验证 schema 和组合泛化 |
| WebQSP / CWQ | 自然语言 Freebase 问答 | 时间允许时作为自然问题扩展 |

正式开题只承诺 KQA Pro 与 MetaQA。当前仓库已有 KQA Pro 完整 KB 与 11,797 条验证问题适配基础，实测可展开 362,023 条扁平三元组；MetaQA 需补充统一工具环境适配。

### 7.4 训练与测试使用原则

公开数据集有两种使用方式：

1. 域内训练：在公开训练集上重新进行 SFT/RL，与公开基线比较；
2. 跨域迁移：雷达数据训练后在公开集小样本或零样本测试，考察动作协议和组合能力迁移。

不将不同底层 KG、实体链接器或子图覆盖造成的差异简单归因于策略模型。雷达数据与公开数据集均分别报告环境 oracle、策略执行和最终答案三个层次：环境 oracle 衡量知识与工具能否支持金标答案，策略执行衡量动作与计划能否正确完成，最终答案衡量完整问答效果。

## 八、实验设计

### 8.1 核心 2×2 对照

核心实验以“动作空间设计 × 训练方式”为两个因素：

| 方法 | 动作空间 | 训练方式 | 主要作用 |
|---|---|---|---|
| 扁平 SFT | 通用工具名与自由参数 | 成功轨迹监督微调 | 基础策略模仿基线 |
| 类型化/分层 SFT | 宏动作、类型参数、变量和数据依赖 | 成功轨迹监督微调 | 验证 action-space design |
| 扁平 RL | 通用工具调用 | SFT 后基于可用环境反馈优化 | 检验扁平空间中的策略优化上限 |
| 完整方法 RL | 类型化计划与确定性执行 | SFT 后基于多粒度可执行反馈优化 | 同时解决动作空间与 credit assignment |

在 SFT 条件下比较扁平与类型化方法，验证动作空间设计价值；在策略优化条件下再次比较两种动作空间，检验结构化动作是否降低学习难度；在相同动作空间内比较 SFT 与 RL，验证执行反馈能否带来超越轨迹模仿的增益。四组方法统一基座模型、知识环境、训练问题、最大步数、检索预算和答案生成器。

### 8.2 外部基线与评价指标

外部参照包括 BM25-only、Vector-only、Hybrid RAG、单轮图检索增强方法、现有固定路由方法和 prompt-only ReAct；复现成本可控时加入 ToG、RoG、Search-R1 或 GraphRAG-R1。它们用于说明相对现有检索范式的总体收益，不替代核心 2×2 对照。

主要评价指标为：

- 答案指标：EM、Accuracy、集合 Precision/Recall/F1、计数误差；
- 计划指标：JSON/Schema 有效率、算子序列准确率、计划树执行等价率；
- 执行指标：工具成功率、变量绑定正确率、支持事实覆盖率、空执行率；
- 泛化指标：未见实体、未见关系组合和未见计划模板上的正确率；
- 恢复指标：错误检测率、重规划成功率、修复后正确率；
- 效率指标：平均调用数、轨迹长度、token、延迟和显存/训练时间。

### 8.3 消融与泛化实验

| 设置 | 验证问题 |
|---|---|
| 扁平动作 vs 类型化/分层动作 | 动作抽象是否降低计划错误和长程难度 |
| SFT-only vs 策略优化 | 执行反馈是否带来超越模仿的增益 |
| 仅答案奖励 vs 多粒度奖励 | 计划、进展和重复惩罚是否有效 |
| 去除类型检查 | 类型化协议对稳定性的贡献 |
| 去除重规划 | 错误恢复机制的独立贡献 |
| 去除图工具或文本工具 | 两种模态分别解决哪些问题 |
| 单轮限制 vs 多轮执行 | 环境交互与状态反馈的价值 |
| 不同成本系数 | 正确率与调用成本的权衡 |

所有核心方法均在 IID、实体隔离、算子/程序组合隔离和错误恢复测试上评估。组合隔离是主泛化实验，用于判断模型学习的是可迁移检索策略还是训练模板；错误恢复测试用于判断策略是否能利用执行观察修正后续动作。

### 8.4 统计分析

正式实验至少运行 3 个随机种子；对同一测试问题上的方法差异使用配对 bootstrap 置信区间或随机化检验。除总体结果外，按题型、计划深度、算子数量、实体是否未见和环境覆盖情况分组报告。失败案例分为任务识别、宏动作选择、参数生成、执行环境、知识缺失和终止错误。

### 8.5 最低成功标准

为了避免只在个别案例上证明有效，预先设定最低标准：

1. 类型化/分层 SFT 相对扁平 SFT 显著提高计划有效率或执行成功率；
2. 完整方法 RL 相对类型化/分层 SFT 在组合隔离测试集上取得统计显著增益；
3. 多粒度奖励相对仅答案奖励减少空执行或重复调用，同时不降低答案准确率；
4. 至少在一个公开数据集上复现同方向增益，或明确分析无增益来自环境覆盖而非选择性报告。

## 九、拟创新点

### 创新点一：面向复杂问答的类型化图检索决策建模

针对扁平工具空间大、长程调用不稳定的问题，将复杂图检索决策表示为宏动作、结构化参数、变量引用和数据依赖组成的类型化计划，并由确定性执行器完成路径、集合、计数、比较、聚合及图文协同操作。该方法解决 action-space design 问题，使语言模型负责语义规划，程序环境负责类型校验和精确计算。

### 创新点二：基于多粒度可执行反馈的图检索策略学习方法

利用知识图谱查询和类型化程序能够自动执行与验证的特点，在最终答案奖励之外，引入计划合法性、类型与变量依赖正确性、支持事实覆盖、状态进展、错误修复、重复调用和执行成本等反馈；采用成功轨迹 SFT 冷启动后进行策略优化，解决长程检索中的 credit assignment 问题。方法贡献是可执行反馈的构造与使用，而不是某种具体策略优化器。

组合泛化评测是上述两个方法创新的验证手段，不单独包装为算法创新。通过 IID、实体隔离、算子/程序组合隔离和错误恢复测试，以及 RadarKG-QA、KQA Pro 和 MetaQA 上的环境 oracle、策略执行与最终答案分层报告，检验方法适用边界。

> 创新表述保持克制：不使用“首次提出 Agentic GraphRAG”“首次使用 RL 训练图检索”或“经典层次化强化学习”等不准确表述。论文价值由类型化动作空间和多粒度可执行反馈两个核心方法贡献共同支撑。

## 十、可行性与风险控制

### 10.1 可行性依据

1. 已有类型化执行器、外层数据流计划和反思节点，无需从零构建环境；
2. 现有 5,401 道问题和 4,277 条成功轨迹可支持 SFT 与初始 RL；
3. 72 道组合题 99% 的原型结果证明计划树和执行器具备基本正确性；
4. 大量任务可由 KG 自动生成答案、程序和支持事实，奖励不依赖人工 Judge；
5. KQA Pro 提供显式程序，适合外部验证计划和执行奖励；
6. 题目不依赖置信度、某一种策略优化算法或特定参数规模模型，具有实现弹性。

### 10.2 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 类型化决策被认为只是工程封装 | 创新性不足 | 给出形式化动作定义、状态转移和扁平/类型化 2×2 严格对照 |
| 策略优化相对 SFT 无增益 | 第二项方法假设失败 | 强化组合隔离与错误恢复任务；分析反馈有效性、奖励方差与优化稳定性 |
| 过程奖励可被投机 | 轨迹变长但答案不提升 | 最终答案门控、重复状态惩罚、奖励上限和轨迹审计 |
| 模板数据导致虚高 | 泛化结论不成立 | 人工改写、组合隔离、实体隔离和公开数据集验证 |
| KG 缺失造成错误负奖励 | 训练目标有噪声 | 训练仅使用可闭世界验证子集；报告环境 oracle 上限 |
| KQA Pro 总体无增益 | 跨域验证失败 | 先解决子图覆盖和执行适配，按题型报告；不隐藏负结果 |
| 在线策略优化显存不足 | 无法完成大模型实验 | 先用 1.5B/3B LoRA 验证方法；成熟框架、量化和 offload；7B 为扩展 |
| 来源置信度未校准 | 扩展反馈不可靠 | 不进入核心奖励；通过人工校准后仅作附加消融 |

### 10.3 研究边界

本论文研究复杂检索与问答策略，不将知识图谱持续自更新、完整电子战对抗策略学习和大规模多模态知识抽取同时纳入主线。现有对抗建议、报告和 Streamlit 系统可作为应用展示，不作为新增算法创新。

## 十四、开题答辩的核心表述

### 14.1 一句话主张

本研究将复杂雷达情报问答视为可执行图检索策略学习问题：策略模型生成类型化查询计划，确定性执行器完成图路径、集合和聚合计算，再利用多粒度执行结果优化后续检索策略。

### 14.2 为什么需要类型化/分层决策

复杂问题同时包含语义分解和精确计算。完全交给 LLM 容易实体漂移，完全依赖固定程序又缺乏自然语言适应性。类型化/分层设计让语言策略处理语义和宏动作，确定性执行器保证类型、计算与复现。它是动作空间设计，不是经典层次化强化学习，因为低层执行器不是独立学习策略。

### 14.3 为什么需要执行反馈策略学习

SFT 主要模仿已有成功轨迹，难以充分利用失败尝试和环境反馈。进一步的策略优化可以比较同一问题的多条计划，根据答案、计划合法性、执行进展和成本提高更优轨迹的概率，并学习在空结果或错误参数后重规划。RL 是可选的优化实现，核心研究对象是多粒度可执行反馈如何改善信用分配。

### 14.4 为什么不是已有 Graph-R1 的重复

Graph-R1 系列主要训练自然语言查询和检索调用；本研究的动作是具有输入输出类型的算子和计划树，执行环境包含集合、计数、差集、聚合和变量数据流，反馈直接利用计划类型与中间执行状态。是否形成有效差异，将通过相同基座和环境下的扁平/类型化 2×2 对照验证。

### 14.5 来源与置信度如何定位

来源、置信度和冲突不是题目或主创新。它们未校准时只用于引用展示；校准后有增益才作为扩展反馈实验。因此该扩展失败不会影响论文主线。

## 文档结论

本方案将论文统一抽象为复杂领域问答中的可执行图检索策略学习问题，并形成两个递进的方法贡献：以类型化计划和确定性执行解决 action-space design，以多粒度可执行反馈和策略优化解决 credit assignment。组合隔离、错误恢复和公开数据集实验用于验证策略是否具备超越模板模仿的泛化能力；来源与置信度仅作可选扩展。由此形成“复杂雷达情报问答 → 复杂组合检索需求 → 类型化可执行图检索决策 → 多粒度执行反馈 → SFT 与策略优化 → 组合泛化图检索策略 → 雷达数据和公开 KGQA 验证”的统一主线。
