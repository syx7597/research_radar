# 查询修复第二轮有界开发协议

冻结日期：2026-09-26。本协议在v1的2,000题结果及错误分析之后制定，属于第二轮有记录的开发，不是v1的事前假设。v1算法、冻结策略、首次holdout结果和所有失败结果保持原样；本轮代码、策略和结果另存v2目录。截至本协议冻结，尚未对本轮完整官方validation做结果评估。

## 1. 修改依据与唯一算法变化

v1事后分析发现：20个从基线正确变为错误的案例中，19个覆盖了原本`schema_clean`的first-valid候选。这一观察只用于提出保守保护假设，不作为v2已经有效的证据。原2,000题从此明确转为**已见诊断集**；只有首次冻结v1评估仍可称为当时的holdout结果，不能把在同一集合上跑出的v2改进当作独立验证。

本轮唯一新增机制为首个可执行原查询的保护规则：

```text
fallback = 原4候选中排名最先、执行合法的候选
如果 fallback 存在且 schema_clean 为真：直接返回 fallback
否则：使用原评分与接受策略选择修复，失败则保留原 fallback
```

`schema_clean`沿用v1可观测判据，即整个程序的字段角色合法且不存在显式函数类型冲突；不读取金标，不依据答案非空或正确性判断。合法空集、0、否定答案同样受到保护。无可执行原候选、或原first-valid含schema/类型冲突时，继续沿用v1的有界修复机制。

global和local均应用同一保护规则。固定BART、训练数据、实体与数值等编辑保护、字段匹配公式、候选分配与每题至多4个新增候选、单字段单轮限制、局部前缀规则、教师强制评分方法、执行器适配层和候选执行语义均保持不变。不增加训练、召回扩展、同义词规则或按题型制定的新策略。

该保护规则只是降低误修改的候选方法，不能从schema合法推出原答案正确。它可能放弃可纠正的语义错误；同时保护global后，local是否仍有额外价值须由对照结果决定。

## 2. 校准、旧数据与冻结边界

- 使用原calibration的500题重新选择global/local参数，两者使用相同73项网格：关闭修复，或`alpha ∈ {0, 0.25, 0.5}`、`min_match ∈ {0, 0.4, 0.6, 0.8}`、`margin ∈ {-0.25, 0, 0.1, 0.25, 0.5, 1.0}`。评分仍为`tf_mean + alpha × match`；择优及并列规则完全沿用[v1协议](QUERY_REPAIR_PROTOCOL.md)。
- 原500题dev仅作开发检查，检查保护规则、覆盖及回退行为。原2,000题已经用于提出本轮假设，只能报告事后诊断；不依据其准确率、子集结果、最优阈值或具体答案重选参数。
- 保存全部校准尝试、最终策略、代码/模型权重/KB/执行器/划分/缓存哈希和运行环境。`PYTHONHASHSEED=20260926`继续用于所有执行进程。v2的策略和实现单独冻结，不修改v1算法文件及冻结记录。
- 在完整官方validation评分前固定所有配置。校准或dev检查未见收益时仍可完成预定完整评估，但不得再增添其他算法机制来追求正结果。

## 3. 官方validation全量准备与数据限制

`python3 -m experiments.condition_consistency.prepare_repair_val`复核固定数据文件SHA256，完整保留official val的11,797题及原始顺序。每题使用`val:<原始索引>`作为ID，不按类别、可执行性、答案、难度或模型表现删选。金标程序仅用于与训练、校准及既有开发划分的精确重叠检查；准备阶段不执行金标程序、不分析答案、不计算模型成绩。

输出分别为：

- `data/condition_consistency/repair_splits/official_val.questions.jsonl`：仅ID、问题，用于生成和修复。
- `data/condition_consistency/repair_splits/official_val.gold.jsonl`：独立离线评分文件，包含问题、程序、答案。
- `results/condition_consistency/query_repair/v2/official_val_manifest.json`：全部ID、计数、原始及派生文件哈希、与generator_train/calibration等划分的归一化问题和完整程序重叠检查。

原训练划分已排除与official val问题或完整程序重叠的整个组件，本次再次核验所用5,000训练题及500校准题零精确交叠，同时记录其他开发划分的检查。精确去重不等于语义无相似题，也不改变其validation身份。

**这是公开validation，不是hidden test。旧项目曾使用该集合，必须持续披露；不能称它为项目从未见过的数据。** 本轮仅承诺在本轮完整评估前冻结v2算法和参数、全量一次评分并保留结果。官方validation承担扩展公开评估，不抹去v1后验开发或旧项目使用历史。

## 4. 方法对照与评价

所有方法使用同一固定生成器及同一修正执行器：beam4 first-valid、beam8 first-valid、带同一保护规则的global repair、带同一保护规则的local repair。必要的无保护/无接受策略结果须标记为冻结消融，不能根据validation表现选择新的主方法。不能只比较“无保护global”和“有保护local”来宣称局部约束有效。

采用全部11,797题分母，保留生成失败、解析失败、超时、合法空结果及金标疑点。报告答案准确率、相对beam4/beam8/global的净纠正及改错、2,000次问题级配对bootstrap的95%区间（种子20260926）、保护触发率、候选覆盖上限、实际候选/执行次数、token开销和延迟。候选数量相同不等于计算开销相同。

v2首次完整validation评分不与旧条件的pilot准确率直接相减。算法增益均相对本轮同一候选与执行条件下的基线。若global与local相当、local劣于global或收益主要来自保护规则，应明确结论，不将全部提升归因于局部知识约束。

## 5. 本轮截止条件

**完整official val一次评估完成后停止本轮调参，不再追逐更好结果。** 保存首次完整结果和负结果，不换评测集合、不按错误新增规则、不重训后重报为同一次冻结实验。随后只做结果解释、研究范围决策与论文记录。

这仍是单个生成器种子的可行性实验；若方法有价值，后续多种子正式研究须另立协议并完整披露已使用的开发数据。若未超过合理对照，则收缩创新主张或更换研究问题，不把本轮工程完善包装成已验证的新算法贡献。
