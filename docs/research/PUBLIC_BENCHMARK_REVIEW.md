# 公开基准与近邻方法核验

核验日期：2026-09-26。本文区分论文/源码事实与项目建议；未在本机复现外部训练，也不据此保证改进有效或具有创新性。

## 结论与候选问题

优先在 **KQA Pro 的复杂条件查询** 上建立公共证据，再将方法迁移到经过人工核验的雷达知识库。自建问答数据承担工程验证与领域适用性展示，不承担方法有效性的主要证明。

候选问题收窄为：**程序语法正确、能执行，却将限定条件绑定到错误事实、遗漏条件或弄错条件作用域。**
待检验的是：显式表示“哪个条件约束哪个事实”，并使用经执行筛选的针对性错误样本，能否改善小模型的候选程序选择。
“增加执行器”“类型化动作”“难负例”“重排器”“SFT 后做 RL”都已有近邻，不能作为独立创新主张。

## 已核验的直接近邻

| 工作 | 已做内容 | 对当前选题的约束 |
|---|---|---|
| [KBQA-R1](https://arxiv.org/html/2512.10999v2) | 类型化动作、多轮执行反馈、参考动作生成 SFT 轨迹、GRPO、邻接关系检索与置信度门控 | 原有 Agent+SFT+RL 主线重叠明显；论文给定已链接的问题实体，使用 8×A100-80GB，不宜作为默认资源配置 |
| [ISP-KGR，ACL 2026](https://aclanthology.org/2026.findings-acl.1023.pdf) | 逐步生成可执行逻辑子句，树状 rollout，以图距离构造过程奖励 | “从结果奖励走向过程奖励”已有直接研究；论文用 4×A6000-48GB；[官方代码](https://github.com/NUSTM/ISP-KGR) 有训练插件及 KG 服务，但本轮未实际部署 |
| [PO-KGQA，ACL 2026](https://aclanthology.org/2026.findings-acl.2083.pdf) | 低资源小模型、LoRA、SFT 后迭代偏好优化、KoPL 执行与 grounding | “1,000 条数据+偏好优化+执行反馈”已被研究；需要在负例机制、事实条件表示及真实错误上建立具体差异 |
| [Semantic Parsing with Candidate Expressions](https://arxiv.org/pdf/2410.00414) | 类型与候选表达式约束解码，BART 语义解析，强/弱监督实验 | 不能把一般类型约束或限制候选集合称为新方法；[代码](https://github.com/daehwannam/candexpr-sp) 提供训练和消融入口，但环境较旧，尚未复现 |
| [CodeAlignKGQA，COLING 2025](https://aclanthology.org/2025.coling-main.267/) | 知识约束的 KoPL 代码生成和动态纠错 | “代码式程序生成+纠错”已有先例 |
| [Correcting on Graph，ACL Findings 2025](https://github.com/HUSTNLP-codes/CoG-ACL-2025) | 生成知识路径，并通过 KG 修正实体幻觉和路径缺陷 | 一般图上纠错不是新切口；其路径修正与本项目拟关注的限定条件绑定需明确区分 |
| [Du 等，KBS 2023](https://www.sciencedirect.com/science/article/pii/S0950705123007463) | 出版社摘要/引言明确包括语义正负样本、hard negatives、对比学习和候选逻辑形式重排 | 与“难负例+重排器”高度相关；**未取得完整方法和官方实现，不能断言它没有做单编辑或条件扰动** |

以下交叉领域近邻本轮只核验官方摘要/有限段落，尚未完整检查方法与实现，必须在正式声称创新前补读：

- [SemCL，EMNLP 2022](https://aclanthology.org/2022.emnlp-main.269/)：细粒度语义区分、多层负例采样和对比学习，说明“语义相近但逻辑错误的负例”已有基础。
- [SNOWBALL，ACL Findings 2021](https://aclanthology.org/2021.findings-acl.388/)：逻辑一致性生成、规则逻辑扰动和质量控制，与扰动构造及一致性评价存在方法重叠。
- [CAPER，2026 预印本](https://arxiv.org/abs/2606.03327)：SQL AST 干预、子句级过程监督和候选验证。**换成 KoPL 本身不构成充分区别**；需检验 KG 事实限定符的作用域/绑定是否带来独有问题与有效机制。

## PO-KGQA 的论文与源码事实

[论文 §3.2](https://aclanthology.org/2026.findings-acl.2083.pdf) 每轮让当前模型 greedy 生成程序；只有执行答案错误时，才构造“金标程序优于生成程序”的偏好对。自然失败样本可能含漏条件或错误比较，不能说该方法完全不处理这些错误。碰巧答对的错误程序被排除出偏好数据，而不是被进一步识别。

实际读取了官方 [cand_gen.py](https://github.com/data-iitd/PO-KGQA/blob/main/cand_gen.py) 与训练入口：

- 主流程每题生成一个 greedy 候选，`do_sample=False`、`max_new_tokens=256`，再保存金标程序；未见该文件定义定向程序变异。
- `get_entities_concepts(program_json)` 从金标程序提取实体和概念，并加入模型输入。复现必须标记为提供金标链接的解析设定，不能与端到端问答直接比较。
- 文件包含前 1,000 条截断、`../scratch` 路径及 `config.ini` 依赖。[训练入口](https://github.com/data-iitd/PO-KGQA/blob/main/irpo_after_sft.py) 确有偏好训练流程，但仍需配置适配，未验证开箱可训。

当前可测区别不是“首次利用错误程序”，而是：**在相同数据和推理预算下，针对事实限定条件作用域/绑定构造和表示错误，是否优于自然失败采样及一般合法变异。**

## 基准选择与环境成本

| 数据集 | 标签与执行资源 | 本项目用途 |
|---|---|---|
| [KQA Pro](https://github.com/shijx12/KQAPro_Baselines) | train 94,376、val 11,797、test 11,797；train/val 有程序和答案；[KoPL](https://github.com/THU-KEG/KoPL) 可执行本地 JSON KB | 主基准：包含 qualifier、比较、集合与计数；优先采用原生 KoPL，避免先部署大规模 Freebase |
| [Overnight](https://aclanthology.org/P15-1129/) | 8 个领域、自然语言与逻辑形式；可通过 [GraphQ IR](https://github.com/Flitternie/GraphQ_IR) 或 candexpr-sp 的数据/执行适配进入，λ-DCS 执行依赖需验证 | 第二基准候选：检验不同 schema 的条件组合；不是证明雷达事实限定符能力的直接替代 |
| [GrailQA](https://dki-lab.github.io/GrailQA/) | 64,331 题；IID、组合、zero-shot 分层；train/dev 标签公开，test 金标隐藏；官方推荐 Freebase/Virtuoso | 若主张未见 schema/组合泛化，应优先考虑；环境成本高于本地 KoPL，首阶段不同时铺开 |
| [MetaQA](https://github.com/yuyuz/MetaQA) | 本地电影三元组，公开 train/dev/test 问答；1–3 跳，问题实体有标记 | 执行器和多跳迁移的辅助检查；模板化路径查询不直接覆盖目标条件绑定，不能作为主要创新证据 |

Overnight 的常用实现会从原始训练部分再取开发集，需固定采用的版本、领域设置及划分脚本；不能混合不同实现的结果。其规模、划分和 SEMPRE 执行方式可参照 [Candidate Expressions §7](https://arxiv.org/pdf/2410.00414)。

## 官方 test 与公共 val 的报告规范

KQA Pro 的官方 test 金标未公开；[Candidate Expressions §7](https://arxiv.org/pdf/2410.00414) 明确说明这一限制。GrailQA [官方说明](https://dki-lab.github.io/GrailQA/) 同样保留隐藏 test 标签。

1. 从 KQA Pro **train 内部**划出开发集，用于超参数、候选数和停止条件选择；所有训练样本及其扰动只来自训练部分。
2. 原始 val 作为冻结公共报告集时，结果明确写为 **KQA Pro official validation set**，不能改称官方 test。
3. 若持续用 val 分析错误并调整方法，它就已承担开发用途；需另留未接触的评估集，并公开用途变更。
4. 官方 test 需要按维护者协议提交；本轮没有验证评测服务响应，不保证能获得官方 test 分数。
5. 同时报告完整集合、预先定义的条件类型子集；若只跑抽样，公开 ID、种子及抽样规则，不与完整集分数混比。
6. 自定义组合划分和合成扰动挑战集作为补充，不能替代原始公开分布；同时报告自然问题上的实际收益。
7. 推理阶段不得输入金标程序、答案、错误位置或由金标程序提取的候选，除非明确作为独立 oracle 设定报告。

## 强基线与公平预算

[Candidate Expressions 表 6](https://arxiv.org/pdf/2410.00414) 的 BART-base 在完整监督、候选类型约束下，greedy 为 val **92.96%**、test **92.60%**；beam=4 为 val **93.17%**、test **92.81%**。其 BART-large beam=4 的 val 为 **93.34%**（表 8）。这些是不同监督/模型配置的文献结果，尚未本地复现，不能与少样本配置直接排名。

公开基准已有强小型解析器。因此，项目可以主张固定低资源预算的改善，但不能只超过普通 Top-K RAG 或弱 zero-shot 提示就宣称方法先进。

最低对照组：相同生成器的 top1、候选 log-probability 排序、仅执行合法性过滤、普通自然负例重排、一般合法变异重排、拟议条件绑定方法。另尝试强 BART/约束解析基线；若无法复现，记录失败原因并保留文献参照。

必须统一或分别披露：训练问题数、负例数、训练步数、基础模型、实体/关系链接设定、候选数 K、生成 token 数、工具调用数和推理延迟。不能把多次生成得到的收益全部归因于重排方法。

起步不预设多卡 RL：先跑候选生成与轻量判别/重排实验，资源规模由实际 GPU 和延迟测量决定。RL 只有在受控实验能证明额外收益后才作为扩展。

## 开工门槛与可证伪实验

- **先测错误空间：** 对真实基线错误做人工分类，区分语法/类型、grounding、缺知识和限定条件绑定；若目标错误很少，应收缩或放弃切口。
- **先测候选上限：** 统计 K=4/8 的 oracle answer accuracy 与 top1 差距；如果正确候选几乎不存在，重排不是合适方案。
- **负例标签可靠性：** 首批仅保留合法执行且答案变化的条件变异；不要把所有不同于金标字符串的程序标为错。
- **语义等价处理：** 加入等价正例，控制程序长度与函数数，防止判别器依赖表面差异；答案相同但条件错误需独立人工/逻辑证据，单独评估。
- **测试真实泛化：** 同预算比较自然失败负例、随机合法变异、定向条件变异；留出编辑类型/条件组合，并另测未经人工扰动的完整公共数据。
- **报告不确定性：** 固定开发决策后报告多种子或配对置信区间；不给定必须增长多少的保证，不以单一挑选子集支撑结论。

## 向雷达知识库迁移的边界

候选关联点是知识表示：同型号不同版本/时间/工作模式下的属性、数值和单位，以及限定条件应附着于哪条事实。方法若在公开数据成立，再构建少量独立人工核验的领域问题，检查模型是否保持同样的条件绑定能力。

原始三元组如果已丢失事实限定条件，重排器无法恢复它；迁移前须把来源和条件表示完整。单位转换与事实限定符不是同一问题，也不能把 KQA 上的增益自动解释为领域单位推理已解决。

**当前结论：这是一条可用公开数据进行低成本证伪的候选路线。工程实现有现成基础，目标误差是否足够、区别是否成立、收益是否可迁移，仍需实验与进一步近邻核验。**
