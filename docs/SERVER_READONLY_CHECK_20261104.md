## 实际观察

1. **四卡确有计算占用。** 绕过命令行工具，直接调用 NVML，四卡利用率均为 100%，显存使用为约 13,725–13,982 MiB。两项计算进程为 PID 1628885 和 2256203，各在每张卡上占约 6,662 MiB。这次读取没有创建 CUDA 工作负载。
2. **PID 1628885 的 proc 目录被覆盖。** /proc/self/mountinfo 包含挂载点 /proc/1628885，文件系统为 tmpfs。该目录存在但内容为空，读取 status、exe、cwd 均得到文件不存在。NVML 同时仍报告此 PID 使用 GPU。这解释了之前“GPU 有进程但 ps/proc 无法确认”的一项具体原因。
3. **PID 2256203 是 root 身份进程。** 可读状态显示名称 sshd、UID/GID 为 0、20 个线程。syx 对其 exe 和 cwd 没有读取权限，因此本次没有确认它对应的真实可执行文件。进程名称本身不能用来证明其身份。
4. **两个系统命令与安装包记录不一致。** /usr/bin/uptime 和 /usr/bin/nvidia-smi 的实际 MD5 与各自 dpkg 安装清单中的 MD5 不同。本次校验后没有继续执行这两个路径。
5. **全局预加载配置残留。** /etc/ld.so.preload 引用了不存在的 /usr/local/lib/libaudit.so，对应当前持续出现的动态链接器错误。
6. **存在异常 Python 路径。** /usr/sbin/python3 为 UID 14 所有、36,332,912 字节的 ELF 文件，未找到 dpkg 文件归属。本次没有执行它。
