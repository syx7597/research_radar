## 3. 方法、答案与训练目标

主方法继续是**利用真实执行历史构造恢复后缀监督**。这次完成的是让该方法直接解决雷达参数组合问题所需的数据和执行环境。

查询操作包括 `Scan / Expand / Project / Join / Filter / Derive / Assess / Assemble`，最后通过 `finish` 提交答案句柄。每个中间结果有固定编号，表格单元保留来源。程序能够按型号与供电条件连接参数、按量值范围筛选、判断部件是否满足温度规格，并返回完整表格及依据。

主评分核对完整答案中的值、单位、边界、条件、配对与来源。兼容单位可以换算，行序和列展示顺序不影响判断；来源记录不能被改写。空表保留实际候选范围与筛选条件，“资料未确立联合配置”具有独立状态，未提交答案计执行失败。辅助指标包括完成率、无效调用数、工具调用数及输入/生成token。

完整开发案例：JMA-5200Mk2资料给出的扫描器温度范围为−25至55°C，处理器、显示器与键盘为−15至55°C。五次调用完成两类部件的范围读取及−20°C包含判断，分别返回范围内、范围外。若中途多执行一次查询，恢复构造保留真实反馈并重新映射后缀句柄，最终仍返回同一完整答案。案例数据见[执行摘要](../results/radar_domain/programs_dev_20261107/development_case.json)，论文图4.2给出具体句柄变化。

12题各构造两种接口测试状态：额外有效查询、被拒绝的动作，共24组。保存的原始fixture用于检查恢复逻辑；实际token配平在 `balanced_pair` 阶段完成，原始fixture与配平输出均标记不可正式训练。真正的恢复样本必须来自 `I_domain` 在训练题上的模型自由运行，且通过文件、模型和实现哈希、来源标记、全题覆盖及重放检查。

实际分词结果：708条参考的最大上下文8228 token；24组恢复测试最大8616 token。统一登记上下文16384、单轮生成192、总生成2048、最多24次调用。无截断。见[分词预检](../results/radar_domain/frozen_20261107/token_preflight.json)与[恢复验证](../results/radar_domain/recovery_contract_20261107/summary.json)。

独立审阅发现离散选项父级单位没有归一化，可能把等价的kW/W选项误判。已按统一评分规范修正，并增加等价与不兼容单位测试。[评分修订](../results/radar_domain/frozen_20261107/scoring_revision.json)保存修改前后代码哈希与旧源码位置；冻结数据和原manifest保持不变。[独立最终审计](../results/radar_domain/frozen_20261107/independent_audit.json)记录全部核对结果。

## 5. 下一步按什么顺序执行

当前研究主线保持为：**公开数据验证恢复轨迹监督 → 雷达来源知识与条件表示 → 域内组合查询的配对训练与应用评价。** 公开项目留出平均+4.75个百分点的结果、原领域迁移结果和条件绑定表示结果继续沿用原实验记录。

1. **计算环境恢复后核验模型与运行条件。** 使用普通实验账号核对现有权重、运行环境及空闲GPU，在开发材料上完成短测并冻结实际训练参数与运行清单。服务器当前暂停使用。
2. **补齐已登记的公开同状态评价。** 继续原2400题设计，统一正常/偏离状态及预算；本轮上限9小时5分钟GPU时间，沿用原协议。
3. **训练共同域内初始模型。** 以Qwen2.5-3B-Instruct和576条合成成功轨迹完成 `I_domain`。在96条合成开发题与12条真实开发题上分别报告调用、完成和完整答案表现。检查是否学会跨记录操作及条件处理。
4. **采集训练失败并开展配对续训。** 固定 `I_domain` 的训练集自由轨迹，筛出可重放恢复样本。从同一初始检查点训练普通后缀组 `A_domain` 与恢复组 `C_domain`，匹配问题、顺序及监督token。首轮训练与开发推理共用原8 GPU小时上限。若失败样本或恢复配对不足，先根据开发证据诊断原因并记录，不用人工fixture补成真实失败。
5. **确定方案后运行24题新来源评价。** 使用同一目录、工具、解码与预算，报告完整分母、四来源分组、任务类型及成本。开发收益值得复现时优先追加同方案配对种子；评价结果用于结论，不用于反向挑题或修改标签。
