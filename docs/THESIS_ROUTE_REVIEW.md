# 论文整体路线审查（讨论稿，尚未确定新算法）

执行细化已完成第一版：[方法论证](research/METHOD_FEASIBILITY_BRIEF.md)包含已有开发缓存的瓶颈统计、三项近邻、基础对照及开训门槛；[雷达标注规范](research/RADAR_DATA_ANNOTATION.md)给出来源核验样例和模板。具体任务以[当前计划](ROADMAP.md)为准。

日期：2026-09-26。按用户要求，暂停新算法实验和训练，先明确完整论文路线。用户已说明题目可以调整，不必保留策略学习或强化学习，预计六个月后提交。本稿整合既有开题、数据审计和预实验，是供讨论的论文范围，不代表算法有效性已成立。前一份负例训练建议降为候选，不能作为自动开训指令。

## 1. 需要纠正的判断

原开题的工程主干可用：资料构建知识环境，模型生成结构化检索计划，确定性执行器负责查询与计算，系统返回证据。当前结果没有否定这条主干，也没有验证或否定原设想的完整SFT/RL方法。

尚未成立的是类型化表示的独立创新、多粒度反馈的增量、RL相对SFT的收益，以及自生成雷达问答能否支撑真实泛化结论。旧RL代码存在实现问题，属于修复与资源风险，不等于研究思想不可行。图检索执行反馈已有[KBQA-R1](https://arxiv.org/abs/2512.10999)等近邻，既说明路线有研究基础，也要求给出实质区别。

此前把小型修复试验迅速写入论文主线，并在公平强对照补齐前提出扩大验证，次序不合适。现有实验应保留为诊断和负结果，不能将试验过程的每次转向都变成新开题。

## 2. 稳定研究对象与全流程

建议保持的研究问题：**在来源分散、标注有限的雷达知识环境中，怎样把包含多个条件、关联和统计要求的问题正确转化为可执行查询，并返回可核查的答案？**

建议工作题目：**面向雷达领域的知识构建与复杂约束问答方法研究**。题目保持研究对象稳定，具体方法章节在机制论证和实验支持后确定，不预先绑定RL、修复或某一种损失函数。

研究对象是知识问答，不是雷达信号处理，也不依赖某个修复规则、模型名称或优化器。主线包括知识资源、语义解析与执行、公开验证及领域应用四部分。方法证据优先在公开数据建立；雷达知识整理可并行，不能只依靠自建测试集论证方法。

```text
雷达原始资料
  → 保留来源的事实抽取、实体归一和数值/单位规范化
  → 结构化知识库 + 可追溯证据文本
                               ↓
自然问题 → 实体/schema映射 → 可执行查询计划 → 确定性执行 → 答案与证据
                 ↑                 ↑
           公开KQA任务用于方法训练、对照和验证

原文独立核验的雷达问答集 → 领域应用评测
```

英文KQA与中文雷达问题共享的是方法及执行设计，不能默认直接迁移同一BART权重。需要明确中文解析器、领域字段及实体适配；在两域内分别对相同输入和知识条件做方法对照，不将模型或语言差异算成算法收益。

## 3. 必须区分的三类数据

| 对象 | 用途 | 当前事实与需补工作 |
|---|---|---|
| 雷达知识资源：事实、属性、文本、来源 | 系统回答问题的依据 | 已有21,928条边、10,744实体及图文检索基础；需抽样核验事实、实体合并、单位与来源。已有属性缺少结构化条件，不能凭常识补造 |
| 训练/开发问答与程序 | 让解析器学习任务与调试流程 | 已有5,401题和4,277条SFT轨迹。由同一图谱自动生成并回放，只证明内部一致性，不能替代真实事实和自然问题质量 |
| 独立评价问答与证据 | 检验方法与应用效果 | 公开KQA承担主要方法证据；雷达需从原始材料独立编题、核对答案和证据，冻结后按来源/型号家族隔离。旧自生成test不能冒充独立人工金标 |

雷达核验可从20–30个型号和100–150题的可管理范围起步，最终规模取决于原文质量与实际时间。这个规模适合作应用验证，不能单独支撑广泛泛化结论。数值记录保留原值、原单位、规范值、区间端点及原文明确存在的条件；条件缺失明确标记未知。

例：问题要求统计“资料中明确记录满足频段与距离阈值的型号”。应先解析约束，核对属性含义与单位，在支持比较的事实中筛选并计数，再列出证据；未记录距离的型号不能直接当成不满足，更不能将局部资料计数说成现实世界全部数量。这同时约束知识构建和问答行为。

## 4. 问答模块的范围

核心任务先限定在结构化事实查询、多条件筛选、关联查询和统计比较。模型负责理解问题、定位实体与字段、生成计划；执行器负责类型检查、关系查询、集合和数值运算；输出模块负责答案和来源展示。文本检索为解释性问题提供补充，不必同时把复杂图文路由也做成新的学习算法。

应研究的核心方法问题是**生成的可执行计划是否忠实表达问题条件**。语法合法、能执行和最终答案碰巧相同，都不能单独保证语义正确。字段映射、条件绑定、关系方向、实体链接和计划结构应分别诊断，不能全部归为同一种“条件错误”。

## 5. 对新负例训练的现实判断

判断为：有机制上的理由，但当前项目证据不足，暂不列为已定主算法。

支持理由是更新生成器能够改变正确候选覆盖，避开纯重排的固定候选限制。限制是当前错误异质，旧500题审计中的结构差异、字段、实体等问题不能由一种单点负例统一解决；此前严格匹配只留下166对训练样本，且存在空结果和题面/金标噪声。尚未证明目标混淆是主要瓶颈，也没有依据承诺总体涨幅或超过强对照。

[SemCL](https://aclanthology.org/2022.emnlp-main.269/)和[PO-KGQA](https://aclanthology.org/2026.findings-acl.2083/)已有语义对比与偏好训练。只有当特定样本机制能解释、覆盖真实错误并超过普通错误训练，才可能形成小方法贡献。不能因常见技术有效就推定本项目组合具有创新性。

当前单字段修复停止开发。生成器负例训练保留为候选；用户确认不必保留RL，因此六个月计划不将在线强化学习作为必做项。当前修复负结果没有验证或否定完整RL方案，单次BART程序生成也不能被重新命名为多轮交互策略学习。

后续已完成[字段合法性约束的500题对照](research/SCHEMA_PILOT_RESULTS.md)：80.4%相对普通beam4的80.2%只净增1题，未显示可靠优势且更慢。停止继续调该模块，12个剩余单点合法谓词差异仍待语义核查，不据此直接启动负例训练。

## 6. 三层评价，避免互相掩盖错误

| 层次 | 固定什么 | 验证什么 |
|---|---|---|
| 知识构建质量 | 抽样原文与核验标准 | 事实是否有证据、实体是否正确归一、数值/单位/区间是否保真；不以三元组条数替代质量 |
| 公开方法验证 | 相同KB、训练问题与推理预算 | 自然问题答案准确率、计划语义错误与候选覆盖；对照含普通SFT、执行筛选、扩候选及同保护对照，训练方案还须比较同预算继续SFT和普通负例 |
| 雷达应用验证 | 独立题目、来源和知识版本 | 分别在人工核验图上测问答模块，在原始抽取图上测端到端系统；报告事实缺失、抽取、语言/实体适配与计划错误 |

公开数据已有访问历史必须披露。后续评价用途、隔离方案和冻结时点先写进协议，不能反复挑新集合追求正结果。雷达RAG与图查询系统应尽可能使用同一资料和可比预算；不能仅通过给某方法更完整知识制造算法收益。

## 7. 论文内容与贡献边界

可围绕“绪论与相关工作 → 雷达知识资源与任务构建 → 可执行复杂问答方法 → 公开对照与误差分析 → 雷达应用及系统 → 总结”组织。

知识资源规范化与独立评价集属于数据/工程贡献；一个有证据的小方法改进属于算法贡献候选；可执行查询和证据展示属于系统应用贡献。已有类型化执行、通用SFT、RAG和单位转换不能仅因组装在一起就被称为原创算法。

若学位要求必须有明确方法创新，现有系统和资源不能自动填补尚未成立的算法部分；具体要求需与正式开题和导师口径一致。论文框架可以稳定，算法候选允许被否定，不能承诺尚未实现的结果。

## 8. 下一步先完成方向论证，不开训

在现有材料基础上形成一份短的可审查方法说明，只选择一个具体瓶颈，回答：

1. 对应哪些自然问题与已有错误，范围和证据是什么？
2. 当前最强简单方案为什么解决不了，拟议机制补在哪里？
3. 近邻论文已经做了什么，实际区别是什么？
4. 需要什么训练信号，能否取得且无需测试答案？
5. 如何区分真实机制收益与额外数据、训练量、候选数的收益？
6. 一次最小试验的预算、开发次数和停止条件是什么？

方向说明与已有技术基础对照现已补齐，见[方法论证](research/METHOD_FEASIBILITY_BRIEF.md)及上述500题报告。对候选训练假设H，这些问题尚未说清，不开始新的训练或算法模块扩展；负例训练建议不会自动升级为论文路线。继续利用已有文献、结果和错误记录完成机制判断，不重新进行全量试验。
