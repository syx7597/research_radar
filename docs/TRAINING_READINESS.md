## 正式训练前的阻断项

### 1. SFT 输入拼接丢失 assistant 角色头

[`train_sft.py`](../ca_agraphrag/train_sft.py) 的 `build_example()` 在 assistant 轮使用含 generation prompt 的前缀长度切掉 `cur` 的开头，然后只拼接新段。由于此前累积的 `input_ids` 并不包含这个 generation prompt，最终输入遗漏 assistant 角色头。已用无需外部依赖的字符级假 tokenizer 复现：两轮 assistant 的拼接结果缺失两个 `<assistant>`，不等于整段对话的 chat template 输出。

验收要求：完整 `input_ids` 与整段 chat template 的 token 序列逐 token 一致；只有 assistant 内容及明确约定的结束 token 计 loss；system、user、tool 和 padding 均为 `-100`。须用实际基座 tokenizer 进行覆盖多轮和截断的断言测试。现有 `--dry` 只打印少量片段，没有验证这些不变量，不能作为训练就绪证明。本轮未改训练脚本。

### 2. GRPO 目标、参考模型与运行方式未闭环

[`train_grpo.py`](../ca_agraphrag/train_grpo.py) 存在以下源码可见问题：

- 文档描述参考策略是冻结的 SFT 权重，实际 `ref` 仅加载基座，未加载 SFT adapter。
- 所谓 KL 为采样序列上的 `(logp_policy - logp_ref)`。参考项在 `no_grad` 下是常数，当前显式梯度不依赖参考概率，不能据此宣称实现了正确的 KL 正则；须先确定采用的目标及其梯度估计，使用经过验证的训练实现或补数值检验。
- 脚本是按组标准化奖励的 REINFORCE 原型，未实现概率比率裁剪等完整 GRPO 训练机制。论文和日志须如实命名。
- 文档给出 `accelerate launch --multi_gpu --num_processes 4`，代码却没有 Accelerator/DDP 初始化、rank 数据划分与单 rank 保存；每个进程都用 `device_map="auto"` 载入模型并遍历全量数据。不能将此命令视为已支持四卡训练。
- 生成 token 先 decode（跳过特殊 token），完整对话再 tokenize，却按原始生成长度标注 mask。实际 tokenizer 下是否发生边界错位尚未验证，必须检查生成 token 与最终序列片段逐 token 一致。
- 每个更新保留多条完整序列的前向图，且训练 rollout 与 eval 模式、随机种子、断点恢复、尾批次处理、显存峰值尚未验证。先做单卡最小更新与梯度/内存检查，再扩展。

前四项由静态源码可确认；token 边界和显存是待实际 tokenizer/GPU 验证的风险。本轮未调用该训练流程。

### 3. 环境与训练器的奖励定义不同

当前工具步骤返回 `-0.02`，正确 finish 又返回 `1 - 0.02 * (steps - 1)`。一条 lookup 后正确 finish 的两步轨迹，奖励为 `[-0.02, 0.98]`，累计为 `0.96`，同一步成本被扣了两次。

GRPO 不累计 `env.step()` 的 reward，而是重写 `correctness - 0.02 * (steps - 1)`，因此忽略环境中的非法调用格式惩罚与超步硬罚。解析失败在 `llm_agent.py` 和 GRPO 中被转换成空 finish，也没有独立保留格式错误事件；GRPO 将工具错误观察写成 `result: null`，丢失了可用于修复的错误信息。

本轮为保持已有实验协议可追踪，没有擅改 reward 公式。正式训练前须统一一个轨迹回报定义，以手工轨迹测试正确、错误、非法参数、重复调用、预算耗尽和有效修复。训练器应消费环境统一提供的奖励/事件，避免各自复制公式。

### 4. 动作长度与当前协议不匹配

保存的 SFT 轨迹最多 4 个 assistant 动作，最长单动作 JSON 为 **9,701 字符**。动作中直接复制集合，`count(items)` 和 `intersect(sets)` 会把上一轮查询结果重新生成一遍。当前 SFT `MAX_LEN=2048`、GRPO/评测每步 `max_new_tokens=160`，尚未测量完整的实际 tokenizer 长度、截断比例及 finish 保留率；不能假定当前长度限制足够。

应优先接入类型化结果句柄和变量引用，例如 `find(...) -> $s1`、`count(items="$s1")`、`finish(answer="$n1")`。工具侧保留完整集合，模型观察可返回规模、摘要和句柄，避免复制实体列表。扁平与类型化对照必须使用同一知识视图、可表达能力及输出规则，区分动作表示效果与纯上下文节省效果。

## 数据与评测尚不能支持的论断

- 当前切分依据 anchor 分桶。比较题只按第一个实体分桶，多跳中间实体、另一比较实体和集合成员可能跨 split 出现，因此不是严格实体隔离。严格划分及相关统计由工作区数据审计另行记录。
- 当前多约束题只保留非空且至少 2 个成员的交集；count/enumerate 只保留 3–30 个成员；两跳只保留单一中间实体。这解释了 oracle 满分为何没有发现空集合错误，也说明缺少零结果、大集合与分支路径测试。
- 4,277 条 SFT 保存的动作数量为：lookup 3,892、find 1,732、count 472、intersect 394、finish 4,277；没有 union/difference。现有数据可用于基础协议学习，不能直接证明未见算子组合、长程规划和错误恢复。
- `comparison` 当前仅对 `same` 布尔值计分，不检查两边证据；set 题返回 F1，评测器却统一显示为 `acc`。正式结果须同时记录各题型 EM/F1、布尔准确率及证据/程序有效性，避免把平均混合分数称为精确准确率。
- 对图谱未出现的关系生成 False 属于闭世界假设。在事实图谱可能缺失时，现实世界“不存在”和知识库“未记录”不能混同；题目应明确“依据当前图谱”，或设计未知/不可回答标签。
- 直接 finish 正确答案无需执行证据也能满分。需区分最终答案正确性与有效工具执行，使用无工具、空答、多数类和记忆基线诊断捷径；奖励不能鼓励为了得分而无意义调用工具。
- KG 金标与工具共享过滤规则只说明内部一致性，不能证明雷达事实本身正确。应固定图谱版本、人工抽查来源与题目可回答性，再研究策略学习。

## 最小训练门槛

1. **协议冻结：** 统一旧类型化执行器与 v3 工具视图，定义输入输出类型、变量引用、错误类别、预算和结束条件；扩充零结果、重复操作、类型错误和变量依赖边界测试。
2. **数据冻结：** 固定图谱哈希、过滤规则和题目生成版本；建立 IID、严格实体隔离、程序组合隔离、错误恢复四种独立测试；补足 union/difference、分支路径和至少 5 步的真实依赖任务。
3. **SFT 正确性：** 修复模板拼接，验证 token/label 对齐，报告截断率和各题型长度；小批次过拟合与完整工具 rollout 均成功后再扩大训练。
4. **RL 正确性：** 统一回报，核对参考模型，验证正确轨迹优于错误轨迹、奖励不可刷分、梯度有限且更新方向正确；先单卡最小实验，再采用受验证的分布式路径。
5. **研究门槛：** 先做相同条件下的扁平 SFT 与类型化 SFT，并评估 base、固定规划和无工具基线；确定复杂组合仍有提升空间后，再加入 RL 与过程反馈消融。若任务短且 SFT 已饱和，应增加有意义的组合/恢复任务，不以调奖励制造增益。

**当前成熟度：** 工具执行和基础数据为可复用原型；类型化统一协议、严格泛化数据和正式 SFT/RL 训练为待实施内容。研究价值必须由公平对照和独立泛化结果建立，不能由 oracle 满分代替。
