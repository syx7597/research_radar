> 归档说明（2026-10-03）：以下保留2026-09-26制定的实验方案，包括当时的状态描述。它约束当前公开方法子实验，不再定义整篇论文的唯一贡献。论文整体范围以[论文主线与框架](THESIS_ROUTE_REVIEW.md)为准，运行进度见[README](../README.md)与[执行计划](ROADMAP.md)。本次调整论文定位，不修改已冻结的数据、预算、对照或评分协议。

更新：2026-09-26。依据用户最新要求，以六个月内完成毕业论文为目标，允许复用已有方法及与文献技术路线重合。本文件替代此前“继续审查单字段负例假设H”的任务优先级；旧结论和负结果保留于Git历史及各实验报告。本轮完成文献、代码和方案审查，**未开始新训练**。

## 1. 决策与贡献定位

建议题目：**面向雷达知识问答的小模型工具调用与执行反馈学习方法研究**。

固定主线：有来源的雷达知识资源构建 → 小模型逐步调用查询工具 → 执行器完成检索与计算 → 返回答案和证据。方法训练与主要验证放在公开KQA Pro，雷达小数据承担领域适配和应用评价。

主框架采用已有的SFT冷启动及终局奖励GRPO。唯一重点改进为：**把执行过程中出现的错误及经核验的恢复过程构造成训练轨迹，比较其与只学习成功轨迹的策略差异**。暂称“执行反馈恢复训练”，不是另造一种RL优化器。模型固定为Qwen2.5-3B-Instruct，采用LoRA；不从头预训练，不同时搜索多个模型系列。

本项目需要完成的是有明确问题、方法适配、可信对照和领域应用的研究闭环，不把“必须区别于所有顶会论文”当作启动条件。恢复训练、工具Agent、SFT和GRPO均有既有研究基础，不能声称首次提出。任务中的具体轨迹构造、受控实验和雷达知识表达可以构成毕业论文的增量贡献，实际效果由实验决定。

已失败的小试是字段重排、局部修复及字段合法性约束，不能外推为小模型Agent或RL不可行。约束小试80.4%对80.2%且实现明显更慢，故停止该模块；完整Agent训练从未得到有效验证。原型代码存在问题意味着需要规范适配，不意味着研究思想已被否定。

## 2. 文献依据与边界

| 主要依据 | 可以借鉴的部分 | 本项目的边界 |
|---|---|---|
| [KQA Pro及官方基线](https://github.com/shijx12/KQAPro_Baselines) | 公开问题、答案、KoPL程序及确定性执行环境 | 可把训练程序转为动作与真实观察轨迹；这是本项目的适配方案，数据集本身不是现成Agent训练集 |
| [KBQA-R1](https://arxiv.org/html/2512.10999v1)及[代码](https://github.com/sunxin000/KBQA-R1) | KBQA中的SFT→GRPO、动作—执行—观察循环 | 原实验8B、8×A100-80GB及Freebase；不能把其成绩当作3B在KQA上的保证。只借模块，启动脚本不能原样执行 |
| [ToolRL](https://arxiv.org/html/2504.13958v1)及[代码](https://github.com/qiancheng0/ToolRL) | 包含1.5B/3B工具学习实验，小模型训练有依据 | 其训练把多轮拆为单步，并非本项目的真实KG多轮执行 |
| [Search-R1](https://arxiv.org/html/2503.09516v5)及[代码](https://github.com/PeterGriffinJin/Search-R1) | 3B多轮检索RL、真实环境观察与训练mask | 文本检索问答不能直接证明KGQA收益；借训练接口，不另建文本检索研究方向 |
| [KnowCoder-A1 §5.4.3](https://arxiv.org/html/2510.25101v1) | 成功/恢复轨迹及终局监督；相关消融有反面证据 | 其特定实验中，中间错误和超时惩罚降低了效果。不能外推所有过程奖励无效，但不支持未经验证地堆惩罚项 |

这些工作支持技术可实现性，不保证拟议恢复训练一定涨分。选择理由是训练数据和执行监督可获得、公开评价已有基础、方法改动集中、失败时仍能在同一框架内收尾，而不是预判某个奖励公式一定有效。

## 3. 系统流程

```text
公开阶段：KQA Pro训练问题 + 训练程序
                  ↓ 真实执行，构造训练轨迹
        3B模型SFT → 相同终局奖励GRPO
                  ↓
问题 → 模型生成一步工具调用 → 工具执行 → 返回观察 → 模型决定下一步
                                       ↖ 重复，直到完成或达到预算
                  ↓
             执行结果作为最终答案

雷达阶段：原始资料 → 核验事实、单位、条件、来源 → 知识库 + 证据文本
                                               ↓
                        同类Agent接口与中文适配 → 答案 + 条件 + 来源
```

例如：定位实体 → 查询属性/关联 → 按两个条件筛选 → 求交集 → 计数/比较 → 返回证据。模型学习下一步调用什么、使用哪个已有结果、何时结束；数据库负责集合和数值运算。

工具侧保存完整中间结果，模型引用`h0/h1`等句柄，只接收类型、规模和有限样例。句柄保留实体与事实的配对，避免丢失限定条件。这解决旧轨迹反复复制大集合的问题，属于共用基础设施，普通Agent与改进Agent均享有，不把它混入恢复训练的独立收益。

只有本步真实执行后才生成下一步，才称多轮工具Agent。一次性生成整棵计划树的旧planner保留为参考，不能改名冒充已实现的多轮模型。检索发现字段/关系的接口对所有Agent一致，不能给改进组额外金标候选。

## 4. 唯一方法改动：执行反馈恢复训练

**问题假设：** 成功轨迹SFT主要学习理想路径；自由交互时，错误调用或偏离路径后的状态未必在训练中出现。训练模型如何从这些状态继续完成查询，可能比增加同等量的干净轨迹更有用。

研究对象包含工具参数、关系方向、结果引用和动作顺序，不局限于某个字段名。观察不能识别所有合法但语义错误的查询；问题条件及历史状态同样必要。

1. 执行训练题的金标程序，取得可重放的成功轨迹；中间观察由真实执行器生成。
2. 用同一个初始SFT模型收集训练题的真实错误。优先采用具有共同成功前缀、可定位偏离步骤的案例；有限一步扰动仅作补充，分开标记来源与覆盖率。
3. 从可用历史句柄构造恢复后缀，重新执行验证依赖、关键条件及答案。不能仅因与金标程序不同就判错，也不能仅因最终答案相同就认定语义恢复成功。
4. 保留错误动作与真实观察作为上下文，**错误动作和工具观察不计SFT监督损失，只监督正确的恢复动作**。混入正常成功轨迹、合法空集、正确的0/否及不需要恢复的步骤，避免训练成机械重试器。
5. 推理时没有“正确句柄”标记、金标后缀或隐藏回退。模型自行选择所有历史句柄。工具结果来自当前知识库，训练答案和程序只用于离线构造及训练评分。

恢复/普通监督token配额初设1:1，在看比较结果前写入协议；不对比例做网格搜索。若真实可恢复错误不足以达到配额，记录覆盖不足，不用大量人工注错伪装自然分布。

随后两组接入**完全相同的GRPO阶段**：终局执行答案经官方比较函数判定，正确1、错误/未完成0；固定总调用与生成预算。第一版不加字段合法性、空结果或逐步成本奖励，不训练额外奖励模型。成本作为评估指标和硬预算控制。

实际训练的是小模型的工具决策能力；主改动在轨迹与训练状态构造，不是修改网络结构，也不是仅调整temperature、beam或学习率。

## 5. 数据与对照

继续用KQA Pro作主公开任务，不同时引入Freebase和第二套复杂基准。先沿用已有5,000个训练问题和500个已见开发问题；按历史ID清单排除所有训练、开发、校准及诊断用途后，从官方训练范围一次冻结约2,000个项目留出问题。问题/完整程序重复组整体隔离；这不等于严格组合泛化划分。

新训练前落盘留出ID、哈希和使用记录，去重影响规模时记录实际题数。它是项目留出集，不是官方隐藏测试；无法证明基础模型预训练未见这些公开题目。官方11,797题validation已有历史使用，可作全量公开参考，不能再称独立测试。

调参只看开发集；冻结最终方法后运行留出评估，不按结果重选集合。若扩大训练量，所有对照使用相同训练问题，且不改报告集。

| 编号 | 同一3B基座的方法 | 比较目的 |
|---|---|---|
| P | 一次性KoPL程序SFT + 执行 | 多轮Agent相对简单强方案是否值得额外成本 |
| A | 普通成功轨迹Agent SFT，含等量追加干净训练 | 共用工具、句柄与观察的基本能力 |
| B | A + 终局奖励GRPO | 普通RL相对普通SFT的增量 |
| C | 恢复轨迹Agent SFT | 无RL时核心改动是否有效，比较C与A |
| D | C + 与B相同的GRPO | RL后核心增量是否保留，比较D与B |

共享初始SFT权重后，分支做等监督token预算的追加干净训练和恢复训练。A/C使用同一批独立问题；B/D固定RL问题、采样与更新预算。额外输入token和实际GPU时间另记，不能把等监督token写成绝对等算力。

所有Agent采用同一知识、工具、可见候选、最大步骤与生成预算。P不天然等于Agent计算量，应同时报告准确率和实际成本。旧140M BART是历史参照，3B超过它不能归因为本方法；不同训练量的文献分数不直接排名。

主要指标是自然完整问题的答案准确率；同时报告纠正/改错、无效调用、平均/尾部工具次数、输入/生成token及耗时。多跳、集合、比较、限定条件等分组在训练前确定。人工注错恢复率仅作诊断，不能替代自由交互评测。

增加同预算反馈屏蔽诊断，区别利用反馈和机械重试；仅屏蔽错误诊断，不删除句柄/输出类型等必要接口。对关键有效配置做两个训练种子及逐题差异区间，不用几十个案例的涨分证明总体效果。

## 6. 雷达领域与论文贡献

**知识资源：** 事实保存主体、属性、原值、规范单位、区间、适用条件、来源片段及unknown/conflict状态。优先处理已有主体/系统混淆、日期事件混淆、单位错误和未公开参数；不依据常识补造缺失条件。这是可追溯知识表达和数据资源贡献。

**方法：** 在公开任务中验证执行反馈恢复训练。即使与已有论文有重合，也明确采用了什么、为任务改了什么、是否有可归因增量，不声称发明Agent或GRPO。

**应用：** 同一工具框架补中文、领域实体/字段映射及数值区间、单位和显式条件计算。单位转换本身不是新算法。未公开参数返回未知；条件不一致的参数不直接比较；局部资料计数明确知识库覆盖范围。

先核验20–30个型号，独立编写并复核100–150题。核验知识可生成少量适配训练题，但训练和评价按来源/型号家族隔离；旧5,401道自动问答不能冒充独立评价。

比较同来源文本RAG、同模型一次性计划及选定Agent；在核验知识库测问答，在抽取知识库测端到端，区分知识和模型错误。雷达结果不替代公开方法证据，不另起图像理解、抽取RL或通用网页Agent路线。

## 7. 固定投入与停止规则

**首轮三周、累计最多72 GPU小时，是投入上限，不是耗时预测或自动预约。** 按实际占用卡数累计；先测单卡显存和吞吐，空闲多卡用于冻结的对照/种子。旧脚本不能直接多进程复制训练。增加投入前须提交实际吞吐、剩余任务及成本依据，不能后台无上限续跑。

- 第1周：冻结协议，接入逐步环境，检查状态隔离、真实反馈、动作loss mask、评分与函数/分支覆盖。不重新分析官方val找新靶点。
- 第2周：初始SFT及A/C两组比较。达到投入上限或两周仍无法获得稳定SFT时，停止扩展RL，先把同一框架收敛到可靠版本。
- 第3周：基础闭环稳定后进行B/D的有界RL比较，同时完成P强对照。五组是一个2×2方法对照加简单基线，不是五条研究路线。

开发标准预先固定：候选相对匹配对照自然问题准确率至少+2个百分点，或准确率下降不超过1个百分点且平均推理总token至少减少20%，才值得正式扩展。阈值是项目决策标准，不是显著性保证。两种目标事先同时登记，均报告准确率、token、延迟，不能事后换指标；还须与P及全部强对照比较，若P质量和成本均占优，不主张Agent有性能优势。

首轮后最多一轮有明确故障或机制依据的修改，不循环扫参数。恢复训练无收益，不写成已成立创新；RL无益，保留更好的SFT版本。最迟第2个月末确定模型，不再更换公开任务、模型家族或奖励体系追分。论文以实际成立的方法适配、知识资源和应用评价组织，明确未成立的假设。

题目不绑定奖励公式，整体对象和领域应用固定；根据证据在同一框架内选择版本，不将每次小试变成一次新开题。
