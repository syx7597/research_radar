# 执行计划：先公开基准，后雷达迁移

更新：2026-09-26。配套[研究方向](RESEARCH_DIRECTION.md)与[文献核验](research/PUBLIC_BENCHMARK_REVIEW.md)。上一版RL中心计划保留于[历史文档](archive/ROADMAP_before_public_first.md)。
以下是整体计划。用户已提供四卡4090，首轮最小验证按[实验协议](../experiments/condition_consistency/MINIMAL_PROTOCOL.md)执行；时间按数据和计算资源就绪后的工作周估计，截止日期尚未确认。毕业论文以可复现的小幅改进及适用边界为目标，不以顶会水平或SOTA为验收条件。

## 0. 最新进展与下一轮顺序

首轮P0/P1及轻量P2已完成，见[实测报告](MINIMAL_VALIDATION.md)。固定500题上：BART top1 73.0%，执行筛选80.0%，条件定向线性排序79.0%，oracle82.4%。尚未实施完整神经评分器、正式报告集或雷达迁移。

1. 保留80.0%执行基线和原500题开发结果，审计12个可挽回案例、定向排序新增10个错误及无正确候选问题；[首批错误审计](research/MINIMAL_ERROR_AUDIT.md)已完成。
2. 只选择一个有数据依据的小切口：有明确条件证据时保守替换；或处理schema/数值日期参数映射与局部修复。不得因为预设题目而继续叠加排序器。
3. 下一方案的参数由排序训练集内部确定，从其余train冻结新的留出集验证；保持同候选/查询预算，完整保留失败记录。
4. 达到可信的公开增益后再进入P3/P4和雷达迁移。当前不启动RL，不以79.0%高于弱排序对照为由跳过80.0%基线。

以下为整体阶段规范，P0/P1已有交付不需重做。

## 1. 第一目标：两至三周判断是否值得做条件一致性

| 阶段 | 工作 | 交付与验收 | 不通过时 |
|---|---|---|---|
| P0，第1周前半 | 获取并核验KQA Pro train；接官方KoPL；冻结数据/执行器版本 | 哈希、划分、官方算子覆盖表；金标程序回放及失败原因；train/开发/报告集无重复泄漏 | 修环境，不训练；不把旧扁平三元组适配当官方语义 |
| P1，第1周后半 | 复现一个程序生成基线；在train独立留出500–1,000题生成固定K候选 | top1、oracle@K、可执行率、原始候选和费用；分层审计真实错误 | 若错误主要是实体链接/候选缺失，优先解决这些基础问题 |
| P2，第2周 | 同一评分器只比较负例来源 | 自然失败、随机合法变异、条件定向变异；等样本/等预算 | 定向方法不优于自然难负例则不扩大、不改名宣称新方法 |
| P3，第3周 | 固定方案后跑完整公开报告集；三个评分器种子 | 官方答案指标、配对CI、qualifier子类、净纠正/改错率、成本 | 只有合成扰动集提升则保留为诊断结果，不作为主方法完成 |
| P4，第4–5周 | 成立后补最重要消融及第二生成器/Overnight适配 | 不依赖单模型或同模板，检查作用域输入与负例选择各自贡献 | 收窄结论；不把不支持任务静默删除 |
| P5，第6周起 | 方法冻结后整理雷达核验小库与盲测 | 20–30型号、约100–150题、原文证据、范围/单位/条件保留 | 没有来源条件的题标不可答，不能用LLM编补 |
| P6，后续 | 写作和接入原系统 | 公开方法结果、域内适配结果和数据质量分别陈述 | 删除未成立的贡献，保留负结果和适用边界 |

不先扩图谱、不先写新的大框架、不先启动当前`train_grpo.py`。首轮项目目标是检验一个小机制，而非完成整套Agent训练平台。

## 2. P0：公开评测协议

- 已取得固定revision镜像train，原官方云盘失效与镜像来源限制见[数据记录](../experiments/condition_consistency/DATA.md)。后续沿用固定哈希，不静默换版。
- 从train划分生成器训练、排序器训练和开发数据，公布seed与问题/程序哈希。等价改写、相同语义家族尽量归为同组。
- 原始官方val的11,797题作为冻结公开报告集，所有方法完整评测；不利用其中金标构造负例或挑超参。已被旧项目使用这一事实保留披露。
- 官方test隐藏标签；能提交才追加，否则明确报告validation。不得把自建组合切分称官方test。
- 原有`datasets/kqa_pro_adapter.py`会扁平化属性且不完整保留qualifier，不用于这次官方执行基线。使用官方KoPL实现，验证数值、日期、属性和限定的输入/输出语义。
- 官方gold程序执行失败要查明数据版本、依赖与返回值规范；完整报告原始分母、支持比例及异常，不能为了满分随意删题。
- 将模型输出解析为白名单KoPL函数/参数并由执行器调用，不直接执行生成的Python。评测金标仅供离线评测器使用；候选评分器只能读取问题、候选和实际执行观察。

## 3. P1：决定具体机制的诊断

先用较轻程序模型或1.5B/3B级模型复现SFT/约束生成；是否使用LoRA根据资源选择。模型、tokenizer、数据预算、实体链接策略和最大长度固定。
强BART/候选表达式方法作为参考，不能只用旧Top-K或弱提示模型。若采用1,000/5,000训练样本的低资源设置，所有对照使用同一子集，同时报告充分监督参照，不宣称通用SOTA。

在公开train的开发留出部分测：

1. top1答案正确率及K=4/8的候选oracle正确率。oracle使用金标仅做离线诊断，不是可部署方法。
2. 语法/类型错误、实体链接错误、属性关系错误、比较方向、漏条件、qualifier作用域错误、工具环境错误。
3. 尽可能分层标注至少200条错误；若可观察错误不足200条则报告实际数量，不用人为变异凑真实错误。
4. 正确候选是否被模型排在后面、目标条件错误是否有真实样本支撑、执行信息是否足以解释。

建议事先固定投入门槛：可重排的目标错误至少约50例，且候选oracle比top1有约3–5个百分点空间；这些是项目决策建议，不是学术通用标准或预期结果。
不足时停止reranker路线。若正确候选缺失，研究候选生成/grounding；若目标错误极少，不能仅因与雷达叙事匹配就坚持它。

## 4. P2：第一版训练与负例质量

只固定生成器并训练评分器，不同时加入RL、自由重规划、文本补全和自建雷达数据。
评分器读取问题、候选计划与真实执行得到的事实作用域信息；不额外调用大模型生成一份不可核验的“约束清单”作为真值。

训练组用同一结构、正例、更新步数和负例数量：

- 模型自然失败程序；
- 随机但合法的程序变异；
- 定向限定条件变异（只改变绑定对象/限定字段/比较方向等一个语义因素）；
- 定向变异移除作用域输入，用于消融。

变异不得跨入开发/报告集。先保留执行合法且答案改变的高置信负例，匹配程序长度、函数数、结果类型和空/非空比例。
不要以“有空结果”判断错误；合法空结果可保留，需与其他组平衡。对答案相同的程序暂不标负。
尽可能用经过验证的等价变换作正例；加入未见编辑类型或组合的辅助诊断，防止评分器只识别变异痕迹。
保留每条变异的来源qid、修改位置、原因、执行结果和筛选状态，人工抽查至少50条，发现伪负例就修生成规则。

同训练集和预算下对照PO-KGQA/通用难负例思想时，明确哪些是作者代码复现、哪些是同环境改编；不要把自写弱版本标成作者原结果。

## 5. P3/P4：成立标准

- 完整原始公开报告集按官方答案评分；同一候选集合上做配对比较，固定随机种子。测试候选不能含人为注入的gold程序。
- 报告各训练种子及配对bootstrap区间；观察新增正确数、原正确改错数、条件子类和成本。复杂程序的表面精确匹配只作辅助，不替代答案正确性。
- 预先限定主要比较：定向反例组对自然难负例组，而不仅对原始top1。增益需在至少三个种子方向稳定，配对区间支持正向变化；必要时按语义家族聚类重采样。
- 全体指标若无增益，只能讨论预定义条件子类的改进，并报告整体非劣/退化，不能临时挑显著类别。
- 报告K候选生成本身的成本；与所有组同K比较，不能把多采样收益算作机制收益。
- 有正向结果后再测试第二生成器或Overnight相应任务；不强制第一阶段同时复刻GrailQA/Freebase。

停止规则：最多两轮事先限定的开发调参，若定向反例不优于一般难负例，则认为本机制尚无证据，保留负结果并重新按错误分析选方向。不要继续扩大模型来掩盖对照失败。
如果重排有效但成本太高，可研究把选择能力蒸馏回生成器；只有此后存在明确需要时，才考虑偏好优化或RL。

## 6. P5：雷达只承担迁移与应用验证

方法先在公开集冻结，雷达schema映射与少量开发样例属于域适配，不能伪称完全零样本。
现有16,609属性中未结构化保存条件，且数值区间可能被折成端点，不能直接自动造答案。先建立独立人工核验子库。

- 保留原文数值/区间、单位、型号/版本及有来源的条件，不补造工况。
- 用手册原文独立提问和标注，不让系统自己的程序输出充当正确答案。
- 开发与盲测按型号家族/文档分隔；尽可能安排另一人复核，记录标注者与分歧。单人评测明确限制。
- 包含证据不足和不可比较情况；小库计数的范围是小库，不是现实全部雷达。
- 分别测“人工核验图上的查询能力”和“原始抽取图上的整体效果”，所有基线使用相同图版本。
- 限定条件正确率和错误案例支撑应用意义；主方法是否有效依靠公开实验，不依靠这100多题高分。
