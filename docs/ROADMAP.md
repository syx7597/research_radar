## 2. 当前结果如何使用

完整official val：v2 local比beam4提高1.4919个百分点，95%问题级配对区间为[1.2715, 1.7123]；比同样保护的global仅高0.1441个百分点，区间为[0.0000, 0.2882]；比beam8低0.0424个百分点，区间为[-0.4238, 0.3306]。不能宣称胜过beam8，也不能把未确认差异称为等效。方法价值暂聚焦在相对固定beam4基线较少误修改的同时获得净收益。

v1首次2,000题评估：beam4 first-valid为79.25%，global为79.70%，local为80.15%，beam8为80.70%。local纠正38题、改错20题，净增加18题；相对global的配对区间跨0，尚未证明局部约束的独立增量。不能只与73.60%的top1比较后宣布成功。

v2已受到上述2,000题事后错误启发，因此这批题从此是**已见诊断集**。任何v2旧集成绩均不能当作新的独立验证。完整official val仍是公开validation，旧项目曾使用它，继续披露这一历史，不称hidden test。当前仅一个生成器种子，问题级置信区间不能代替多次训练稳定性。

原pilot与本轮存在执行器一致性修正，历史dev的400/500与当前401/500不能直接横比并归因于算法。本轮只比较同一批候选、同一执行语义下的方法。v2保护发生在选择阶段，仍运行完整候选生成、执行和评分，尚未实测节省计算。

## 4. 若方法有依据，如何补正式实验

固定候选预算、字段编辑范围、保护规则、校准网格和评测口径后再增加生成器种子。每个种子使用相同5000条训练数据和训练预算，阈值仍仅由原calibration按同一规则选择；不能按validation为不同种子手动挑参数，也不能将旧线性排序器的三个种子当成生成器复现。

独立语义抽查应覆盖纠正、改错及答案不变的修改，检查题意、实体路径、限定符、单位和来源。答案相同不保证查询语义相同，程序不同也不一定错误。优先安排第二人复核；做不到时明确标注单人/AI审查限制，不伪称独立人工评审。抽查用于解释可靠性，不再反向修改当前冻结算法。

报告所有种子、净纠正、误修改与成本，不只挑最佳种子。BF16、批次形状及环境可带来微小数值差异；并行分片的总墙钟时间与单方法独立延迟分开。毕业论文允许小幅改进，但需要在合适对照和清楚限制下成立，不以文献SOTA为目标。

## 5. 雷达迁移的具体范围

公开方法范围确定后，先人工核验20–30个雷达型号。保留原文证据、单位、数值范围、型号/版本和来源中明确给出的工作条件；缺失条件留空，不根据常识补造。知识标准化和单位转换是领域适配工作，需单独验证。

从原文独立设计约100–150题，按来源或型号家族划分开发与盲测，并记录标注依据。原自生成QA只用于开发调试，不能作为独立金标。分别测试人工核验图上的查询效果和原始抽取图上的端到端效果，避免将图谱错误混算为修复算法失败或提升。

当前公开实验是英文问题到KoPL，不能直接假定BART会处理中文雷达问题。需要先建立并固定“中文问题→结构化查询”的适配接口，在小型开发集验证字段映射、关系、单位与型号信息，再接入相同的有界修复机制。中文解析器和领域schema的变化单独报告，不把额外模型能力全部归因于修复。

接入现有图谱、检索与界面，展示原查询、修复位置、答案和证据来源。系统服务于论文验证与答辩演示，优先保证可追溯和可复现，不新增无关大模块。

## 6. 论文组织与贡献边界

论文按“研究问题与相关工作 → 数据和基线诊断 → 有界查询修复 → 公开实验与可靠性分析 → 雷达适配和系统 → 局限”组织。方法贡献必须由最终对照决定；数据整理、执行器一致性与系统实现按实际工程价值陈述，不能包装为算法突破。

已有图谱构建、检索和展示用于领域应用基础；旧Agent/RL尝试作为历史路径保留，不作为已验证的新主线。历史88.6%、工具oracle、首轮排序和当前查询修复成绩分别解释。

最近一步是**冻结保守修复的稳定性验证协议，补两个生成器种子与独立语义核验**。完整公开评估已经结束；不再围绕本轮val调参，也不把局部约束写成已被证实的创新点。
