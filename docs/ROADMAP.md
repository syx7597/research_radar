# 六个月执行计划

更新：2026-10-03。当前唯一主路线见[论文路线与方法方案](THESIS_ROUTE_REVIEW.md)：公开KQA Pro上的3B工具Agent，SFT→终局奖励GRPO，唯一增量为执行反馈恢复轨迹训练；随后迁移到可追溯的雷达知识问答。

第一阶段已完成：两组正式SFT、500题开发评测、5,000题训练轨迹收集和418组恢复对构造，累计约6.03 GPU小时。初始Agent 75.6%，同3B程序基线75.2%；纠正42、改错40，差异95%区间[-3.2, 3.8]个百分点，Agent成本更高，尚无可靠优势。这不等于恢复训练已被验证，因为A/C增量对照尚未完成。见[逐题配对统计](../results/agent_feedback/initial_vs_program_dev.json)。

当前已在GPU 0/1启动A/C对照：共享初始adapter，每组一轮、5,772条记录、788,534个监督token，严格匹配题目、顺序与复用次数；418道配对题各重复7–8次，覆盖局限如实记录。执行种子复核及预算检查已通过，正在并行训练普通续训A与恢复续训C，完成后自动评测相同500题开发集，比较C/A及C/程序强基线。见[恢复样本统计](../results/agent_feedback/recovery_pairs.json)、[语料清单](../results/agent_feedback/continuation_data.json)与[预算审计](../results/agent_feedback/continuation_token_audit.json)。留出集不参与调参。

四GPU经授权重启后恢复，所有训练由syx执行。原生GRPO一步运行短测已通过，但该短测奖励和梯度均为零；正式RL前须检查完整SFT分支的学习信号，后续命令携带[私有头文件CPATH](../results/agent_feedback/python_headers.json)。完整正负运行记录和预算均保留；[训练快照](../results/agent_feedback/running_snapshot.json)仅代表其标注时间。

## 已结束的实验

原BART训练、排序、字段修复、完整官方validation及字段约束小试均已保存。约束对照80.4%对80.2%未显示可靠收益，本次实现明显更慢，停止开发。不再把核查12个字段差异或旧负例假设H作为主线前置条件。

已有知识图谱、检索系统、类型化执行代码和12条带来源的待审雷达事实可复用。原SFT/RL原型有实现问题，不能直接多卡启动。

## 近期三周：一个有上限的验证包

上限为三周、累计72 GPU小时，不是耗时预测或自动预约。训练前冻结ID、采样和评价协议。先测单卡吞吐，空闲多卡用于固定对照/种子。以技术检查通过作为开训依据，不增加“必须全领域原创”的门槛。

| 时间 | 工作 | 交付 |
|---|---|---|
| 第1周 | 固定5,000训练题、500已见开发题及约2,000项目留出题；接入逐步KoPL环境和成熟训练库 | 数据ID/哈希与用途、真实观察、状态隔离、正确mask、评分及成本记录 |
| 第2周 | 共享3B初始SFT，比较追加干净训练和恢复训练 | 同问题/监督token预算的A/C对照，准确率、纠正/改错和真实错误覆盖率 |
| 第3周 | 两分支接相同终局奖励GRPO；完成同3B一次性程序基线 | B/D比较、RL增量、强基线与实际成本；全部正负结果 |

主比较为恢复SFT对普通SFT，以及恢复SFT+RL对普通SFT+RL。同3B一次性程序生成是必要强基线，旧140M BART仅作历史参照。人工注错恢复率不是主要成绩。

开发标准：匹配对照准确率至少+2个百分点，或下降不超过1个百分点且推理总token减少至少20%；这是项目阈值，不是显著性保证。正式评价补种子、差异区间及强对照。若一次性程序方案质量和成本均更好，如实报告Agent无性能优势。

随后只允许一轮有证据的针对性修改，第2个月末冻结方法。RL无益保留SFT，恢复训练无益不宣称其成立；论文主对象与领域应用不变，不继续换奖励和任务追正结果。

## 六个月里程碑

| 时间 | 重点与交付 |
|---|---|
| 第1个月 | 协议、环境、有界验证；开始相关工作与任务定义写作 |
| 第2个月 | 最多一轮修改，冻结方法；并行雷达核验，完成方法章节 |
| 第3个月 | 两种子、必要消融、固定留出与公开val参考，公开方法完整结果 |
| 第4个月 | 独立雷达QA、中文适配、同资料对照，目标20–30型号/100–150题 |
| 第5个月 | 端到端归因、系统展示与完整初稿 |
| 第6个月 | 修订、复现与答辩，不再开启新算法方向 |

雷达评价顺序：原文 → 人工核验事实 → 独立问题与证据 → 核验图上的问答 → 抽取图上的端到端。公开方法与领域应用证据分开，自动生成题不作独立人工评价。
