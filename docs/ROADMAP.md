## 六个月里程碑

| 时间 | 重点 | 完成标准 |
|---|---|---|
| 第1个月 | 明确问题、方法机制、知识质量与评测协议 | 一项可解释、可证伪的机制；同时开始论文问题与数据章节 |
| 第2个月 | 雷达核验子集、独立QA规范和公开强基线；满足门槛后做一次最小试验 | 数据来源可靠、训练和评价隔离，控制额外数据/训练/候选预算 |
| 第3个月 | 有限方法开发及关键消融，持续写作 | 方法只在合理对照下有增量才保留；开发最多两轮，不连续堆模块 |
| 第4个月 | 冻结方法，正式公开对照、多种子和中文雷达适配 | 分开证明公开方法与领域应用，披露已访问数据历史 |
| 第5个月 | 雷达端到端评估、系统与完整初稿 | 区分知识、抽取、解析、执行误差；证据与文稿一致 |
| 第6个月 | 修订、必要复核、复现与答辩 | 不再开始新算法方向，保留写作和失败缓冲 |

如果第3个月仍没有方法证据，应及时调整贡献定位并与导师核对要求；不能以工程量或自建测试集高分替代方法有效性。

## 验证顺序

公开方法验证与雷达资料核验并行。原始资料 → 人工核验事实 → 独立问答金标 → 干净知识图上的问答评测 → 原始抽取图上的端到端评测。公开方法采用相同知识、训练与推理条件的强对照，先冻结报告集，所有正负结果保留。

旧阶段计划与研究调整保存在Git历史；历史结果见[首轮排序](MINIMAL_VALIDATION.md)、[修复验证](QUERY_REPAIR_VALIDATION.md)和[后验对照](research/NEXT_EXPERIMENT_DECISION.md)。
