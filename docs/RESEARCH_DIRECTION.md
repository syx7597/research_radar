# 研究方向：公开基准优先的条件一致性问答

更新：2026-09-26；替代[上一版以雷达数据和RL为中心的建议](archive/RESEARCH_DIRECTION_before_public_first.md)。以下保留候选方法的研究设计；最新决策以[首轮实测报告](MINIMAL_VALIDATION.md)为准。

**首轮已完成真实训练和开发集对照：执行筛选80.0%，条件规则77.6%，定向负例线性排序79.0%，oracle@4为82.4%。当前简单机制未超过有效基线，暂不扩大纯重排投入，先审计候选缺失与参数映射。** 完整神经事实作用域方法尚未实现，不能把这一小探针的结果外推到所有相关方法。

## 1. 判断与研究顺序

**原主线不能称为“确定可行”：系统能做出来，但方法新颖性、公开集增益和RL必要性均未被证明。**
根据用户要求，将主要证据来源改为公开基准：

> 公开KGQA基准复现 → 真实错误诊断 → 一项条件一致性改进 → 同条件公开评测 → 独立人工核验的雷达迁移。

自建图谱是应用环境和迁移对象，现有自动生成QA不再承担论文主要有效性证明。
其问题不只在体量：生成器、工具和金标同源、划分重叠、抽取噪声及版本漂移都降低独立性。单纯扩量不会解决这些问题。
公开数据也可能有生成偏差、标注噪声和预训练污染，不能将“公开”直接等同绝对可信；优势在于独立来源、标准协议和可比基线。

建议暂用工作题目：**面向复杂知识问答的条件一致性建模及其在雷达领域的应用**。
等小实验有证据后再确定最终题目；不提前绑定Agent、GRPO、置信度或模型大小。

## 2. 调研改变了哪些判断

详细来源与实现核验见[公开基准调研](research/PUBLIC_BENCHMARK_REVIEW.md)。

| 方向 | 现有证据 | 决策 |
|---|---|---|
| 类型化动作 + 执行反馈RL | [KBQA-R1](https://arxiv.org/abs/2512.10999)已有高度相近设计，官方训练配置与Freebase后端成本较高 | 不再作为默认核心；RL降为后续选项 |
| 约束生成 + 执行纠错 | [CodeAlignKGQA](https://aclanthology.org/2025.coling-main.267/)已在KQA Pro实现 | 作为强近邻，不能以同样组件直接主张创新 |
| 小模型 + 低资源偏好优化 | [PO-KGQA](https://aclanthology.org/2026.findings-acl.2083/)已有直接方法 | 必须比较负例来源，不能只把SFT换DPO就算改进 |
| 语义困难负例 + 重排 | [SemCL](https://aclanthology.org/2022.emnlp-main.269/)及[KBS 2023对比框架](https://www.sciencedirect.com/science/article/pii/S0950705123007463)已有先例 | 不宣称首次；候选差异只能落到具体事实条件的绑定监督 |
| 通用规则变异/局部反例 | [SNOWBALL](https://aclanthology.org/2021.findings-acl.388/)、[CAPER预印本](https://arxiv.org/abs/2606.03327)覆盖相关思想 | 最小编辑本身也不是新贡献 |
| 类型/候选表达式约束 | [Candidate Expressions](https://arxiv.org/abs/2410.00414)已给出较强KQA Pro结果 | 不能只比较弱prompt或旧Top-K基线 |

本次未找到可以保证“没人做过、一定有效”的空白。以下是成本较可控、能快速否证且自然关联雷达的**候选小改进**，仍须完整近邻方法比较和实测确认。

## 3. 推荐问题：可执行程序是否保留了问题条件

例：问题要求“某城市2010年的人口是否超过给定阈值”，程序却读取另一年份的人口；两者可能都能执行且输出布尔值。
类似错误包括：漏掉限定条件、比较方向错误、把年份/条件挂到错误属性、混淆两个比较对象。语法与类型检查只能排除一部分错误。

优先假设：**针对KG事实的限定条件作用域和绑定关系构造定向、合法的训练反例，能否在相同模型、数据量及推理预算下，比一般难负例更有效地识别问题—程序条件不一致？**

这里的“作用域”是条件限定哪一条属性或关系事实，例如年份限定人口记录，而不是城市的成立日期。
数值比较符错误是辅助覆盖，最值得寻找差异的是事实与qualifier的绑定；其是否足够常见尚未实测。

## 4. 第一版只做一个小机制

先固定一个已复现的程序生成器和官方执行器，生成固定K个候选；仅训练一个轻量候选评分器。
评分器输入为问题、候选程序及可由该候选执行获得的事实/限定信息。第一版不额外堆一个LLM规划器、自由修复循环和RL。

训练阶段：

1. 从公开训练集金标程序做一处受控语义改动：限定字段/绑定对象/比较符/条件遗漏。数值与属性类型保持合理，不把语法错误混成目标负例。
2. 通过官方执行器检查，起步只把“类型合法、可执行且答案确实不同”的变体作为可靠负例。额外记录空答案比例，并匹配各负例组的输出类型、长度与结果规模，避免学捷径。
3. 答案相同的变体既可能等价，也可能碰巧正确，不能仅因程序字符串不同标负；第一版排除，另做人工诊断。
4. 与等量模型自然失败样本、随机合法变异做比较。训练预算与评分器结构固定，差异主要来自条件定向监督。
5. 只有显式证明等价的规则变换才能用于等价正例；不能把同一KB上答案相同叫逻辑等价。

推理阶段只看问题、公开schema、相同实体候选和执行观察，不看金标程序、答案或数据集类别。
测试候选中不能补入金标；重排也不能凭空创造生成器未给出的正确答案。
KG条件作用域表示、定向反例与低资源效果是待测的具体增量；pairwise loss、reranker、执行器均不是新发明。

## 5. 公开数据的选择

| 数据 | 角色 | 理由与限制 |
|---|---|---|
| KQA Pro | 第一主基准 | 有关系、属性、qualifier、KoPL程序与答案；可直接定位条件错误。标准执行器已有数值/日期/计数能力 |
| Overnight | 第一候选补充基准 | 有跨领域语义解析和条件组合，Candidate Expressions同时支持；先查实际可测属性。不能声称它完整覆盖KG qualifier |
| GrailQA | 后续扩展 | 有组合/零样本划分，但Freebase环境和适配成本较高，test标签隐藏 |
| MetaQA | 可选路径对照 | 主要考察多跳，不足以单独验证限定条件和数值绑定 |
| TAT-QA / MultiHiertt | 另一选题的备选 | 与表格参数和数值证据有关，但会切换输入、推理形式与基线，第一阶段不同时开展 |

KQA Pro官方test金标不公开。优先从官方train划出独立开发部分，用完整官方val作为冻结公开报告集并明确写“validation”；如果能获得官方测试评测再追加。不能把自行划分或镜像标签叫官方test。
现有val曾在旧项目中使用，不能称从未接触；本轮只做任务结构统计，后续不再用它选择负例类别、超参或最优模型。
现已通过固定revision第三方镜像取得train，并冻结5,000/1,000/500题首轮划分；KB/val与原本地文件逐字节相同，未取得官方train压缩包作独立比较的限制已披露。见[数据来源与执行记录](../experiments/condition_consistency/DATA.md)。不能拿val训练。

本地val的11,797题中，2,806涉及qualifier相关函数，3,095涉及数值或比较，3,436涉及And/Or，1,318涉及Count；分组可重叠。
这是任务覆盖，不是模型错误数、提升上限或条件方案有效证据。函数集合、哈希和复核脚本见[统计清单](../artifacts/public_benchmark_profile.json)与[脚本](../scripts/profile_public_benchmark.py)。

## 6. 必须怎样比较才可信

第一阶段在同一生成器、相同K、相同实体链接/schema信息、相同训练问题上比较：

| 组 | 设置 | 验证什么 |
|---|---|---|
| B0 | 原生成概率取top1 | 原始水平 |
| B1 | 同K候选 + 标准执行合法性筛选 | 排除无效执行的既有收益 |
| B2 | 同评分器 + 模型自然失败难负例 | 常规候选学习能做到什么 |
| B3 | 同评分器 + 随机合法变异 | 一般数据增强收益 |
| Ours候选 | 同评分器 + 条件绑定定向反例 | 定向监督的增量 |
| 消融 | 移除事实作用域信息、或混匀负例类别 | 区分输入表示与反例选择的贡献 |

若只增加K就有提升，不能归功于评分器。所有训练组控制正负样本数、训练步数、金标信息和推理token；原子查询成本、候选数和延迟分别报告。
必须有较强受约束解析基线，BART/KoPL或小模型SFT按统一协议复现；论文中约93%的强监督结果只能作为其原设定参考，不能与少样本设定直接比数字。
PO-KGQA部分代码从gold程序提取实体/概念；因此固定已链接实体实验与端到端实体链接实验应分别报告，不能借金标信息降低难度而不披露。

主结果是完整原始公开报告集的官方答案指标与配对置信区间。预先定义的qualifier/比较子类、净纠正数、原正确改错率和人工条件错误率是解释性指标。
合成最小对照集只用于诊断；若只在自己造的扰动上赢，不称公开问答方法已提升。
至少三个评分器训练种子，另报告固定生成器与候选缓存的限制；有提升后再用第二生成器或补充公开集检查可迁移性。

## 7. 与雷达领域的关系

雷达应用关注的是“这个数值属于哪个型号/版本/工作模式，原文是标称值还是范围，比较是否使用相同条件”。
这些条件必须有来源，不能从模型常识补造。KQA Pro的qualifier提供通用实验对象，但并不能证明物理单位和工况适配自动成立。

本地实体表有16,609条属性，8,470条含数值和单位，未发现结构化condition/qualifier字段。
抽样核查发现原文区间`0.3–3.0 GHz`被存为`3.0 GHz`，另一条`300MHz～3GHz`被存为`0.3 GHz`。
这说明当前scalar字段不能直接作为范围问答金标；修复数据只算应用基础，不算公开集算法提升。

迁移阶段只整理20–30个型号的小型核验库，保留“主体—属性—值或区间—单位—来源条件—证据”。
从原手册独立编写约100–150个问题和答案，包含基础属性、条件比较、型号版本及证据不足；按来源/型号家族分开开发与盲测。
方法冻结后测试，由另一人独立复核一部分并记录分歧；若只有单人标注，明确限制，不能宣称独立双人金标。
分开报告人工核验库上的问答质量和原始抽取库上的整体表现，以区分抽取错误与查询错误。
不推断现实世界全部型号，不对无条件支持的数值强行比较，不把小案例集的高分称为通用能力。

## 8. 可行性与停止条件

| 判断 | 结论 |
|---|---|
| 是否能建立可靠的公开实验流程 | 可行，第一阶段工作量可控；需先取得train并接通官方语义 |
| 是否有可复用代码和数据 | 有，但需要版本固定与适配，不能把已有脚本都当作开箱可运行 |
| 这个具体小改进一定有效吗 | 首轮简单实现尚未超过80.0%执行基线；该基线距oracle仅2.4个百分点 |
| 是否已证明新颖性 | 没有，多个近邻重叠；KG限定作用域的具体设计仍待全面比较 |
| 是否需要先做RL | 不需要；当前首轮实验不依赖在线RL |
| 雷达小库能否支撑主要结论 | 不承担主要证明，只做独立应用验证 |

首轮发现候选不足与排序回退：执行筛选剩余100个错误中88个没有正确候选，当前条件重排不作为已成立主方法。按错误审计决定保守条件检查或参数/候选修复的小实验，参数在训练内部确定，再用新的训练留出集验证。
有稳定公共数据收益后，再投入完整评测与雷达迁移。原500题保留开发用途，不把新划留出集冒称官方test，不删除或覆盖本轮负结果。
