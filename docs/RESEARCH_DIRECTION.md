# 研究主线：局部约束查询修复与雷达知识应用

更新：2026-09-26。本轮明确下一阶段设计，没有新增模型实验。已测事实见[最小验证报告](MINIMAL_VALIDATION.md)，实施顺序见[计划](ROADMAP.md)。上一阶段重排假设及文献对照保留在[Git历史版本](https://github.com/syx7597/research_radar/blob/41e3096/docs/RESEARCH_DIRECTION.md)。

## 1. 论文定位

建议工作题目：**面向低资源复杂知识问答的局部约束查询修复及雷达知识应用**。
“低资源”指首轮只有5,000条公开监督问题，不暗示四卡GPU是低算力，也不声称比其他方法更省资源，相关比较需要实测。

核心问题：小模型生成的查询常接近正确，但字段与知识库不匹配。能否利用字段角色、局部事实上下文和参数约束，仅修改必要位置，同时减少把原本正确的答案改错？
论文工作量组织为：**一项小方法改进 + 可信公开对照 + 雷达领域适配系统**。不以SOTA或顶会级理论贡献为目标，也不将已有组件改名算创新。最终创新表述以实验和近邻比较成立为前提。

## 2. 为什么收敛到修复

首轮500题：BART首选73.0%，执行筛选80.0%，定向负例线性排序79.0%，候选上限82.4%。执行筛选剩余100个错误中88个没有正确候选，仅靠重排无法挽回。
固定前30个错题的AI审查中，大量问题涉及字段、关系方向和实体参数；不能将其全部归为限定条件错绑，也不能外推总体比例。详见[错误审计](research/MINIMAL_ERROR_AUDIT.md)。
因此保留现有生成器、官方执行器和公开数据流程，把下一轮预算用于有限的候选修复。首版只修一个字段参数，不承诺同时解决实体链接、路径重建、数值推理和所有条件问题。

## 3. 最小技术路线

问题 → 固定BART生成4个程序 → 官方执行和字段角色检查 → 可观察的异常定位 → 至多4个单字段修复候选 → 约束检查与保守接受 → 执行答案与证据。

### 3.1 触发与候选

1. 先计算现有执行筛选的输出，保留为回退结果。触发依据只能来自问题、知识库、程序和执行观察，不能看金标或离线错误分类。
2. 首版触发聚焦字段不在对应角色的合法schema中、参数类型不兼容，或可信执行前缀下的明确字段冲突。合法空答案、合法计数0本身不是失败证据。局部不存在某字段本身也不证明查询错误；局部候选约束仅用于已有独立异常证据的修复。前缀可信度仅依据推理时可见信号判定，并记录具体判据。
3. 字段按属性、关系、限定符等角色分别检索。基础对照在全局合法字段中做匹配；拟议方法进一步利用当前实体/事实的局部字段、值类型和限定符所属事实缩小候选范围。
4. 第一版只替换一个字段参数，至多4个候选、只运行一轮。不同时修改实体名、关系方向、函数序列或分支结构。若上游实体或程序结构已不可信、无法形成可靠局部上下文，则不执行本方法的局部修复；全局回退作为明确对照单独报告。

例如，程序把正式字段`discontinued date`写成`discontinue`，可以提出合法字段替换。另一类问题是把年份限定符挂到错误事实；若需要重写程序依赖，则不属于首版单字段修复范围。

### 3.2 条件保护与接受

- 保持未修改位置的实体、数字、日期、比较符、函数和依赖不变；限定符仍依附原事实槽位。检查替换字段与原值类型、上下文及有来源的条件是否兼容。
- “保护”只表示限制本次编辑范围，不保证原程序已正确，也不构成自然语言语义等价证明。不能为得到非空答案而删除条件。
- 候选选择结合固定生成器的程序概率、问题与字段匹配、角色/事实兼容性。首次实现不另训练大型修复模型。
- 接受阈值和候选间隔在训练内部校准；证据不足则保留原输出。无原可执行输出且修复未通过时保留失败，不补造答案。
- 单纯恢复可执行或得到非空结果，不足以接受修复。最终以原始自然问题上的净纠正和改错数评估。

## 4. 创新点与贡献边界

### 拟方法增量：受局部约束的单字段修复

研究“字段角色 + 局部事实上下文”是否能减少无关替换，以及条件保护和保守接受是否能减少答案回退。这是同一个方法中的两个可消融设计，不包装成多个独立算法。

一般schema匹配、类型约束、执行筛选、代码纠错和回退都已有研究。[CodeAlignKGQA](https://aclanthology.org/2025.coling-main.267/)包含问题相关子图约束与动态纠错，[Candidate Expressions](https://arxiv.org/abs/2410.00414)已有类型/候选约束。因此不能声称首次图约束或首次查询修复；最终要与近邻的实际机制区分，并超过普通字段修复对照。更完整文献线索见[调研记录](research/PUBLIC_BENCHMARK_REVIEW.md)。

### 实验贡献：公开低资源设置下的效果和代价

验证修复覆盖哪些错误，新增正确是否多于原正确改错，以及局部上下文/保护机制各贡献多少。准确率、条件子类、成本和失败案例共同支撑结论。单纯比最弱模型高几个点，不足以证明拟议机制有价值。

### 应用贡献：有条件的雷达参数知识表达与迁移

将字段角色和值类型约束映射到雷达属性、单位、范围、型号版本和有来源的事实条件。构建小型人工核验应用库，展示可追溯查询；这属于领域适配与系统贡献，不能等同第二个通用算法创新。

## 5. 公开实验如何证明增量

| 对照 | 用途 |
|---|---|
| beam4 + 首个可执行候选 | 已建立的真实基线；80.0%只是原500题参考，新集合需重测 |
| 更多beam候选 + 执行筛选 | 检查提升是否仅来自更多候选预算 |
| 相同单字段编辑 + 全局角色/类型合法字段匹配 | 检查普通字段纠错已能获得多少收益 |
| 局部事实约束修复，移除保守接受或指定兼容检查 | 检验条件保护与减少改错的作用 |
| 完整方法 | 相对以上强对照的净收益和成本 |

同一生成器和训练问题预算、同样可访问KB信息。初步预算为4个原始候选+至多4个修复候选；扩beam对照至多8个执行候选。候选数量相同不等于计算量完全相同，另记生成token、程序重评分、KB检查、执行次数与延迟。
所有题计入分母，修复触发覆盖率另报；成功/失败案例均保留。不用测试金标选字段或挑修复点。

原500题留作开发诊断；现有1,000条排序训练题可在内部划分设计/校准用途。新方向另从未使用的train冻结约2,000题检查效果，分组去重沿用既有规则。该留出集查看后不得继续作为未接触集反复调参；最后冻结方法再跑完整official val。
完整公开报告保留官方答案指标、纠正/改错数、配对区间和修复案例抽查。补三个生成器训练种子，而非只换排序器种子。第二公开数据集或第二生成器是增强证据的选项，不同时开多个大后端。

## 6. 雷达联系与落地范围

通用任务中的“字段角色、值类型、事实条件”对应雷达库中的“属性类别、单位/范围、型号版本及原文条件”。例如不同计量单位可以做明确转换，参数区间必须保留两个端点，某版本的属性不能随意借用另一版本。
这些约束只来自原始证据；没有条件信息就承认缺失。KQA上的结果不能自动证明单位换算或区间推理已经成立，雷达适配须单独验证。

当前库16,609条属性中8,470条含数值和单位，但没有结构化条件，且区间可能被折成端点。先核验20–30个型号，保存“主体—属性—值/区间—单位—来源条件—证据”，独立编写约100–150题。
方法先冻结，再按型号家族/来源分开发和盲测；尽可能由第二人复核。分别报告干净核验库的查询表现与原始抽取库的整体表现。旧图谱、检索和界面继续复用。

## 7. 成立条件与失败处理

目标是相对合理对照的小幅、稳定且可解释的改进，不规定必须增加几个点，不把统计波动或比弱对照好当成成果。
如果单字段修复覆盖过少，或完整方法不优于普通字段匹配，应停止当前机制并保留负结果；按可修复错误决定是否扩展某一种参数映射，不自动扩大成通用Agent/RL平台。
论文可形成“问题与数据 → 局部修复方法 → 公开实验 → 雷达适配系统 → 局限”的结构。已有工程和基线是基础，尚待成立的方法增量必须单独标明。
