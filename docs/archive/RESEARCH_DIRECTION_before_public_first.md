# 研究主线与可行性判断

审查日期：2026-09-26。本文以本地原型、历史结果和下列一手论文为依据，是对[开题方案](../research/proposal.md)的研究审查；其中建议的方法、实验和门槛尚未实现。执行顺序见[路线图](../ROADMAP.md)。

## 1. 当前建议

保留题目 **“面向复杂雷达情报问答的图检索策略学习方法研究”**，主线收敛为：

> 在固定知识图谱上，将复杂问题映射为可执行查询程序，研究可验证的执行反馈是否能帮助小模型在未见算子组合和可恢复错误下，得到更完整的答案、减少无效调用。

**工程上可行，应用问题真实；算法新意和 RL 收益尚未成立。** 当前资产足以启动验证，但不足以直接宣布两个创新点已经成立，也不足以保证强化学习优于充分训练的 SFT。

| 判断维度 | 当前结论 | 原因与成立条件 |
|---|---|---|
| 应用价值 | 有 | 精确集合、计数和关系组合需要执行语义；手册与型号别名提供领域落地场景 |
| 工程可行性 | 较高 | KG、问答数据、确定性工具与旧计划执行器均存在，但尚未统一 |
| 实验可信度 | 需先补基础 | 当前有数据划分重叠、执行边界错误、模板偏差和训练原型未验证的问题 |
| 方法新意 | 有条件，风险较高 | 类型化动作、SFT+RL、过程反馈已有直接近邻；需要更具体的方法差异及公平验证 |
| 硕士论文可交付性 | 可规划 | 可围绕可靠执行、组合泛化与反馈有效性形成实证研究；最终成果要求仍以导师和培养单位标准为准 |
| RL 必要性 | 未证明 | 静态、干净、短程序任务可能由单次程序生成或 SFT 解决；应先比较再投入 |

建议先投入四个工作周完成可否证的小实验，再决定是否扩大 RL。不要先扩大 KG、模型规模、工具数量和应用演示。

## 3. 文献核验后的研究边界

以下来自论文正文、作者仓库或正式论文集，核验截至 2026-09-26。它们说明“图检索 + Agent + RL”与“类型化 + 过程反馈”均不能仅凭组件名称主张创新。

| 近邻工作 | 已经做了什么 | 本项目需要面对的问题 |
|---|---|---|
| Search-R1 | 学习多轮搜索交互，使用结果奖励，并对检索返回的 token 做训练掩码 | 不能将“RL 学何时检索”作为新意；可参考训练与交互实现。[论文](https://arxiv.org/html/2503.09516v5)、[作者代码](https://github.com/PeterGriffinJin/Search-R1) |
| Graph-R1 | 在知识超图环境中训练多轮检索，奖励包含格式和答案 F1 | 不能将“图环境 + RL”作为新意。[论文](https://arxiv.org/html/2507.21892v2)、[作者代码](https://github.com/LHRLAB/Graph-R1) |
| GraphRAG-R1 | 使用检索衰减奖励、成本感知 F1 和阶段训练 | 调整调用数、加入成本惩罚已有先例；其作者仓库当前说明主要提供推理和评测，不应预设可直接复用完整训练。[论文](https://arxiv.org/html/2507.23581v2)、[作者代码](https://github.com/ycygit/GraphRAG-R1) |
| HyperGraphPro | 原名 ProGraph-R1；v2 于 2026-04-12 改题，包含步级进展与结构进展反馈 | “由终局奖励走向密集进展奖励”本身已被研究。[v2 论文](https://arxiv.org/html/2601.17755v2)、[版本记录](https://arxiv.org/abs/2601.17755) |
| **KBQA-R1** | 在可执行 KB 动作中使用查询、交集、排序、比较、计数等操作，经 SFT 冷启动和 GRPO 优化 | **最直接近邻**：不能再以“别人仅自然语言检索，本项目首次类型化算子”作为区分。[v4 论文 §4.1–4.3](https://arxiv.org/html/2512.10999v4)、[作者代码](https://github.com/sunxin000/KBQA-R1) |
| Interactive Semantic Parsing | 逐步生成可执行逻辑查询，使用距离引导的过程奖励；还讨论计数和约束查询 | “可执行逻辑查询 + 过程奖励”也不是空白，须比较具体反馈定义及监督成本。[ACL 2026 论文 §4、附录 F](https://aclanthology.org/2026.findings-acl.1023.pdf) |
| KQA Pro / KoPL 与神经符号方法 | 组合程序和确定性执行有长期基础；KoPL 提供程序监督，早期 NSM 已结合程序生成、变量与 RL | 类型系统和执行器主要是研究基础；需要强程序生成基线。[KQA Pro](https://aclanthology.org/2022.acl-long.422/)、[NSM](https://arxiv.org/abs/1611.00020) |

据此，建议调整开题表述：

1. 将“类型化决策”定位为待验证的动作表示方案和可靠环境，而非仅凭架构图成立的独立新算法。
2. 将“多粒度反馈”具体化为**基于已验证子目标与执行状态的增量反馈**，明确如何处理集合完整性、空结果、等价程序与重复状态。
3. 候选差异在于：相对于答案 F1、调用成本、图距离等反馈，程序语义反馈是否以可接受的监督成本改善组合泛化。该差异是研究假设，尚无新颖性或收益证明。
4. 相关工作需要同时覆盖 GraphRAG 和可执行 KGQA，不能只与 Top-K、ToG、RoG 比较。最邻近方法适配时，应标注“同环境重实现”，不可把适配结果当成作者原结果。

## 4. 最小研究范围与假设

第一版只做固定 KG 上的单跳、多跳、交并差、计数、比较和组合。先不把文本补全、持续更新图谱、置信度校准、电子战对抗和多模态抽取纳入训练。图文解释保留为最终系统的扩展，避免引入不可确定判分的生成任务。

计数和否定默认含义是“在该版本数据库的已记录事实中”。缺边不能证明现实中不存在；真实知识缺失返回 unknown/证据不足，不能当作普通空集合。合法空集、执行错误、截断与未知是四种不同状态。

| 假设 | 比较 | 可接受的结论 |
|---|---|---|
| H1：结构化表示降低执行错误 | 相同工具能力下，扁平与类型化 SFT | 执行率提高且答案/成本至少一项改善；仅 JSON 合法率提高不足以证明推理提升 |
| H2：交互优于单次程序生成 | 同模型、同环境，单次程序 SFT 与多轮 SFT | 在有真实观察依赖或错误恢复的子集上获益；干净静态题无增益可接受 |
| H3：反馈优化超越模仿 | 类型化 SFT、继续 SFT、答案奖励 RL、过程反馈 RL | 组合隔离或恢复测试上有可重复增益；不能只报告训练奖励上升 |
| H4：反馈反映程序语义 | 过程反馈与答案/成本、图距离或支持覆盖反馈比较 | 减少不完整集合、重复调用和错误修复投机，且不损害答案质量 |
| H5：效果不局限于雷达模板 | KQA Pro 的明确适配子集 / 全集 | 同方向结果；若失败，收窄领域结论并报告，不事后把覆盖问题作为无证据解释 |

## 5. 公平实验：先分清表示、学习与奖励

开题当前 2×2 把动作表示和奖励设计同时改变，难以识别增益来源。正式实验先把 RL 奖励固定为相同的终局答案与成本 `R0`：

| 编号 | 动作表示 | 训练方式 | 比较作用 |
|---|---|---|---|
| A | 扁平原子工具 | SFT | 基线 |
| B | 类型化计划 / 数据流 | SFT | B−A 检验表示 |
| C | 与 A 相同 | SFT → RL，统一 R0 | C−A 检验扁平空间的策略优化 |
| D | 与 B 相同 | SFT → RL，统一 R0 | D−B 检验类型化空间的策略优化；D−C 再检验表示 |

然后增加 E：`B → RL，R1 = R0 + 可执行过程反馈`；E−D 才是反馈贡献。增加 F：相同 B 检查点继续 SFT，控制额外训练投入。条件允许再把 R1 用到扁平动作的同一执行状态，验证增益是否依赖表示。必要外部参照是同模型的单次完整程序生成、现有固定路由、prompt-only 工具调用与 KBQA-R1 式结果奖励动作策略；普通文本 RAG 只作应用参照。

公平约束：

- 所有组用相同基座、tokenizer、KG 快照、训练问题、实体候选、可见关系、最终判分和停止规则。金标程序编译为两种表示，保留等价监督信息。
- 扁平基线同样拥有集合、计数与变量句柄；不要故意让它手抄长集合、自由口算或缺少工具。比较的是组织和约束方式。
- 宏动作编译为相同原子工具；同时记录模型轮数、原子查询数、实际扫描量、token、延迟。不能将一个十跳宏动作按“一次调用”与一次原子查询等价计费。
- 相同最大原子查询预算、可见结果和截断规则；类型检查、约束解码与宏动作分别做小消融，否则只能归因于整个表示方案。
- 以同一 SFT 检查点开始 RL；额外监督、候选轨迹数、训练 token 和 GPU 小时全部记录。R1 使用金标程序/支持事实属于更强训练监督，不能称为“只用答案标签”。
- 最终精确答案由执行结果引用生成，所有组共用渲染器；语言润色不进入核心 EM。把“答案相同但无正确执行证据”单独列为碰巧答对。
- 正式核心组至少三个训练随机种子；在同一问题上做配对 bootstrap，按程序家族聚类，避免大量同模板题放大显著性。先固定主指标和测试集，再做正式比较。

## 6. 可执行反馈：先防投机，再研究增益

第一版只实现少量可审计信号，不将所有设想线性相加。状态包括变量的类型和值、来源节点、已经满足的子目标、执行错误和剩余预算；训练用金标保存在评分器，策略只看到真实工具观察。

**基础奖励 R0：** 终局集合 EM / 数值严格匹配为主，集合 F1 作有界的部分信用；格式合法本身不获得可累积正奖励；以归一化原子成本控制冗长。每条轨迹的成本与格式项有界，保证完整正确执行优先于错误答案。

**候选过程反馈 R1：** 只对首次得到一个已验证、可被最终数据流使用的子目标结果计分；验证包含算子语义、类型、依赖和结果集合，不能仅凭结果含金标实体。规范化变量名和交换律后接受等价次序，保存重复状态指纹。完整正确轨迹与非完整轨迹设置不重叠的总分区间，终局与过程奖励分别记录。具体权重只在开发集选择。

| 可能的投机 | 必须具备的防护 / 验证 |
|---|---|
| 不检索直接背出答案 | 同时报答案分与有来源的执行分；`finish` 引用已执行变量；用改名、局部事实替换的反事实图检查是否跟随环境 |
| 为合法 JSON、重复查询刷分 | 格式不逐步加分；同一语义状态只记一次进展；重复、缓存命中与空耗仍计成本 |
| 返回全部实体提高支持覆盖 | 奖励检查集合 precision 与 recall / 完整执行约束，不能只奖励 recall；完整结果保存在执行器，样例不能拿来计数 |
| 不断缩小集合以冒充进展 | 集合变小不等于更正确；union 和路径展开可合法增大集合；进展以完成哪个语义子目标为依据 |
| 主动制造错误再领取修复奖励 | 不奖励自造错误；恢复正例来自预先固定的环境扰动，与干净配对样本比较总成本；无法恢复时正确停止 |
| 只学唯一金标程序 | 等价程序、不同约束顺序共用执行判分；单图上输出相同仅称“指称相同”，不冒称逻辑等价 |
| 利用宽松数值/布尔解析 | 类型严格校验；不能从任意字符串抽第一个整数当正确数值；比较题同时验证比较对象、维度与执行来源 |
| 把未知当否定、截断当全集 | 分开 `empty/error/unknown/truncated`；仅在定义好的闭世界数据子集验证否定与完整计数 |
| 策略看到了评分信息 | `gold_answer/gold_support/program/split` 不进入模型提示；评测接口传公开输入，不把整条带金标样本交给真实策略 |

若使用势函数差 `γΦ(s_next)−Φ(s)`，应处理终止状态与折扣一致性，并保留对完整回报的核对；不能把截断、裁剪、终局门控后的启发式奖励仍宣称为有理论不变性保证。先交付奖励攻击用例和轨迹审计，再比较训练收益。

## 7. 数据：组合泛化比继续放量更紧迫

目前 anchor 不交，但按题目支持结构抽取的直接查询实体中，测试集 315 个有 143 个也出现在训练集。现有划分只能称 **anchor 分桶**。同时，oracle 与 SFT 轨迹用同一套工具构造，需独立参考执行器核验。

正式数据版本应包含 `qid/question/program/answer_kind/gold_answer/support_ids/kg_hash/split_manifest`，保留旧版不覆盖。生成程序后再生成自然语言，并记录改写来源；全部同义改写、反向表述、count/enumerate 对、交换比较对象的题目按同一语义家族分桶。

| 测试集 | 划分方式 | 可检验的结论 |
|---|---|---|
| IID | 按程序实例家族去重后随机划分 | 同分布学习效果 |
| 组合隔离，主测试 | 对去实体/常量并规范化交换顺序的 AST 分组；训练覆盖所有原子算子，但保留部分嵌套组合给测试 | 见过算子，未见组合；另外记录关系组合隔离和更长程序外推，避免混称 |
| 目标实体隔离 | 同一雷达在主语、比较对象、路径中间变量中的角色一起分配；报告答案/支持实体交集 | 控制目标实体记忆；国家、频段等共享 schema 常量明确列为允许共享 |
| 严格支持实体隔离，若可构造 | 所有被定义为隔离对象的实体及别名跨集合交集为零 | 比目标实体隔离更强；若图连通性导致无法实现，就不声称严格隔离 |
| 错误恢复 | 固定别名扰动、临时失败、歧义候选与不可恢复缺失；干净题配对且扰动类型留出 | 利用观察修复或正确停止；无替代通道的缺失不能要求凭空找回答案 |
| 自然语言审计集 | 人工校验问题与程序一致；包含合法空集、零计数、否定及高基数集合 | 减少模板和只保留非空答案造成的偏差 |

各划分应独立成测试套件，不强求一个小数据集同时承受全部隔离条件。训练前发布规模、程序深度、答案大小、布尔比例、重复率与交集审计。KG 在推理时包含测试实体并不违规，但这是固定图上的传导式 KGQA，不能宣称未见图谱泛化。

公开验证优先 **KQA Pro**：使用官方 KB 和 KoPL 执行语义，保留 qualifier、属性类型和过滤逻辑，不能把全部语义扁平化为简单边后直接报完整基准结果。先发布支持的算子清单、筛选规则、题数与环境 oracle，再报告完整集和支持子集各自结果。[官方代码](https://github.com/shijx12/KQAPro_Baselines)

MetaQA 可做较低成本的多跳迁移补充，但不能替代集合、差集、比较与聚合的验证；其定位以[官方任务定义](https://github.com/yuyuz/MetaQA)为准。现阶段不同时承诺适配四五个公开集。

## 8. 最终应形成的论文证据链

1. 定义一个真实且可复现的复杂查询任务，冻结图谱、程序与划分，独立验证环境。
2. 用公平程序基线确认类型化交互有用的条件，指出单次程序生成已经足够的情况。
3. 给出具体、可复现且经过攻击测试的反馈定义，披露额外监督信息。
4. 对未见组合、完整集合和错误恢复做同条件比较，并给出公开集验证与负结果。
5. 将最有效的方法接入现有雷达应用；若 RL 无增益，保留 SFT/程序执行路线和失败分析，修改论文贡献表述。

当前最值得继续的问题不是“能否再做一个 GraphRAG Agent”，而是：**在已经能够可靠执行复杂查询的环境里，什么反馈和训练方法真正改善了未见组合，并且值得支付额外训练成本？** 这个问题可检验、有应用意义；能否形成方法贡献由后续证据决定。
