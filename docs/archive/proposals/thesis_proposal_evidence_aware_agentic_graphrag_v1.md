## 论文题目

**面向复杂雷达情报问答的证据可信性感知智能体式图检索增强生成方法研究**

## 一、开题摘要

雷达情报知识具有实体型号密集、别名缩写多、关系链条长、来源异构且事实可能冲突等特点。传统检索增强生成通常采用一次性文本召回，难以稳定完成多跳关系、集合交并差、计数比较和多约束筛选等复杂查询；现有基于知识图谱的检索增强生成方法虽然引入了结构化关系，但检索路径和工具调用仍较多依赖固定启发式规则或提示词，面对不同问题时缺少可学习的自适应检索策略。同时，多数方法主要优化最终答案正确率和检索成本，较少显式建模证据来源等级、多源印证和事实冲突对检索决策的影响。

本研究拟面向复杂雷达情报问答，构建证据可信性感知的智能体式图检索增强生成方法。首先，将雷达领域知识图谱、叙述文本库以及类型化查询工具封装为可交互环境，把复杂问答建模为智能体在图文知识环境中的多轮序贯决策过程；其次，利用可执行查询结果构造单跳、多跳、计数、集合运算、比较和多约束等可自动判分任务，通过成功轨迹监督微调与执行反馈强化学习，使模型学习何时调用何种工具、如何根据中间观察继续检索以及何时终止；最后，将事实来源层级、多源印证、证据链完整性和冲突状态纳入奖励与验证机制，引导智能体在保证答案正确性的同时优先选择高可信证据，并在冲突或证据不足时进行审慎回答或拒答。

实验拟在自建雷达知识图谱问答数据集上开展主实验，并在 KQA Pro、MetaQA 等公开复杂知识图谱问答数据集上验证组合推理和跨领域泛化能力；同时通过真实冲突样本与可复现的受控冲突注入实验验证证据可信性机制。研究将从答案正确性、执行成功率、证据可靠性、冲突识别能力、检索成本和泛化性能等维度，与单轮混合检索、提示式 ReAct、确定性算子规划、SFT-only 及不含可信性奖励的强化学习方法进行比较。

关键词：雷达情报问答；智能体式 GraphRAG；知识图谱；强化学习；执行反馈；证据可信性

## 二、研究背景与意义

### 2.1 研究背景

雷达装备资料分散于装备手册、技术报告、结构化数据库、网页和扫描文档中，同一装备可能存在多种名称、不同改型及跨来源参数差异。面向装备档案、型号对比、体系关联和对抗分析的问答任务，往往不是“从某一段文字中找到一句答案”，而是需要完成如下组合过程：

1. 识别型号、平台、国家、厂商、频段等实体和约束；
2. 沿多条关系路径查询并组合中间结果；
3. 对候选集合执行交集、差集、计数、枚举或比较；
4. 判断证据是否来自可靠来源、是否得到多源印证、是否存在冲突；
5. 依据可追溯证据生成最终回答。

传统 RAG 的单次 Top-K 文本召回容易遗漏跨文档关系链，高基数枚举与精确计数也难以通过有限上下文可靠完成。知识图谱提供了确定性的关系查询基础，但固定查询模板难以覆盖自然语言问题的多样组合。智能体式 GraphRAG 将检索视为多轮工具交互，为复杂问答提供了新的技术路线；强化学习则有望利用最终执行结果反向优化工具选择和检索策略。

### 2.2 理论意义

本研究关注的不只是“让模型多调用几次工具”，而是研究三个相互关联的问题：复杂知识问答如何表示为可学习的序贯决策过程；稀疏的最终答案奖励如何与可执行工具反馈结合；证据来源、印证和冲突等可信性信号如何进入策略学习目标。相关研究可为领域知识图谱问答、可验证 RAG 和工具增强大模型提供方法参考。

### 2.3 应用意义

研究成果可服务于雷达装备档案生成、型号对比、关联分析和情报报告辅助生成。通过保留查询轨迹、证据来源和冲突状态，系统输出能够被人工复核，降低仅依赖大模型参数知识产生幻觉的风险。

## 三、国内外研究现状与本研究定位

### 3.1 从图推理到智能体式 GraphRAG

ReAct 将推理与行动交错执行，为大模型工具调用提供了基础范式。ToG 将大模型作为智能体在知识图谱上迭代搜索关系和实体；RoG 采用“规划关系路径—检索有效路径—基于路径推理”的方式提高知识图谱推理的可解释性。这些方法证明了图结构对多跳问答有价值，但策略通常依赖提示、启发式搜索或监督训练。

2025 年以来，Search-R1 和 ReSearch 使用强化学习训练模型在推理过程中主动调用搜索工具。随后，Graph-R1 将图检索建模为多轮智能体—环境交互，并使用端到端强化学习优化检索过程；GraphRAG-R1 进一步设计渐进检索衰减和成本感知 F1 奖励，缓解检索过浅和过度思考问题。这些工作直接证明了“多轮检索 + 可验证结果奖励 + 强化学习”路线的正确性，也意味着本论文不能将“使用 GRPO 训练 GraphRAG Agent”本身表述为独立首创。

### 3.2 可信 RAG 与知识冲突处理

现有 RAG 可信性研究表明，答案正确、引用正确与模型真实依赖引用证据并不是同一概念。TruthfulRAG 使用知识图谱定位事实级冲突；FaithfulRAG、FaithEval、ConflictQA 等工作研究了模型参数知识与外部上下文冲突、跨来源冲突和上下文忠实性。2026 年出现的引用感知奖励研究还表明，仅使用最终答案奖励容易导致捷径行为，需要对证据连接和归因进行更细粒度约束。

现有 Agentic GraphRAG 强化学习主要优化答案、检索深度、格式和成本；现有冲突处理工作则多在检索后进行过滤或生成约束。将知识图谱中已有的来源等级、多源印证和事实冲突直接作为检索策略学习信号，仍具有明确的研究空间。

### 3.3 本研究的定位

本研究不主张重新发明 GraphRAG 或 GRPO，而是在已有智能体检索强化学习范式上，研究**面向带来源与冲突元数据的领域知识图谱，如何学习兼顾正确性、证据可信性与执行成本的组合查询策略**。

与代表性工作的主要差异如下：

| 方法 | 主要环境 | 主要优化目标 | 与本研究的区别 |
|---|---|---|---|
| ReAct | 通用工具/文本 | 提示式推理与行动 | 无策略训练，稳定性依赖提示和基座模型 |
| ToG / RoG | 通用知识图谱 | 路径搜索与忠实推理 | 以启发式、规划或监督方式为主 |
| Search-R1 / ReSearch | 文本搜索引擎 | 最终答案与搜索行为 | 不面向类型化图查询和证据来源等级 |
| Graph-R1 | 文档知识超图 | 答案质量、检索效率 | 重点是轻量图构建和端到端图检索策略 |
| GraphRAG-R1 | 图文混合检索 | 检索深度、F1 与成本 | 重点是过程约束和成本，不显式利用来源印证与事实冲突 |
| TruthfulRAG | 文本构图后的 RAG | 事实级冲突消解 | 主要是推理时过滤，不训练多工具检索策略 |
| 本研究 | 雷达图谱 + 叙述库 + 类型化工具 | 正确性、可信证据、冲突处理与成本 | 以来源等级、多源印证和冲突状态塑造智能体检索策略 |

## 四、拟解决的核心问题

### 4.1 总体科学问题

在具有来源层级、多源印证和事实冲突的领域知识图谱中，如何利用可执行反馈训练智能体式 GraphRAG 策略，使其在复杂组合问答中同时优化答案正确性、证据可靠性和检索成本？

### 4.2 子问题

1. 如何将图查询、集合运算、文本检索和终止回答统一表示为可学习且可执行的动作空间？
2. 如何从知识图谱自动构造规模足够、答案可确定验证、执行轨迹可复现的训练任务？
3. 如何设计不会鼓励“为了高可信而回避正确答案”的证据可信性奖励？
4. 强化学习相对提示式 ReAct 和成功轨迹 SFT，是否真正提升未见组合问题上的工具调度能力？
5. 雷达领域学到的策略能力能否在公开知识图谱问答基准上得到独立验证？

### 4.3 可检验研究假设

- H1：执行反馈强化学习在多跳、多约束、计数和集合问题上优于 prompt-only ReAct 与 SFT-only。
- H2：在答案正确性约束下加入证据可信性奖励，可降低低等级、未印证证据的使用比例，并提高冲突识别和审慎回答能力。
- H3：类型化图工具相对单一搜索工具，可提高组合查询执行成功率并减少无关上下文。
- H4：策略在 KQA Pro、MetaQA 等公开数据集上仍能取得相对基线的稳定增益，说明提升不只是雷达模板记忆。

## 五、已有研究基础审计

### 5.1 雷达知识与检索基础

当前 `kg_v3` 包含 22,241 条边、10,744 个实体和 16,609 条属性记录；其中 2,413 条边具有多源印证标记，构建报告记录 553 组单值关系多尾冲突。经当前 RL 环境的过滤规则处理后，可用于冲突识别任务的冲突组为 331 组。两处数字口径不同，论文中应分别称为“原始构建冲突”和“过滤后可训练冲突”，不能混用。

已有系统还包括 BM25、FAISS、RRF、图扩展与 Cross-Encoder 重排组成的混合检索链路，以及 1,432 段叙述文本库。这些能力可作为单轮 RAG 基线，也可封装为智能体的文本/混合检索工具。

### 5.2 当前问答与轨迹数据

当前 `ca_agraphrag/data` 的数据规模如下：

| 划分 | 数量 | 题型 |
|---|---:|---|
| train | 4,277 | 单跳、两跳、计数、枚举、比较、否定、多约束 |
| dev | 582 | 同上 |
| test | 542 | 同上 |
| SFT 可执行轨迹 | 4,277 | 与训练问题对应 |

已对 5,401 道问题执行 oracle 回放，所有金标轨迹均可通过现有工具复现并获得满分。可自动生成的候选任务规模包括约 21,928 个单跳事实、15,868 个两跳桥接、813 个可用计数/枚举分组、19,385 个比较对以及约 21,928 个否定候选，说明执行反馈任务的数量基础成立。

当前 dev/test 另有 582/542 条 LLM 润色版本，润色脚本只修改问题文本，并通过关键实体与约束 token 保留检查保护金标。该处理改善了模板句的表面自然度，但尚未替代人工语义一致性抽检；训练问题和 SFT 轨迹仍主要来自模板生成。

### 5.3 当前实现成熟度

现有代码已经具备只读知识图谱工具环境、答案自动评分、数据生成、成功轨迹生成、SFT 脚本、GRPO 原型和策略评测入口。当前可认定为“方法原型已打通”，不能认定为“强化学习实验已经完成”，原因包括：

1. 当前环境奖励只有答案正确性、格式和步数惩罚，可信性奖励尚未实现；
2. 工具返回值尚未完整携带来源层级、印证和冲突元数据；
3. 当前 GRPO 为简化自研实现，KL、rollout、分布式显存和数值稳定性仍需在 GPU 上验证；
4. 训练集问题主要由模板生成，dev/test 虽已有自动润色版本，仍存在实体脏值、语言多样性和人工验收不足的问题；
5. 当前按 anchor 哈希划分只能保证锚点不跨集合，尚不能证明答案实体、关系模板和近重复表达不存在泄漏。

因此，正式实验应优先采用成熟 RL 训练框架，先以 1.5B/3B 模型验证奖励和训练趋势，再决定是否扩展到 7B。4×24GB 显卡可支持 LoRA/QLoRA 方案验证，但不应在开题中承诺一定完成 7B 全参数或大组在线 GRPO。

## 六、公开数据集与外部可验证性方案

### 6.1 可用公开数据集

| 数据集 | 规模与特点 | 可验证能力 | 使用建议 |
|---|---|---|---|
| KQA Pro | 117,970 个问题，提供 KoPL 程序、SPARQL 和答案；含 27 种基础函数 | 多跳、属性、计数、比较、集合组合和程序执行 | **首选公开主基准**；与本研究类型化工具最匹配 |
| MetaQA | 电影领域 KG，提供 1/2/3-hop 问题和显式知识库 | 路径检索、跨跳泛化、低成本复现 | **首选轻量辅助基准** |
| GrailQA | 64,331 个 Freebase 问题，含逻辑形式，提供 i.i.d./组合/零样本划分 | 组合泛化和零样本 schema 泛化 | 可作为高难度扩展，部署 Freebase 成本较高 |
| WebQSP | 4,737 个带 SPARQL 语义解析的问题 | 自然问题、1/2-hop Freebase KGQA | 适合小规模迁移验证 |
| ComplexWebQuestions | 由简单问题组合得到的复杂问题 | 问题分解、多约束和组合问答 | 适合复杂自然语言评测，Freebase 依赖较重 |
| Mintaka | 20,000 个自然问题，含多跳、交集、计数、比较等 8 类复杂题 | 自然语言泛化、多类型问答 | 适合作为端到端 OOD 评测，不宜作为首个 RL 环境 |
| LC-QuAD 2.0 | 30,000 个问题及 SPARQL，基于 Wikidata/DBpedia | 可执行查询、复杂意图和限定符 | 可用于 Text-to-SPARQL/工具调用扩展 |
| HotpotQA / 2WikiMultiHopQA / MuSiQue | 多文档、多跳文本问答 | 与 Graph-R1 系列直接对齐 | 用于图文混合扩展，构图和训练成本较高 |
| FaithEval / ConflictQA | 含不一致、反事实或参数知识冲突场景 | 上下文忠实性和冲突处理 | 用于辅助验证，不直接替代图谱冲突实验 |

### 6.2 当前仓库中的公开数据基础

仓库已经包含 KQA Pro 的 11,797 条验证问题和完整 KB 适配器。实测该适配器可展开 362,023 条扁平三元组、123,328 个不同节点值和 990 种关系/属性；同时已保存 Mintaka 的 2,000 条 dev、4,000 条 test，LC-QuAD 2.0 的 24,180 条 train、6,046 条 test，以及 WebQSP validation parquet。这说明公开评测不是从零开始，但现有适配器仍需接入新的多轮 RL 环境和统一工具协议。

### 6.3 推荐的最小公开验证组合

为控制硕士论文工作量，建议正式主表只固定三个层级：

1. **RadarKG-QA**：领域主实验，验证类型化组合查询和真实来源/冲突信号；
2. **KQA Pro**：公开主实验，验证多算子组合和跨领域泛化；
3. **MetaQA 2-hop/3-hop**：轻量辅助实验，验证多跳检索策略。

Mintaka、LC-QuAD 2.0、WebQSP、CWQ 和文本多跳基准可作为时间允许时的扩展，不应全部写成必须完成的开题承诺。

### 6.4 可信性机制的公开可复现实验

公开 KGQA 数据通常没有来源等级和多源冲突标签，因此可信性创新应采用双轨验证：

1. 在雷达图谱的真实来源、印证和冲突标记上进行主实验；
2. 在 KQA Pro 上发布可复现的受控扰动协议：针对功能上近似单值的关系注入错误尾实体，为正确/错误事实配置不同来源等级和印证数量，构造无冲突、同等级冲突、低可信冲突和高可信冲突四类样本；
3. 使用 ConflictQA 或 FaithEval 作为文本冲突辅助集，验证模型行为是否能迁移到图外证据冲突。

受控扰动必须只作用于 dev/test 的环境副本，不能污染训练金标；注入规则、随机种子和冲突比例应公开，以保证实验可重复。

## 七、研究内容与技术路线

### 7.1 总体框架

用户问题首先进入策略模型。策略模型依据问题、历史动作和工具观察，在多轮过程中选择图查询、集合运算、文本搜索或终止回答。工具环境执行动作并返回结果集合及证据元数据；训练阶段根据最终答案、证据质量、冲突行为、格式和调用成本计算奖励，更新策略模型。

技术链路可概括为：

```text
问题与任务状态
    -> 策略模型（推理 / 选择工具）
    -> 图查询、图扩展、集合运算、计数比较、文本/混合检索
    -> 结果 + 来源层级 + 印证状态 + 冲突状态
    -> 继续检索 / 修正 / 终止
    -> 可验证答案与证据链
    -> 执行反馈和可信性奖励
```

### 7.2 序贯决策建模

将一次问答建模为有限步马尔可夫决策过程：

- 状态 `s_t`：原始问题、已识别实体、历史工具调用、中间结果、剩余步数和证据元数据；
- 动作 `a_t`：选择工具及其结构化参数；
- 转移：只读知识环境执行工具并返回确定性观察；
- 终止：调用 `finish`、达到最大步数或出现不可恢复的非法动作；
- 策略：参数化语言模型根据状态生成下一步结构化动作。

建议动作空间包含：`graph_lookup`、`subgraph`、`find/attr_filter`、`intersect`、`union`、`difference`、`count/enumerate`、`hybrid_search/text_search` 和 `finish`。正式实现中可合并功能相近的工具，动作空间以“足以表达任务且参数可验证”为原则。

### 7.3 执行反馈强化学习

训练采用“成功轨迹冷启动 + 强化学习优化”的两阶段方案：

1. 通过金标程序或确定性规划器生成可执行成功轨迹，进行 SFT，使模型先学会 JSON 协议、工具参数和基本组合模式；
2. 从同一问题采样多条交互轨迹，根据环境执行结果计算组内相对优势，采用 GRPO 或其他稳定策略优化算法更新模型；
3. 采用从单跳、计数到多跳、多约束和冲突任务的课程学习，逐步增加探索难度；
4. 对工具返回 token 进行 loss masking，避免把不可学习的环境观察当作策略输出优化。

GRPO 是当前优先实现方案，但论文方法应表述为“基于组相对优势的执行反馈策略优化”；若后续实验表明 PPO、REINFORCE++ 或其他方法更稳定，可替换具体优化器而不改变研究主线。

### 7.4 证据可信性感知奖励

总奖励设计为：

```text
R = R_answer
  + lambda_e * R_evidence
  + lambda_c * R_conflict
  + lambda_f * R_format
  - lambda_s * C_steps
```

- `R_answer`：标量题使用 EM，集合题使用 F1，计数题使用精确或容差得分，比较/布尔题使用结构化正确率；
- `R_evidence`：奖励高等级来源、多源印证和完整证据链，惩罚仅依赖低等级、未印证证据；
- `R_conflict`：奖励识别并展示冲突、按来源规则审慎选择或拒答，惩罚无视冲突武断输出；
- `R_format`：奖励合法动作和可解析参数；
- `C_steps`：约束无效检索、重复调用、过长轨迹和 token 成本。

为防止 reward hacking，可信性正奖励应由答案正确性门控：错误答案不能仅因引用高等级证据获得高总奖励；拒答奖励只在证据确实不足或冲突不可消解的标注任务中生效。来源层级不是“真值”，多源印证也不等于绝对正确，因此奖励应在人工校准集上调参与验证。

### 7.5 可追溯输出与验证

最终输出包括答案、执行轨迹、关键三元组、来源标识、来源等级、印证状态和冲突说明。答案生成阶段只允许使用已命中的结构化事实和文本证据；再通过规则校验与事实级验证检查实体、数值和引用是否超出证据范围。

## 八、数据集完善方案

### 8.1 雷达问题集完善

1. 清理实体脏值、截断名称和异常符号，重新生成受影响问题；
2. 为每种题型抽取不少于 100 条进行人工正确性和自然度检查；
3. 在模板问题之外，引入人工改写或模型改写后人工验收，提高语言多样性；
4. 增加需要三步以上或混合图文工具的组合题，避免训练任务全部可由单个 lookup 完成；
5. 为冲突题标注“可按来源消解、应并列呈现、证据不足应拒答”三类目标行为。

### 8.2 防止数据泄漏

当前 anchor 哈希划分应升级为至少三种评测划分：

- 实体划分：核心问题实体不跨 train/dev/test；
- 组合划分：测试集保留训练中未出现的关系组合或程序模板；
- 时间/来源划分：若元数据允许，按文档或来源批次划分，测试跨来源泛化。

同时检查答案实体重叠、问题近重复、同一事实的正反问泄漏和 SFT 轨迹对测试集的污染。测试集一旦确定应冻结，不参与奖励调参。

### 8.3 数据质量评价

自动检查包括程序可执行率、答案非空率、类型约束、重复率、冲突标签一致性和轨迹回放成功率；人工检查包括问题自然度、问题—程序一致性、答案正确性和证据充分性。报告数据质量时给出抽样方法、样本数、置信区间和错误类型，而不只给单一“准确率”。

## 九、实验设计

### 9.1 对比方法

1. 单轮 BM25、向量检索和 BM25+向量混合检索；
2. 单轮 Hybrid GraphRAG；
3. prompt-only ReAct + 相同工具；
4. 确定性算子规划器；
5. SFT-only Agent；
6. 执行反馈 RL，不含证据可信性奖励；
7. 完整方法；
8. 在复现成本可控时加入 ToG、RoG、Graph-R1 或 GraphRAG-R1。

所有 Agent 对比应尽量使用相同基座模型、工具环境、最大步数和上下文预算，避免把模型规模差异误认为算法增益。

### 9.2 主要指标

- 答案：EM、Accuracy、集合 Precision/Recall/F1、计数误差；
- 执行：工具调用成功率、程序/轨迹执行正确率、多跳完成率；
- 检索：Recall@K、MRR、证据路径覆盖率；
- 可信性：高可信证据使用率、低可信孤证依赖率、证据链完整率；
- 冲突：冲突检测 Precision/Recall/F1、冲突消解准确率、合理拒答率；
- 校准：风险—覆盖曲线、选择性准确率，必要时报告 ECE；
- 成本：平均工具调用数、检索 token、响应延迟和显存/训练时间。

### 9.3 消融实验

| 消融设置 | 验证内容 |
|---|---|
| 去除 RL，仅保留 SFT | 强化学习是否带来策略增益 |
| 去除可信性奖励 | 来源、印证与冲突信号的独立贡献 |
| 去除冲突项，仅保留来源等级 | 冲突行为是否来自专门奖励 |
| 去除步数成本 | 成本约束对过度检索的影响 |
| 去除集合/计数/文本工具 | 不同工具对相应题型的贡献 |
| 限制为单轮 | 多轮交互相对单轮 GraphRAG 的价值 |
| 随机化来源等级 | 排除模型只记忆 tier 标签表面模式 |

### 9.4 统计方案

正式结果至少使用 3 个随机种子；对同一测试问题上的方法差异进行配对 bootstrap 置信区间或随机化检验；同时报告总体结果和按题型、跳数、冲突类型、证据等级分组的结果。失败案例应区分实体识别、工具选择、参数生成、图谱缺失、证据冲突和答案生成错误。

## 十、拟创新点

### 创新点一：面向复杂领域问答的可执行智能体式图检索建模

将混合图文检索、关系查询、集合运算、计数比较和终止回答统一建模为多轮序贯决策过程，使大模型学习组合使用类型化工具，而不是依赖一次性 Top-K 召回或固定查询计划。创新重点在于领域复杂问题、类型化组合动作和可执行环境的统一，而不是工具本身。

### 创新点二：基于执行结果的复杂图检索策略强化方法

利用知识图谱可确定执行的特性，自动构造带金标答案和可回放轨迹的多类型任务，采用成功轨迹冷启动和执行反馈策略优化，研究模型能否从局部可判分技能学习可泛化的多轮检索策略。通过与 prompt-only、SFT-only 和确定性规划器比较，验证策略学习的实际增益。

### 创新点三：来源—印证—冲突联合驱动的证据可信性奖励

把事实来源等级、多源印证、证据链完整性和冲突状态从输出展示信息提升为策略学习信号，在答案正确性门控下共同塑造检索行为，使智能体不仅追求“答对”，还学习“基于什么证据回答、冲突时如何回答”。该点是相对现有 Graph-R1/GraphRAG-R1 最需要重点论证和消融验证的差异。

> 创新表述边界：开题和论文中宜使用“提出”“设计”“面向雷达领域构建”，避免使用“首次将 RL 用于 GraphRAG”或“首次处理知识冲突”等已不成立的绝对表述。

## 十一、可行性分析与风险控制

### 11.1 可行性结论

方向总体可行，依据如下：

1. Graph-R1、GraphRAG-R1、Search-R1 和 ReSearch 已验证多轮检索强化学习在公开问答任务上的有效性；
2. 本项目已具备可执行 KG 环境、5,401 道可回放问题、4,277 条 SFT 轨迹和万级可自动判分候选任务；
3. KQA Pro 本地适配已能读取完整 KB，为公开组合问答验证提供了现实基础；
4. 雷达图谱原生保存来源、印证和冲突元数据，能够支持可信性奖励，而无需完全依赖模型自评分；
5. 题目未绑定具体优化算法和模型规模，允许根据显存与训练稳定性调整实现。

### 11.2 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 与 Graph-R1/GraphRAG-R1 创新重叠 | 创新性被质疑 | 将主差异固定为证据可信性策略学习和领域可执行组合工具，完成针对性消融 |
| 生成问题模板化 | 模型记忆模板而非学习策略 | 组合划分、自然语言改写、人工抽检和公开集迁移 |
| 可信性奖励诱导保守或拒答 | 正确率下降、奖励投机 | 正确性门控、风险—覆盖评测、随机化 tier 对照 |
| 真实冲突样本较少 | 统计功效不足 | 真实 331 组为主，增加 KQA Pro 可复现受控冲突测试，不虚构真实来源 |
| 图谱缺失导致假负例 | 奖励错误 | 只在覆盖闭世界子集训练否定/计数，多源文本仅用于评测或补充证据 |
| 7B 在线 GRPO 显存不足 | 无法完成训练 | 先做 1.5B/3B LoRA；使用成熟框架、量化、ZeRO/offload；7B 作为扩展 |
| 自研 GRPO 数值不可靠 | 结论不可复现 | 采用 veRL/TRL 等成熟实现，并用小环境单元测试验证 logprob、mask 和 reward |
| 公开集接入工作量过大 | 延误主实验 | 只承诺 KQA Pro + MetaQA，其他基准作为扩展 |

## 十五、开题时应主动说明的三个判断

1. **为什么方向可行**：公开工作已经证明多轮检索 RL 有效，本项目又具备可执行环境、训练题和硬件/代码基础，因此不是从概念起步。
2. **为什么还有创新空间**：已有图检索 RL 主要优化答案、检索深度和成本，本研究使用真实领域图谱的来源、印证和冲突元数据直接训练检索策略，研究问题不同。
3. **如何防止只在自建数据上自证**：以 KQA Pro 为公开主基准、MetaQA 为辅助基准，并发布受控冲突注入协议；领域结论和通用结论分开报告。

## 文档结论

该选题方向正确且具备现实可行性，但创新论证必须从“Agentic GraphRAG + RL”这一已经出现的通用范式，收敛到“在带来源、印证与冲突元数据的领域知识环境中，以证据可信性信号学习复杂组合检索策略”。建议以本文题目作为开题题目，以 KQA Pro 和 MetaQA 作为明确承诺的公开验证集，以小模型完成闭环作为最低交付线，再根据资源扩展到 7B 和更多公开基准。
