## 1. 系统总览

```
问题 ──► [策略模型 πθ (7B, LoRA)] ──多轮──► think → 选工具 → 执行 → 观察 → …→ finish
                 │                              │
                 │  动作空间 = 工具集(§3)        │ 每步返回观察 + (若命中) 证据的 tier/冲突标记
                 │                              ▼
                 │                       KG 环境(只读 kg_v3)+ 叙述库 + 混合检索底座
                 ▼
        奖励 r = 答案正确性(可判分题型) + trust 奖励项(§4) + 格式/效率项
                 │
                 ▼
        GRPO 更新 πθ (SFT 冷启动 → RL);4×4090 + LoRA
```

**基线**:现有混合检索(BM25+FAISS+RRF+图扩展+Cross-Encoder,`graphrag_retriever.py`)——
单轮、完备,是"多轮 agent 是否真有增益"的对照下限。

## 2. 两道硬门(开工前必须过,决定可行性)

> 纪律沿用诊断协议:先测量/先想清,后投入。任一不过则改方案。

- **G1 奖励可行性(纸上可定,本方案第一步)** —— ✅ **已过**(`experiments/g1_reward_feasibility.py`,2026-07-09):
  - **可自动判分(→可进 reward),量级万级以上,充足**:单跳 22,241 / 2跳桥接 16,119(top模板
    developedBy∘headquarteredIn、hasVariant∘deployedOn…)/ 计数·枚举 853 组(deployedOn 464、
    developedBy 121、operatedBy 91…组大小∈[3,30])/ 比较 16,486 对 / 否定 22k+。
  - **多约束过滤**:可判分,但金标**须限'有该属性/关系的覆盖子集'**(承 71% 缺失教训)。
  - **trust 奖励主场**:474 冲突题 + 任意答案的证据 tier/印证标记。
  - **❌ 复杂/抽象/任务型**:无确定金标,不可进 reward → **只能当泛化评测集**(LLM-judge)。
  - **核心矛盾的对策(定案)**:在可判分子技能(单跳/计数/集合/多跳)上训策略 → **测其对复杂题的
    零样本泛化**。论文的核心赌注 = "多轮策略在子技能上训出的组合能力,泛化到复杂问题优于单轮检索"——可测。
- **G2 题量/轨迹生成(最大工程量)**:RL 吃题量(数千条带金标的轨迹环境),靠人工不现实,
  须**模板自动生成 + 抽样人工校验**。确认各可判分题型能生成的量级(关系频次已核,足够)。

**已确认成立的前提(无需再验)**:trust 奖励的地基——441 冲突 + 分层置信度(manual/llm_grounded/…)
是**真实存在的信号**(与已证伪的属性地基不同),奖励项有东西可挂。

## 4. 奖励设计(论文的"自己的想法"所在)

`r = α·correctness + β·trust + γ·format − δ·step_penalty`

- **correctness(主项,仅可判分题型)**:EM / 集合 F1 / 数值容差(见 G1 表);
- **trust(创新组件,可消融)**:
  - 答案若建立在**低层级证据**(llm_hinted/judge)且**无多源印证** → 扣分;建立在
    **印证过的高层级证据** → 加分;
  - **冲突题**:策略若识别冲突并对冲/弃权(而非武断取一值) → 加分;武断取值且取错 → 重罚;
  - 目的:让策略**学出**偏好可信证据、冲突时审慎的行为,而非事后重排。**±trust 项消融量化其价值**。
- **format**:合法工具调用/可解析计划;**step_penalty**:多轮成本控制(呼应"少调用更好")。

## 5. 训练方案(工程主体)

1. **环境封装**:KG + 工具集包装成 gym 式多轮环境,每步 (obs, action) → (obs', reward_partial);
2. **SFT 冷启动(救命步,不可省)**:用规则/强模型产出的**成功轨迹**微调 πθ,给 RL 一个能用的起点,
   不指望纯 RL 从零起;
3. **GRPO + LoRA**:7B 基座(Qwen2.5-7B 级),LoRA + 序列长度控制,4×4090(96G)可行;
   **训练慢在环境交互(每步查图)不在梯度**——这是真实工程量,也是论文该讲的系统工作;
4. **课程**:从单跳/计数爬到多跳/多约束/冲突题。

## 6. 实验设计

### 6.1 基线(四档)
1. **单轮混合检索**(现有 `graphrag_retriever`)——增益下限对照;
2. **裸 7B + 工具(无训练,prompt-only ReAct)**——判"训练值不值"的对照;
3. **SFT-only**(冷启动不 RL)——判"RL 相对 SFT 的增量";
4. **RoG/ToG 式**(若复现成本可控)——同类 agentic 图推理对照。

### 6.2 消融(每行绑一个 claim)
| 消融 | 去掉 | 证明 |
|---|---|---|
| −RL(退 SFT) | 强化学习 | RL 相对模仿的增益 |
| **−trust 奖励项** | 置信度/冲突奖励 | **本方案核心"想法"的价值** |
| −工具子集 | 逐个去 set_op/count/text_search | 各工具对应题型的贡献 |
| −多轮(限单轮) | 多轮交互 | agentic 相对单轮检索的增益 |

### 6.3 指标
- 端到端:EM / 集合 F1(漏答与编造分列)/ 数值容差;
- 分题型准确率(重点看复杂/多跳/多约束的提升);
- **冲突题**:冲突识别率 + 冲突下答案质量(trust 项的直接证据);
- 成本:平均工具调用数 / token / 延迟;
- 公开集迁移(证通用性,守下限):WebQSP / CWQ / MetaQA 各抽 500 题。

### 6.4 统计
- 3 seed;与最强基线题级配对 bootstrap 显著性;test 集封盘。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| **复杂题无可验证奖励**(G1 核心矛盾) | 先在可判分题型训策略,复杂题作泛化测试/LLM-judge 辅助评测,不进 reward |
| RL 训练不稳/样本效率低 | **SFT 冷启动必做**;先小规模验证 reward 有梯度信号再全量 |
| 4×4090 显存不够 | LoRA + 序列长度截断 + 梯度检查点;基座退 3B~7B |
| 题量不足 | 模板自动生成(关系频次已核足够)+ 抽样校验;冷启动轨迹用强模型产 |
| trust 奖励无增益(−trust 消融打平) | 诚实报告,trust 降为分析章;主贡献转"多轮检索策略工程" |
| "又是 Graph-R1"质疑 | 不辩全新;delta = 领域 KG + 置信度/冲突奖励塑形 + 6 算子作工具 + 完整消融,工程价值立论 |
