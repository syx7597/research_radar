## Attribute-aware Feedback-Routing GraphRAG(工作代号 AFR-RAG)v1

> 定位:硕士毕设方法章的完整技术设计。底座复用 LightRAG / Practical-GraphRAG(RRF 混合检索),

> 属性通道 / 关系通道 / 文本通道之间的动态路由。**

## 1. 总体架构

```
                        ┌────────────────────────────────────────┐
                        │              离线索引层                  │
                        │  实体嵌入 │ 关系嵌入 │ 文本块嵌入 (底座复用) │
                        │  ┌──────────────────────────────┐      │
                        │  │ 属性三重索引 (新增, §3.1)       │      │
                        │  │  ①结构化属性表  ②属性言语化嵌入   │      │
                        │  │  ③单位归一数值列                │      │
                        │  └──────────────────────────────┘      │
                        └────────────────┬───────────────────────┘
                                         │
 用户问题 ──► 查询理解与 IR 编译 (§2) ──► 路由器 (§3.3)
                                         │  初始计划 = f(IR形态)
                                         ▼
              ┌──────────────────────────────────────────────┐
              │                  操作执行器 (§3.2)              │
              │  Ground│AttrLookup│AttrFilter│RelHop│PathExpand │
              │  TextSearch│Relax│Verify│Answer│Abstain         │
              └──────────────┬───────────────────────────────┘
                             │ 每步返回: 结果 + 符号信号
                             │ (空集/断链/键缺失/类型不符/多义…)
                             ▼
                    路由器读取信号 → 切换/续走/松弛/终止
                             │
                             ▼

```

数据流要点:路由不是入口处的一次分类,而是贯穿轨迹的**状态机**;
每个操作的后置符号信号是路由的输入,这是与 Adaptive-RAG 式前置路由的本质区别,
也是实验中 A4 消融直接对打的对象。

## 2. 查询中间表示(IR)——路由不退化的关键

自然语言问题先编译为类型化 IR(一次 LLM 调用 + schema 接地校验):

```
QueryIR {
  target:        (type: EntityType|ValueType, card: one|set|count)
  anchors:       [(surface, canonical_id | UNGROUNDED)]
  rel_chain:     [(relation, direction)]            # 关系约束链, 可空
  attr_cons:     [(key, op, value, unit)]           # op ∈ {=, >, <, between, ≈}
  aggregation:   none | count | argmax(key) | compare(key₁,e₁,e₂)
}
```

- `anchors` 落地用别名表(北约代号/转写/系列指针)+ 图内唯一性校验;
- `attr_cons` 的 key 经属性键归一表映射(§3.1),value 经单位归一;
- IR 编译失败或字段冲突(如 target 类型与 rel_chain 签名不符)→ 打回重编译一次,再失败走纯文本通道兜底。

**IR 的作用**:(a) 初始路由计划由 IR 形态确定性推出(有 attr_cons 无 rel_chain → 属性通道先行;
反之关系通道先行;两者皆有 → 先关系收窄候选集再属性过滤),这一步可审计、可复现;
(b) 中途切换时,IR 提供"还剩哪些约束未满足"的精确记账,切换不是重来而是续算;
(c) 论文中 IR 是"分解可审计"这一 claim 的实体。

## 3. 模块设计

### 3.1 属性三重索引(C1 的载体)

对图中每个实体节点的属性字典 {key: value} 建三重索引:

**① 结构化属性表**:长表 (entity_id, key_norm, value_norm, unit_norm, value_raw, source)。
- key 归一:构建属性键别名表(如 探测距离/range/detection range/max range → `detection_range`),
  半自动构建:嵌入聚类 + 人工审定,规模可控(领域属性键通常 <200 个);
- 数值解析:处理区间("50–80 km")、约值("约 300")、上界("up to X")三种形态,
  分别落为 (lo, hi)、(v, ±δ)、(-∞, X];
- 单位归一:全部换算 SI 存储,保留原始串供溯源。

**② 属性言语化嵌入**:每条属性生成一句模板化言语("<实体>的<键中文名>为<值><单位>"),
入向量索引——服务模糊问法("X 能看多远")到属性键的软对齐,与①的硬过滤互补。

**③ 数值列索引**:对 value_norm 建可范围查询的列索引(SQLite/DuckDB 即可),
支撑 AttrFilter 的 σ(type ∧ key op value) 毫秒级执行。

**可执行约束编译**:IR.attr_cons + IR.target.type → 过滤程序
σ(type≤T ∧ key₁ op₁ v₁ ∧ …),type 按你的实体类型层级做下推包含(NavalVessel ≤ Platform)。

### 3.2 操作集(每个操作带前置条件与符号信号)

| 操作 | 输入 → 输出 | 成功信号 | 失败信号(路由输入) |
|------|------------|---------|---------------------|
| Ground | surface → node_id | 唯一命中 | EMPTY(查无)/ AMBIG(多义) |
| AttrLookup | (id, key) → value | 值存在 | KEY_MISSING |
| AttrFilter | σ → id_set | 非空集 | FILTER_EMPTY |
| RelHop | (ids, rel) → ids | 非空 | HOP_BROKEN |
| PathExpand | (id, ≤k, beam) → paths | 达目标类型 | BEAM_EMPTY |
| TextSearch | query → passages | 含目标实体/键 | LOW_SCORE |
| Relax | σ → (σ', id_set, 报告) | 非空 + 报告 | BUDGET_OUT(判真无解) |
| Verify | (候选, 证据) → pass/fail | — | TYPE_VIOLATION / UNIT_VIOLATION |
| Answer / Abstain | — | — | — |

- Verify 直接复用你 S8 的类型签名检测器 + 单位相容检查,零新开发;
- Ground 复用你的别名表;TextSearch 语料为 1,432 段叙述文本(公开集上为对应文本块)。

### 3.3 路由策略(C3)

**v0 规则版(先跑通,亦是 v1 的示教来源)**
- 初始计划:IR 形态 → 通道序,确定性映射表(写死在附录,可复现);
- 切换规则表(节选):

| 信号 | 切换动作 |
|------|---------|
| KEY_MISSING | TextSearch(verbalize(entity, key)) → Verify → 命中则以文本证据作答 |
| FILTER_EMPTY | Relax(σ);Relax 也 BUDGET_OUT → 判无解或转文本 |
| HOP_BROKEN | 换等价关系重试(schema 近义关系表)→ 仍断则 TextSearch 定向取证 |
| AMBIG | 用 IR 中其余约束(类型/属性)做消歧过滤,仍多义则向用户澄清或并行展开 |
| LOW_SCORE(文本) | 若 IR 含 rel_chain 未用 → 回图走关系通道 |

- 预算控制:总操作数 ≤ B(默认 10),每类操作有单独上限,防循环。

**v1 学习版(算法增量,C3 的"轻量学习"部分)**
- 策略 π(s) → 下一操作;状态特征 s 全部为符号/廉价特征:
  IR 形态 one-hot、各约束满足位图、上一操作及其信号、剩余预算、当前候选集大小分桶;
- 训练:模仿学习。用 v0 在训练切分上跑出的**成功轨迹**(最终答对)做示教,
  (s, a) 对训一个小分类器(逻辑回归/GBDT 级即可,无需 GPU);
- 目标:同等准确率下降低操作数与 LLM 调用数(成本 Pareto 前移),
  这是"路由值得学"的量化证据;
- 明确不做 RL:样本效率与算力不适配毕设,写入"未来工作"。

### 3.4 最小约束松弛算法(C2,方法章的算法硬核)

**问题定义**:过滤程序 σ = {c₁…cₙ} 在图 G 上返回空集。求代价最小的松弛序列
ρ = ⟨a₁…aₘ⟩ 使 σ' = ρ(σ) 满足 |σ'(G)| ≥ 1,或判定预算内无解。

**松弛动作空间与代价**(代价预设并在附录固定,支持敏感性分析):

| 动作 | 语义 | 代价 |
|------|------|------|
| widen(cᵢ, δ) | 数值容差外扩一档(±5%→±10%→±20%) | 1 / 档 |
| alias(cᵢ) | 属性键沿别名表扩展一环 | 1 |
| lift(type) | 目标类型沿层级上推一层 | 2 |
| drop(cᵢ) | 删除整条约束 | 4 |

**求解**:代价上的 best-first 搜索(均一代价即 Dijkstra 层序);
每个松弛态执行 σ' 是列索引上的毫秒级操作,搜索空间由预算 β(默认 8)截断。

```
function MINRELAX(σ, G, β):
    PQ ← {(0, σ)}; seen ← ∅
    while PQ 非空:
        (c, σ') ← pop-min(PQ)
        if c > β: return NO_SOLUTION          # 判"真无满足实体"
        R ← EXEC(σ', G)
        if |R| ≥ 1: return (R, REPORT(σ→σ'))  # 结果 + 松弛报告
        for a in ACTIONS(σ'):
            if ρ(σ') ∉ seen: push(PQ, (c+cost(a), a(σ')))
    return NO_SOLUTION
```

**可写进论文的性质**:
- 最优性:代价非负 + best-first ⇒ 返回的 ρ 是代价最小松弛(Dijkstra 性质,一段引理);
- 单调性:widen/alias/lift 均使 σ'(G) ⊇ σ(G)(松弛不丢结果),drop 亦然 ⇒ 搜索无需回溯剪枝校验;
- 可解释输出:REPORT 明示"在把探测距离容差放宽到 ±10% 后找到 2 个实体",
  该报告(a)进入最终答案的措辞,(b)作为 Abstain 判据(NO_SOLUTION → 更可信的拒答)。

**先行工作披露(动手前精读)**:约束松弛在数据库合作式问答(cooperative query
answering)与 why-not 查询修复文献中是老话题(1990s 起)。本文 delta 必须写死为三条:
①松弛动作与 LLM 编译的类型化 IR、领域类型层级、单位系统耦合(动作空间是 schema 感知的);
②松弛嵌入 agentic 检索循环,其输出直接驱动路由与拒答;
③松弛报告参与生成,服务可解释性与幻觉抑制。若精读后发现①–③已有覆盖,C2 降级为工程组件,
承重转移至 C1+C3(见 §8 退路)。

### 3.5 融合与作答

- 多通道候选统一为 (candidate, channel, score, provenance) 四元组,
  跨通道用 RRF 融合(沿用 Practical-GraphRAG 的做法,不另发明);
- 生成时强制引用 provenance(图边 id / 属性行 id / 段落 id),
  数值答案附单位与(若经松弛)松弛报告;
- 集合型答案(target.card = set/count)必须来自可执行通道(AttrFilter/RelHop)的完整结果集,
  文本通道只允许补充佐证、不允许独立产出集合成员——这是对"支持度≠完备度"问题的
  廉价工程防线(呼应你此前幸存的 #8/#9 假设,不展开为创新点)。

## 5. 实验设计

### 5.1 数据集

| 数据集 | 角色 | 说明 |
|--------|------|------|
| STaRK(amazon / mag / prime) | **主力** | 天生混合结构+文本+属性;报 Hit@1 / Recall@20 / MRR |

### 5.2 基线(四档)

1. **GraphRAG 主线**:LightRAG、HippoRAG 2、微软 GraphRAG、Practical-GraphRAG(RRF 底座原版);
2. **朴素强对照**:稠密向量 RAG、BM25、**属性平铺文本化 RAG**(属性拼成句子当普通块检索)
   ——第三个最关键,它逼 C1 证明"结构化处理属性"优于"属性当文本",输给它则 C1 不成立;
3. **判死刑基线**:ReAct 多工具 agent(裸 LLM + 同样的属性表/图/文本三工具,无 IR、无路由规则、无松弛);
4. **路由对照**:Adaptive-RAG 式一次性分类路由(同样三通道,查询入口分类一次后不再切换)
   ——A4 消融的独立实现,直接回答"这是不是意图识别包装"。

### 5.3 消融矩阵(每行绑定一个 claim)

| 消融 | 去掉什么 | 证明什么 |
|------|---------|---------|
| A1 | 属性通道整体 | C1 存在价值 |
| A2 | 数值/单位结构化(退化为属性字符串匹配) | C1 中结构化的必要性 |
| A3 | Relax(空集即失败) | C2 的增益与拒答质量 |
| A4 | 反馈切换(退化为一次性路由) | C3 vs 意图分类 |
| A5 | v1 学习路由(退回 v0 规则) | 学习带来的成本 Pareto 前移 |
| A6 | RRF 融合(单通道独走) | 通道互补性 |

### 5.4 指标

- 端到端:EM(数值 ±5% 容差)/ F1;集合题 P / R / F1(漏答与编造分列);
- 检索层:**各通道 recall@k**(核心图表——属性证据被检回率是 C1 的直接证据);
- 成本:LLM 调用数 / token / 延迟,给出准确率–成本 Pareto 图(C3/A5 的主图);
- 拒答:应拒题的拒答准确率 + NO_SOLUTION 判定的精度(C2 附加价值);
- 松弛报告人工评价(小样本):报告是否如实反映了放宽内容。

### 5.5 统计规范

- 每配置 3 seed(或 temperature=0 下 2 遍一致性);主对比报均值±标准差;
- 与最强基线做配对 bootstrap 显著性检验(题级);
- 公开集用原始切分;领域集沿用诊断方案的冻结纪律。

## 7. 风险与对策

1. **C1 在 STaRK 上不显著**(最大风险):第 4 周检查点若 recall@k 无提升,先查属性键归一质量
   与言语化模板,仍无效则把主战场移到 KQA Pro/GrailQA 数值子集(约束可执行性优势更直接);
2. **路由退化嫌疑**:A4 消融若显示反馈切换无增益,诚实降级——C3 改为工程组件,
   论文承重转 C1+C2,叙事改为"属性感知检索与最小松弛";
3. **C2 撞车**:§3.4 的先行工作精读若发现 delta 不足,C2 降级,松弛保留为系统功能;
4. **STaRK 工程量超预期**:先只做一个子集(推荐 amazon,属性最密),另两个子集视进度;
5. **属性键归一噪声**:人工审定预算按 200 键 × 2 分钟估计,一天内可完成,不省。
