# 后续路线图

版本：2026-09-26。与[研究方向审查](../RESEARCH_DIRECTION.md)配套。下列时间从正式开始执行算起，按工作周估计，不代表已经完成，也不假设已有可用 GPU。阈值是建议提前冻结的工程/决策门槛，不是已有结果或普遍学术标准。

## 1. 先完成什么

前四周的目标是决定**是否值得把 RL 作为论文核心**。先修环境、建可信数据，再比较强 SFT 与小规模策略优化。四周内若 GPU 不具备条件，就完成 CPU 数据与执行工作，将 SFT/RL 门槛顺延；不要用 oracle 或商业大模型结果代替待训练策略的成绩。

| 阶段 | 时间建议 | 交付物 | 验收门槛 | 不通过时 |
|---|---|---|---|---|
| M0 固定问题与环境 | 第 1 周 | 数据快照 manifest、工具协议、独立参考执行器、边界用例、原型差距清单 | 所有纳入任务的 oracle 严格通过；集合/空值/计数边界通过；公开字段无金标；KG 数量与 hash 可复现 | 暂停训练，修执行语义或剔除并记录不支持任务；不改金标迎合错误实现 |
| M1 数据与公开环境 | 第 2 周 | 新版 train/dev/test；组合与恢复套件；KQA Pro 小适配集；数据审计报告 | 组合 AST 家族无泄漏；声称实体隔离的交集为零；人工分层审计不少于 100 题，语义一致率建议 ≥95%；保留合法空集 | 停止自动扩量，修模板/程序；隔离不成立就更名并缩小结论 |
| M2 强基线 | 第 3 周 | 单次程序生成、扁平 SFT、类型化 SFT；统一逐题轨迹 | SFT 验证格式率建议 ≥95%；程序执行率建议 ≥90%；在开发集确有可定位的组合/恢复错误；训练与推理掩码审计通过 | 优先修数据/协议；若基线已接近 oracle，先检查任务是否过易，不人为削弱基线 |
| M3 RL 可否证试验 | 第 4 周 | 同起点结果奖励 RL、过程奖励 RL、继续 SFT；两种子小实验与成本表 | 至少观察到可复现的开发集收益趋势，或同等准确率下明确降低成本；过程奖励与答案质量不背离 | 达到下述停止条件后降级；不靠不断换测试集维持正结果 |
| M4 正式主实验 | 第 5–7 周 | 公平 2×2、反馈消融、三个种子、冻结测试结果与误差区间 | 预设主对比达门槛，逐题结果可重放；主要结论不依赖单一种子或单一模板 | 报告负结果并收窄贡献；只保留实际成立的假设 |
| M5 公开验证与系统收束 | 第 8–9 周 | KQA Pro 正式结果；必要时 MetaQA；应用接入最佳模型 | 公开环境 oracle 与策略分开；支持子集比例透明；接口结果能追溯至执行产物 | 不把不支持样本默默删除；跨域失败则限制适用范围 |
| M6 写作与复现 | 第 10 周起 | 论文主表、案例、复现说明、版本标签、答辩材料 | 新旧结果分开；一条命令可执行小样例；训练配置、代码、数据 hash 与表格对应 | 删除没有证据的贡献宣称，保留可复现结论 |

M0–M3 是投入决策期，M4 以后只扩展已经通过的路线。若期限较短，优先雷达 + KQA Pro、一个小模型、核心对照，删去多模态、置信度与额外数据集。

## 2. M0：必须先关闭的实现缺口

以下根据本轮审查时的代码列出。2026-09-26 已修复空交集、严格整数判分、非法动作和回合终止，并通过16个边界测试；完整独立参考执行器、比较语义和统一训练协议仍待完成。详细验证见[训练就绪检查](../TRAINING_READINESS.md)。

| 优先级 | 缺口 | 具体工作 / 验收证据 |
|---|---|---|
| P0，部分完成 | `KGTools.intersect` 跳过空输入 | 空交集已修复并测试；继续用独立解释器核验完整组合程序、差集及错误状态 |
| P0 | 原始/过滤图口径漂移 | 固定 `edges/entities/filter/schema` hash；分别报原始边记录、过滤记录、去重三元组与实体数量；生成器和环境只共享一个过滤入口 |
| P0，部分完成 | 评分过宽 | count已改为严格整数；仍需集合同时输出EM/F1、比较对象和维度校验、避免别名归一误合并 |
| P0 | 中间集合由模型重新写出 | 用变量句柄传递结果；模型选择关系和算子，执行器保存全集与 provenance；最终答案引用已执行结果 |
| P0 | 观察与奖励混杂 | 分开公开 observation 与训练评分器；保留错误类别，区分 `empty/error/unknown/truncated`；真实策略不能接触 gold 字段 |
| P0 | 现有 GRPO 原型不足以正式训练 | 当前 rollout 未累计环境逐步 reward；参考模型加载裸基座；目标为简化组基线 REINFORCE，不能当作已验证 GRPO。迁移成熟实现或逐项数值验证后再命名算法 |
| P0 | token 掩码与多轮序列需审计 | 核对完整 chat token 与增量拼接一致；工具观察不计生成 loss；结束动作不因长度截断丢失；生成后重分词的 span 与实际 token 对齐 |
| P1 | 两套执行器未统一 | 第一版确定一个权威执行后端，旧计划树编译到它；先不维护两套语义各自扩展 |
| P1 | 简单否定有知识缺失风险 | 数据卡注明闭世界“库中记录”；未知事实不标为现实中的 false；构造可验证的合法空结果 |
| P1 | oracle 与生成器共享缺陷 | 用独立解释器或 SQL 查询核验一批程序；加图事实扰动后答案随之更新的检查；不能只循环回放同一生成函数 |

现有回放入口可用于基线复核，但不是以上新增检查的替代：

```bash
python -m ca_agraphrag.test_env_oracle
python -m ca_agraphrag.eval_policy --split dev --policy oracle
```

本路线图不启动数据重生成或模型下载。修复改变语义后，生成新的数据版本并保存旧版，不覆盖历史实验输入。

## 3. M1：可信数据的最小交付

建议第一版规模仍控制在现有训练集量级。优先增加语义覆盖，避免十倍重复模板。

- 冻结独立开发集与测试集。组合测试目标至少 500 题、至少 10 个保留程序家族；若只得到较小高质量集合，报告置信区间与规模限制，不用近重复凑数。
- 覆盖 `count(intersect(...))`、`difference(path(...), find(...))`、嵌套交并、不同约束顺序、高基数完整集合与零计数。训练覆盖每个原子算子，测试保留组合而非把全新工具当组合泛化。
- 先做程序规范化和语义家族分组，再生成/润色自然语言；同一程序的同义改写全部留在同一 split。
- 单独构造 100–200 组干净/受扰配对恢复样本，包括可恢复和不可恢复两类。别名需有解析通道；临时失败需可重试；永久缺边无替代通道时金标为 unknown。
- 人工检查不少于 100 题，分层覆盖程序深度、题型、空答案与改写来源。人工抽样、判断及修改日志保存在数据审计中。
- 记录目标实体、比较双方、桥接实体、答案实体和支持实体跨 split 的交集；“只 anchor 不交”的旧版保留为旧版，不继续标成严格实体隔离。
- KQA Pro 在第二周就做 100–300 题 smoke 适配，优先 KoPL 官方执行语义；先确认 qualifier/属性/算子可支持。不要等雷达实验结束才发现公开集工具覆盖不足。

## 4. M2–M3：最小训练试验

先选择一个本地可承受的 1.5B/3B 级模型与 LoRA；型号、revision、精度和 tokenizer 固定。该大小只是试验建议，不保证单张显卡一定容纳多轮 RL。先测 32–64 条完整轨迹的峰值显存、截断率、每秒 rollout 和实际成本，再决定批量、组大小与并发。

训练环境一次性记录 GPU 型号/数量/显存、CUDA、PyTorch、训练框架版本、最大上下文、实际 token 预算和可用 GPU 小时。用户既有代码写有“4×4090”并不构成当前资源已就绪的证明。

小实验执行顺序：

1. **单次程序 SFT / 扁平 SFT / 类型化 SFT。** 使用同一问题与程序监督。若单次程序已稳定获胜，解释多轮交互只在何种恢复任务上需要。
2. **仅答案与成本 RL。** 从对应 SFT 检查点出发，统一评分与预算；先确认 rollout、loss mask、组内奖励方差和更新方向正确。
3. **过程反馈 RL。** 从同一个 SFT 检查点独立开始，先只加“首次完成已验证子目标”的反馈；之后逐项加成本/重复抑制，不一次加入六七项奖励。
4. **继续 SFT 或执行筛选后继续 SFT。** 分别说明额外训练 token、生成轨迹和监督信息，排查 RL 的优势是否只是多训练或多看成功例子。
5. **轨迹审计。** 每次固定抽取高奖励错答、最长轨迹、零工具答案、合法空集和修复样本，检查奖励与任务目标是否一致。

第 4 周决策使用开发集，建议将“值得扩展”的实用门槛预设为：两个种子同方向，主开发集 EM 约提高 3 个百分点，或 EM 下降不超过 1 个百分点且原子工具/token 成本减少约 15%。这些数值只用于是否继续投入，不代表统计显著性；正式结论必须用冻结测试与置信区间。

## 5. M4：正式实验与发表口径

核心矩阵按[研究方向 §5](../RESEARCH_DIRECTION.md#5-公平实验先分清表示学习与奖励)执行：A/B 为两种表示的 SFT，C/D 为统一 R0 的 RL，E 检验过程反馈，F 控制额外训练。至少加入单次程序基线与 KBQA-R1 式同环境动作策略。宏动作按底层原子操作计成本，保持各组工具能力一致。

预注册主结论对应指标：

| 主张 | 主指标与门槛建议 | 辅助证据 |
|---|---|---|
| 表示更可靠 | 同条件答案 EM 改善，或执行错误显著下降且 EM 非劣 | 去除类型约束/宏动作的小消融；变量错误和格式错误分开 |
| RL 超越模仿 | E 对 B/F 在组合隔离 EM 的配对差异 95% CI 下界 >0，且三个种子无明显反向退化 | 单独报告 D；不能把奖励改变的收益全部归为 RL |
| 过程反馈有效 | E 对 D 的主指标改善，或预设 1 个百分点非劣界内成本显著下降 | 奖励攻击通过；高奖励错答率下降；空集/高基数子集无明显退化 |
| 具备外部适用性 | KQA Pro 上相同主对比、已公开适配覆盖与完整分母 | 如果只测支持子集，标题与表格明确写子集；不宣称完整榜单 SOTA |

测试结果同时给出：环境可解率、答案 EM / 集合 F1、计数准确率、计划有效率、执行成功率、有来源的正确率、恢复成功率、unknown 判断、原子调用数、token 与延迟。覆盖可解子集和全部样本都要报告，避免把环境失败静默排除。

所有主结果保存逐题预测与轨迹，按问题/程序家族配对 bootstrap；三个训练种子的方差单独报告。测试集只在冻结方案后运行，失败后调整方法要记录版本，不把反复选最优测试结果当最终证据。

## 6. 停止、降级与范围收缩

| 触发条件 | 决策 | 仍然可以交付什么 |
|---|---|---|
| 第 2 周环境/数据审计不过 | 停止 GPU 训练，先修基础 | 可靠数据、执行器和任务定义 |
| SFT 在计划复杂度分组中已接近 oracle | 不强推 RL；保留自然恢复与组合测试，不人为造难题迎合方法 | 小模型程序生成 + 可靠执行 + 成本边界 |
| 两种子、至多两轮预先限定调参后，RL 仍无开发集实用收益 | 结束该 RL 路线，不扩 7B、不无限扩大训练 | 继续 SFT/执行筛选作为正式方案，保留负结果分析 |
| 奖励上升而 EM 不升，重复/自造修复增长 | 立即暂停该奖励训练，关闭可投机项 | 反馈失败机制与经修复的验证器；不得只展示奖励曲线 |
| 过程反馈只在原模板 IID 上提升 | 不主张组合泛化，检查语义家族泄漏与额外监督差异 | 领域内优化结果，或改用更简单基线 |
| 对最邻近 KBQA 方法无可辨别差异 | 放弃“新框架”包装，将候选贡献缩到具体反馈或实证边界 | 领域系统与可复现实验；方法创新资格需重新与导师确认 |
| KQA Pro 环境覆盖不足 | 先完成支持子集，固定筛选规则；公开完整分母 | 有边界的外部验证，不能换成更易数据后声称同等验证 |
| 公开集无增益但雷达稳定有效 | 缩小为雷达领域方法，不声明通用优越性 | 领域问题、知识环境、可靠查询与适用条件 |
| GPU 预算不足以公平完成核心实验 | 保留一个模型、少量必要组；停止额外规模和数据集 | 完整的小规模比较比零散大模型结果更可解释 |

降级不意味着自动满足毕业要求；它意味着及时改变论文主张，避免把尚未证明的 RL 增益写成既成事实。

## 7. 每个里程碑的仓库交付约定

- 代码、配置、小型验证样例、数据说明和 split manifest 进入 Git；原始手册、大型索引、模型权重和可重建缓存放外部资产位置，Git 内记录获取方式、版本和校验和。
- 每次正式实验记录 `run_id/code_commit/data_hash/kg_hash/config/seed/model_revision`，输出逐题结果和汇总；无这些信息的结果标为探索实验。
- 已发表或已写入论文表格的输入与结果不覆盖；新结果开新 run。历史论文中的 88.6%、71/72 与新主线成绩单独列示。
- 测试集标签不进入训练样本、检索文本或提示词；评分器和模型可见输入保持接口分离。
- 论文写作与里程碑同步：M1 写任务定义，M2 写强基线，M3 写反馈假设，M4 写结果与失败分析，M5 才写整体系统效果。

下一次工作应从 **M0 的执行语义、严格评分和统一数据快照** 开始；优先级高于再生成开题 PPT、扩充雷达条目或启动现有 GRPO 脚本。
